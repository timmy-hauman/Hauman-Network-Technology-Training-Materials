講師導言

前面五章都在「紙上談兵」,這一章開始動手裝機。目標很明確:從一台空的 VM 或剛上架的硬體,走到「Gateway 出現在 MX 的 Gateways 清單、狀態正常」。 最重要的一條順序是 先 MX、後 Gateway:Gateway 首次設定時要填 MX 的 IP 才能註冊,MX 沒起來,Gateway 就註冊不上。 初始化全程靠 impcfg 精靈與 impcli 受限 shell,GUI 要等 MX 資料庫建好才能登入。

Goals 本章學習目標

  • 說明安裝順序(先 MX 後 Gateway)與安裝前要備妥的項目
  • 分辨 VMware、KVM、公有雲、硬體 appliance 四種安裝方式與限制
  • 說出 impcli 登入規則,以及 impcfg 首次設定在 MX 與 Gateway 上各填什麼
  • 登入 MX GUI、了解授權類型,並完成 ADC 手動或自動更新
  • 用檢查清單確認 Gateway 已出現在 MX,並避開常見踩坑

範例環境:MX mx01 10.0.30.10;Gateway gw01 10.0.30.11、gw02 10.0.30.12;管理者電腦 10.0.30.100。

一、安裝前準備與整體順序

用公司總機來想

MX 像總機房,Gateway 像各分機。分機要接上線,得先知道總機的號碼(MX 的 IP)並用密碼報到;總機還沒開機,分機再怎麼設定也報到不了。

安裝前要備妥的項目

項目範例環境的值說明
MX 管理 IP / 遮罩 / 預設閘道10.0.30.10/24,閘道 10.0.30.1【推論:範例網段慣例】MX 只需要管理介面
Gateway 管理 IPgw01 10.0.30.11、gw02 10.0.30.12流量介面另依部署模式規劃(第 4、5 章)
DNS內部 DNS 伺服器(必須是真的 DNS)首次設定若填 DNS client,官方要求填「真實存在」的 DNS 伺服器;ADC 自動更新也依賴 DNS
NTP內部 NTPMX 與 Gateway 時間不一致會讓告警時間軸錯亂、憑證驗證失敗【推論】
對外連線MX → www.imperva.com:443、MX → *.impervacloud.com:443ADC 更新與威脅情資(第 3 章通訊埠表、第 10 章)
授權傳統授權或 FlexProtect見第六節
防火牆管理者 10.0.30.100 → MX 8083、22;GW → MX 8083;MX → GW 22、443啟用憑證式 Trusted Connections 後 GW → MX 改走 8085(第 3 章)

排維護窗口的時間預估(官方)

  • MX 首次設定要 45 分鐘到 1 小時(要建立並初始化資料庫)。
  • Gateway 約 10 到 15 分鐘。

二、四種安裝方式與限制

方式適用重點
VMware OVFESXi 6.x / 7.0 / 8.0需透過 vCenter 部署 OVF;MX 用 VM150,Gateway 依容量選 V1000 / V2500 / V4500
KVMLinux KVM依 KVM 安裝指南匯入映像
公有雲AWS、Azure、GCP、AliCloud、OCI【15.5】用 Cloud Template Tool 產生 Terraform(第 5 章);【16.0】CA 版不支援任何雲端 VM
硬體 appliance7G(X2030…X10K3、M180)依機器隨附的 Quick Start Guide 接 console 開機,進入首次設定

安裝前先確認的四個限制

  • 只支援分散式部署:MX 與 Gateway 必須是不同的 VM / 機器;Onebox(同機)自 v14.1 起不支援。
  • Hyper-V 自 v14.4 起不支援,舊環境若在 Hyper-V 上要先規劃搬遷。
  • 虛擬機只支援 Fail Close(沒有實體 bypass 網卡),要 Fail Open 只能用有 bypass 介面的硬體(第 5 章)。
  • 硬體重灌(USB 安裝映像)的實際步驟與指令以該型號 Quick Start Guide 為準【待實機確認】;【16.0】官方列 NG6 硬體不支援 USB 全新安裝。

VMware 部署步驟(以 MX 為例,Gateway 相同)

  1. 1從 Thales Support Portal 下載對應版本的 MX OVF/OVA【待實機確認:檔名與下載路徑】。
  2. 2vCenter > Deploy OVF Template,選 MX 映像,指定名稱 mx01、資料存放區、網路(管理 port group 接 10.0.30.0/24)【待實機確認:OVF 精靈內的部署選項名稱】。
  3. 3確認 vCPU / 記憶體符合 VM150 規格(4 vCPU / 8GB,可擴到 32GB)。
  4. 4開機,從 vSphere console 進入首次登入(下一節)。

三、首次登入:impcli 與改密碼

登入 appliance 的 shell 是 impcli(Imperva 專屬受限 shell)【待實機確認:起始版本】,不是舊版直接進 Linux。

項目現況
預設使用者admin,首次登入必須改密碼
取得 root在 impcli 下輸入 admin 指令可切到 root
Sealed 模式啟用後不能切 root,適合高安全環境
root 密碼每 90 天必須更換
root SSH預設不允許 root 直接 SSH 登入
稽核impcli 的所有輸入都會被記錄
  1. 1從 VM console(或硬體序列 console)以 admin 登入。
  2. 2依提示設定新密碼(密碼複雜度規則【待實機確認】)。
  3. 3系統接著引導進入 impcfg 首次設定精靈(First Time Login)【待實機確認:是自動進入或需手動執行 impcfg】。

四、impcfg 首次設定:MX

impcfg 是選單 / 問答式設定工具。首次設定時它以問答方式蒐集資料,確認後再呼叫 impctl 套用到系統元件。

vSphere console - mx01(impcfg 首次設定)
1Role: Management Server (MX)
2Management IP: 10.0.30.10
     Netmask: 255.255.255.0 / Default gateway: 10.0.30.1
3Hostname: mx01 / DNS / NTP / Time zone
4Registration password: ********
5Review summary → Apply (等待 45–60 分鐘)
示意畫面:部分欄位名稱待實機確認(精靈選項文字、註冊密碼欄位名稱、NTP 設定位置),版面以實機為準。
  1. 1選擇此 appliance 的角色為 Management Server(MX)【待實機確認:精靈中的選項文字】。
  2. 2設定管理介面:IP 10.0.30.10、遮罩 255.255.255.0、預設閘道。
  3. 3設定 hostname mx01、DNS(填真實 DNS)、NTP、時區【待實機確認:NTP 是否在首次精靈中或稍後在 impcfg 的 platform 選單設定】。
  4. 4設定 MX 與 Gateway 之間的通訊(註冊)密碼,之後 Gateway 註冊要用到【待實機確認:欄位名稱】。
  5. 5檢視摘要、確認後套用;等待 45–60 分鐘直到資料庫初始化完成。

官方警告

對已設定好的 appliance 重跑 First-Time 設定腳本,會覆蓋原有設定。日常修改請用 impcfg 選單,不要重跑首次精靈。

五、impcfg 首次設定:Gateway 與註冊

vSphere console - gw01(impcfg 首次設定)
1以 admin 登入、改密碼、進入 impcfg
2Role: Gateway
3Management IP: 10.0.30.11/24 / gateway / DNS / NTP
4Management Server IP: 10.0.30.10 (單一 IP,不是 CIDR)
5Registration password: ********
6Gateway Group: GG-Shop / Name: gw01
7Operation mode: Bridge / Sniffing / Reverse Proxy
8Apply (約 10–15 分鐘)
示意畫面:部分欄位名稱待實機確認(角色選項文字、註冊密碼、是否在精靈中詢問 Gateway Group),版面以實機為準。
  1. 1以 admin 登入 gw01 console、改密碼、進入 impcfg 首次設定。
  2. 2選擇角色為 Gateway【待實機確認:選項文字】。
  3. 3設定管理介面 10.0.30.11/24、預設閘道、DNS、NTP。
  4. 4填入 Management Server 的 IP:10.0.30.10。官方註明這裡不能填 CIDR,只能填單一 IP。
  5. 5填入上一節步驟 4 設定的註冊密碼【待實機確認】。
  6. 6指定 Gateway Group(GG-Shop)與 Gateway 名稱 gw01【待實機確認:首次精靈是否詢問 Gateway Group,或註冊後在 MX 指派】。
  7. 7選擇 Gateway 運作模式(Bridge / Sniffing / Reverse Proxy;見第 4 章)。日後要改模式,官方建議用 impcfg:Top > Manage SecureSphere Gateway > Change operation mode,改完按 S 存檔、A 套用。
  8. 8確認後套用,約 10–15 分鐘;對 gw02(10.0.30.12)重複一次。

換 MX 註冊

Gateway 可以用 impcfg 從原 MX 解除註冊、再註冊到另一台 MX;底層對應 impctl gateway unregister / register(impctl 只在必要時或原廠指示下使用,見第 13 章)。

六、動手玩:impcfg 首次設定模擬器

每一步選出正確的選項才會前進,選錯會告訴你為什麼不行。可以切換成 Gateway 流程;如果在 MX 還沒完成時就去設 Gateway,看看最後會怎樣。

七、登入 MX GUI、授權與 ADC 更新

登入 GUI

  1. 1在管理者電腦 10.0.30.100 開瀏覽器連 https://10.0.30.10:8083。
  2. 2第一次會看到 MX 自簽憑證警告;正式環境建議日後換成內部 CA 簽發的憑證【待實機確認:替換 GUI 憑證的路徑】。
  3. 3以 GUI 管理帳號登入並依提示改密碼【待實機確認:預設 GUI 帳號名稱與首次改密碼流程】。

授權

  • 除傳統授權檔外,另有 FlexProtect 授權(雲端 AppProtect / Flex Protect);v15.5 Patch 10 起還有不設吞吐上限的「CLOUD」虛擬型號,限 AppProtect / Flex Protect 授權。
  • 上傳授權檔的 GUI 位置【待實機確認】(官方 Administration Guide 有 License Overview 章節)。

ADC 內容更新(官方步驟)

ADC(Application Defense Center)內容包含簽章、預建政策與情資定義,一般約每兩週發布一次。

https://10.0.30.10:8083
Imperva MX MainAdmin

Manual ADC Update
1Download存下 .mprv 檔
2Browseadc-update.mprvUpload
Automatic ADC Update
3RecurringUpdate Now
示意畫面:欄位名稱依 Imperva 官方文件,版面、按鈕位置與配色以實機為準。

手動更新

  1. Admin workspace > ADC。
  2. 在 Manual ADC Update 下按 Download,存下 .mprv 檔。
  3. 用 Browse 選取該檔,按 Upload。
  4. 部分更新要 Apply Settings 後才生效。

自動更新

  1. Admin workspace > ADC。
  2. 在 Automatic ADC Update 選 Recurring,設定排程。
  3. 要立即更新按 Update Now。

前提

預設閘道與 DNS 必須已用 impcfg 設好,否則自動更新會失敗。MX 不能直連網際網路時,可設定 External HTTP Settings 走 proxy,或由可上網的電腦下載 .mprv 再手動上傳。

九、常見踩坑

先裝 Gateway 再裝 MX

Gateway 首次設定要填 MX IP 才能註冊;MX 沒好就只能事後再用 impcfg 註冊,浪費一輪。

DNS 亂填

官方明講首次設定的 DNS 要填真實伺服器;DNS 錯會讓 ADC 自動更新、威脅情資、ABP(第 10 章)全部連不上。

MX IP 填成 CIDR

註冊欄位只接受單一 IP。

對已上線的 appliance 重跑 First-Time 精靈

會覆蓋整份設定;要改 IP 或模式請用 impcfg 選單。

低估 MX 初始化時間

45–60 分鐘內看起來像「卡住」,中途重開機會讓資料庫初始化失敗【推論】。

VM 規劃 Fail Open

虛擬機只支援 Fail Close,要 bypass 只能用硬體。
