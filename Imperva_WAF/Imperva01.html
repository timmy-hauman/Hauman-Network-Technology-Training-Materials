講師導言

歡迎來到 Imperva WAF Gateway 實戰課程。你手邊的設備或文件,很可能還叫 SecureSphere;現場跑的是哪一版、還有多久支援、該不該升 v16.0,都是動手設定之前就要先弄清楚的事。 這一章先帶你把「產品現在叫什麼、現場是哪一代、還能撐多久」看清楚,後面 14 章才不會拿錯版本的文件在操作。

整套課程共 15 章,每一章一頁,範例都用同一組環境(shop.example.com),走向如下:

12 監控、稽核與整合 · 13 CLI 與日常維運 · 14 Imperva Cloud WAF · 15 綜合實作:shop.example.com 上線

Goals 本章學習目標

  • 說出 SecureSphere 與 Imperva WAF Gateway 的關係,以及 v14.4 這個命名分界
  • 對照元件的舊名與現名(WAF Gateway、MX、SOM、Threat Intelligence Services)
  • 判斷現場版本是否還在支援期內,知道該往哪個版本升級
  • 解釋本課程為什麼以 v15.5 LTS 為基準,以及 v16.0 CA 目前不宜當主力
  • 知道舊簡報裡的資料庫、檔案、SharePoint 產品現在去了哪裡

一、這套課程怎麼讀

本課程的觀念保留了 2014 年 SecureSphere 9.0 WAF 技術訓練簡報裡到今天仍然成立的部分(Web Profile、Site Tree 層級、Correlation、WAF 放在負載平衡器前或後的考量等);版本、型號、埠號、GUI 路徑一律改用 Imperva / Thales 官方現行文件重寫。 UI 名稱與功能名保留英文原文,選單路徑用 > 分隔,例如 Main > Setup > Gateways。

二、從 SecureSphere 到 WAF Gateway

用「公司改名、換老闆」來想

舊簡報的 SecureSphere 9.0 是一套「資料安全平台」:同一台 MX 管理 Web(WAF)、資料庫(DAM / DBF)、檔案(FAM / FFW)與 SharePoint 的 Gateway。這十二年間,公司改過名、換過母公司,各部門(產品)也分家各自發展,但辦公室門口還掛著舊招牌:GUI、CLI 和官方文件裡仍處處是「SecureSphere」。

時間 / 版本事件對維運的影響
2014(9.0)舊簡報年代;同一平台管 WAF、DAM、FAM;支援 7.5、8.0、8.5、9.0(舊簡報 p.48)—
v14.1Kernel Reverse Proxy(KRP)移除,改由 user-space 的 Next Generation Reverse Proxy(NGRP)取代;不再支援 Onebox(MX 與 Gateway 裝在同一台實體機)舊 KRP 設定要改寫、容量要重估(第 4 章)
v14.2Universal User Tracking(UUT)移除改用 Web Application User Tracking(第 11 章)
v14.3 以前官方 EOL 表歸在「SecureSphere (Up to V14.3)」—
v14.4 起EOL 表改稱「WAF Gateway」;WAF 與 DAM 拆成兩套完全獨立的版本;Hyper-V 不再支援;SSL cipher、ECC、TLS 協定設定移到 Global Objects 的 TLS Settings一台 MX 不能同時管 WAF 與 DAM Gateway
v15.0作業系統改為 CentOS 7.9;新增系統事件記錄(誰改了什麼)—
2023-12-04Thales 完成併購 Imperva(2023 年 7 月宣布),2024 年 1 月開始整合文件站、社群、支援入口陸續搬到 Thales 網域
2024-02第 7 代(7G)硬體推出新購硬體為 7G(第 5 章)
約 2026-02【推論】v15.5 發布;v15.5.0.10 起指定為 LTS本課程基準
2026-08-20v16.0(Patch 10)發布,僅 Controlled Availability;改用 Oracle Linux 9.5功能受限,見第五節

日期的查證限制

  • 官方查不到正式的「改名公告」日期,也查不到 v14.4 的發布日期;本課程以 EOL 表的分界(v14.3 / v14.4)為準。
  • v15.5 的確切 GA 日期官方未明載。「自發布日起至少 3 年,估計到 2029 年 2 月」反推約為 2026-02,官方「Getting Started with WAF Gateway v15.5」頁建立於 2026-02-16 也可佐證【推論】。
  • v16.0 的 GUI 與文件內文仍大量使用「SecureSphere」字樣,例如 impcfg 選單的 Manage SecureSphere Gateway。看到舊名不代表你讀的文件過時。

三、母公司、支援入口與元件現名

品牌與支援入口

  • Imperva 現為 Thales 集團旗下公司,官方 datasheet 標示「imperva — a Thales company」。產品名維持 Imperva:地端是 Imperva WAF Gateway,雲端是 Imperva Cloud WAF(前身 Incapsula,第 14 章)。
  • 官方文件站 docs.imperva.com 已轉址到 docs-cybersec.thalesgroup.com。文件依版本分 bundle,網址會帶版本,例如 .../bundle/v15.5-waf-administration-guide/...;查資料時先確認 bundle 版本與現場一致。
  • 社群改到 community-cybersec.thalesgroup.com;開案改走 Thales Support Portal。
  • 2026-02-15 起不再直接以 email 寄送產品通知。維運單位要改成定期到支援入口查看公告與 patch 訊息【推論】。

四、版本與支援期限(EOS)

官方 EOL 政策頁把 WAF Gateway、MX、SOM 放在同一列,三者的支援期限相同。下表「狀態」以查證日 2026-11-02 計算。

版本類型End of Support狀態(2026-11-02)
v16.0CA未列入 EOL 表僅 Controlled Availability,需開 support ticket 申請下載
15.5-LTSLTSTBD(release notes 估至少到 2029-02)支援中,最新為 Patch 21
V15.4minor2027-09-10支援中
V15.3minor2026-11-09一週後到期
V15.2minor2026-05-31已到期
V15.1minor2026-03-02已到期
V15.0minor2025-08-31已到期
V14.7-LTSLTS2027-02-28支援中,仍在出 patch(Patch 220,2026-09-28)
V14.6 / 14.5 / 14.4minor2024-04-30 / 2024-02-05 / 2023-06-30已到期
SecureSphere v13.x—EOL 2023-09-30;v13.6 LTS 延長到 2024-03-31已到期

支援規則

  1. LTS 至少支援 2 年才進入 EOL 階段(EOL 頁原文);但 v15.5 release notes 寫「自發布日起至少 3 年」。兩處說法不同,規劃預算與升級時程時以 EOL 表公告的日期為準;15.5 目前是 TBD,先以 2029-02 當參考值。
  2. LTS patch 依 EOL 頁原則只含 bug 與安全修正、不含新功能;但 v15.5 Patch 21 的 release notes 列出新增 Web Custom Policy 比對條件(回應 header 值、request body 參數數量上限)。兩者不一致,套用 LTS patch 前仍要逐條讀 release notes【待實機確認】。
  3. minor 版(如 15.4)自發布起至少支援 1 年。
  4. v15.5 指定為 LTS 後,v14.7 LTS 至少再支援 1 年(對應 EOL 表的 2027-02-28)。

現場怎麼看版本?

impcfg 首頁會顯示安裝的元件與狀態(舊簡報 p.153 的畫面即是),MX GUI 也可查看版本資訊;新版確切的顯示位置【待實機確認】。

五、為什麼以 v15.5 LTS 為基準?v16.0 又卡在哪?

選 v15.5 LTS 的五個理由

  1. GA、全平台:6G / 7G 硬體、VMware ESXi、KVM,以及 AWS、Azure、GCP、AliCloud、OCI 都有支援(第 5 章)。
  2. 支援期最長:LTS,估計至少到 2029-02。
  3. 部署模式齊全:STP Bridge、IMPVHA Bridge、Sniffing、Reverse Proxy、TRP、ABR 都能用(第 4 章)。
  4. 是升 16.0 的必經之路:升 v16.0 必須從任一 v15.5 LTS patch 起跳,v14.0 以下直接升級會被阻擋(第 13 章)。
  5. 舊 LTS 即將到期:v14.7 LTS 到 2027-02-28,現場若還在 14.7,現在就該排 15.5 升級。

v16.0 Controlled Availability 的限制

v16.0 採分階段釋出:先放出 NGRP 與 ABR,Bridge 與 Sniffing 排在最後。目前的 CA 版只適合「全部都是 Reverse Proxy / ABR、沒有 MX-HA 與 SOM 需求、跑在 VM 或硬體上」的環境,而且要開 ticket 申請。

項目【16.0】CA 狀態
Gateway 模式只支援 NGRP(Reverse Proxy)、ABR;不支援 STP / IMPVHA Bridge、Sniffing
Gateway HA用 VRRP;不支援 IMPVHA
管理端不支援 MX-HA、SOM
平台支援 VM 與硬體(release notes 列 6G 仍支援);不支援任何雲端 VM(AWS / GCP / Azure / AliCloud)
舊硬體M100、M150 不能升 v16.0;NG6 硬體不支援 USB 全新安裝
HSM不支援清單列出 Luna / nCipher HSM,同一頁卻又列支援 Luna HSM integration;互相矛盾,保守視為不支援【待實機確認】
整合Advanced Bot Protection 整合列為支援
作業系統Oracle Linux 9.5(首次離開 CentOS)
升級流程新的 client-server 程序:Gateway 先升、MX 後升,需另外部署「s7 server」;必須從 v15.5 LTS 任一 patch 起跳
AWSv16 起淘汰 AWS 的 HTTP Health Check Monitoring

路線圖的更正

v15.0 / 15.2 的 release notes 曾公告 v16 要淘汰 Bridge 與 TRP;v15.3 Patch 20 / v15.4 更正為 Bridge 保留、TRP 由 ABR 取代。舊部落格若寫「Bridge 要被淘汰」,是更正前的說法。

六、舊資料安全產品的去向

本課程只談 WAF。舊簡報裡的資料庫、檔案、SharePoint 產品,現況整理如下,不再展開。

舊簡報產品現況
資料庫安全 DAM / DBF(舊簡報 p.16)DAM(Database Activity Monitoring),歸在 Data Security Fabric(DSF) 產品線;最新 DAM v15.4(2026-10-08),LTS 為 DAM 14.19
(新)資料風險分析DRA(Data Risk Analytics),同屬 DSF
(新)統合平台DSF Hub(前身 Sonar);最新 v15.4(2026-08-12),LTS 為 4.19
檔案安全 FAM / FFW(舊簡報 p.17)FAM 改透過 DSF Hub 操作,多數情境使用 Thales CipherTrust Manager 的 agent;SecureSphere 舊 FAM 支援已於 2022-01-31 結束
SharePoint 安全(舊簡報 p.18)SecureSphere SharePoint Protection 支援已於 2022-01-31 結束

v14.4 起 WAF 與 DAM 分開發行,一台 MX 不能同時管 WAF 與 DAM Gateway,SOM 也不能混管。同一家客戶若兩者都有,就是兩套 MX。

八、常見踩坑

以為 SecureSphere 和 WAF Gateway 是兩套產品

同一系列,v14.4 是命名分界,GUI 與 CLI 仍處處是舊名。

拿 v13 / v14 時代的文件或部落格操作 v15.5

KRP、UUT、Hyper-V、Onebox 都已移除。以文件站對應版本的 bundle(網址帶 v15.5-waf-)為準。

看到 v16.0 就想升

CA 版要申請、不支援 Bridge / Sniffing / MX-HA / SOM / 雲端 VM。Bridge 或 Sniffing 部署升上去等於整個模式要重做。

忽略 EOS

V15.3 在 2026-11-09 到期;V14.7 LTS 在 2027-02-28 到期。停在 minor 版的現場最容易被忽略。

想在同一台 MX 加管 DAM Gateway

v14.4 起不可行,要另建 DAM 的 MX。

還在等原廠 email 通知

2026-02-15 起不再寄送,要主動到 Thales Support Portal 查看。
