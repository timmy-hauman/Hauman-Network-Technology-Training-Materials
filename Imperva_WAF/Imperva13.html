講師導言

WAF Gateway 的日常維運大多在 MX 的圖形介面完成,命令列(CLI)主要用在初始化、排障、備份與升級。這一章先釐清 impcli、impcfg、impctl 三者的分工,再整理常用指令、備份、升級路徑、疑難排解,以及開案前要收集哪些資訊。 原則和 2014 年一樣:把設備當黑盒子,能用 impcfg 就用 impcfg,impctl 只在必要時或原廠指示下使用。

Goals 本章學習目標

  • 說出 impcli、impcfg、impctl 各自的用途與風險
  • 知道 Sealed 模式限制了什麼,以及為什麼不要用 seal --strict
  • 熟悉 impcfg 的「S 存檔、A 套用」習慣,以及官方「Safe impctl Commands」的範圍
  • 依步驟完成 MX 完整匯出備份
  • 依目前版本判斷升到 v15.5 的路徑,並知道 v16.0 的限制
  • 用疑難排解檢查表縮小問題範圍,並備齊開案資訊

一、三種 CLI 的分工

先記住這一條

impctl 只在必要時或原廠指示下使用。能用 impcfg 就用 impcfg;官方的 Safe impctl Commands 清單以外,先開案詢問原廠。

工具是什麼什麼時候用風險
impcliImperva 專屬的受限 shell,SSH / console 登入後的預設環境一般查詢、備份匯出、上傳診斷資料、打 patch低;所有輸入都會被記錄
impcfg選單式設定工具網路介面、Gateway 工作模式、註冊 MX 等系統層設定中;官方建議以它改工作模式與網路設定
impctl底層控制工具,impcfg 實際上也是呼叫它啟停服務、重新註冊等;其餘只在原廠指示下高;官方註明僅限資深管理者

CLI 文件目前分四節:impcfg、impctl、impcli、Miscellaneous Commands(WAF Administration Guide)。

二、impcli 與 Sealed 模式

內建使用者

使用者說明
adminimpcli 預設使用者,預設密碼 admin,第一次登入必須改密碼
rootLinux 超級使用者;須在首次設定時改掉預設密碼才能使用;每 90 天須更換密碼;預設不能用 root 直接 SSH 登入
grub只用於開機載入程式密碼,不是 CLI 使用者;可在首次設定或用 impcfg 設定
  • 要取得 root:先以 CLI 使用者登入,再輸入 admin 指令切換。
  • 若必須允許某個 IP 以 root SSH 登入(例如原廠遠端支援期間):impctl hardening config --root-source-ip-exception=<IP address>。用完要移除例外【待實機確認:移除語法】。
  • 新版 shell(12 以上)已移除舊的 secure 使用者(以前的 impcfg 使用者)。

Sealed 模式(封存模式)

把設備鎖成只能執行有限指令。

項目一般(default)模式Sealed 模式
admin 切 root可不可
Run a Shell Command 的 Followed Action可不可(第 12 章)
scp 等安全檔案傳輸可不支援
解除—unseal + 封存時設定的密碼

封存步驟:輸入 seal → y → 設定解封密碼兩次 → 重新連線生效。解封密碼規則:10–14 字元,至少一個數字、一個大寫字母、一個指定特殊字元(* + = # % ^ : / ~ . , [ ] _),不得有超過兩個相同字元連續。

警告

seal --strict 是永久封存,無法解除。除非資安政策明確要求,不要使用。

三、impcfg:選單式設定

impcfg 是選單式工具,改完先按 S(Save) 存檔,再按 A(Apply) 套用;沒有 Apply 的變更不會生效。官方的選單路徑寫法例如:Top > Manage SecureSphere Gateway > Change operation mode(注意選單仍沿用 SecureSphere 舊名)。

常見工作位置參考章節
首次設定(管理 IP、DNS、NTP、密碼)首次登入精靈第 6 章
變更 Gateway 工作模式(含轉 ABR)Top > Manage SecureSphere Gateway > Change operation mode第 4 章
網路介面、bridge 介面設定Manage SecureSphere Gateway 底下第 4、5 章
註冊到 MXManage SecureSphere Gateway 底下【待實機確認】第 6 章

好習慣:一次只改一件事

變更前先截下 impcfg 首頁狀態(各元件狀態與標記),變更後比對;一次只改一件事,Apply 後確認 Gateway 在 MX 上恢復連線再做下一件。

四、impctl:只在必要時使用

使用原則

  • impctl 只在必要時或原廠指示下使用,官方註明僅限資深管理者。
  • 安全清單以外的 impctl 指令,先開案詢問原廠。
  • impctl teardown 屬破壞性操作,只在原廠指示下執行。

Safe impctl Commands:可以自行使用的範圍

指令用途
impctl show commands --verbose列出所有 impctl 指令與參數
impctl status顯示設備狀態
impctl server start / stop / restart啟動 / 停止 / 重啟 MX 服務
impctl gateway start / stop / restart啟動 / 停止 / 重啟 Gateway 服務
impctl gateway register / unregister將 Gateway 註冊到 / 自 MX 解除註冊
impctl gateway config --encryption=yes加密 Gateway 上的稽核檔(主要為資料庫稽核用途)
impctl hardening config --root-source-ip-exception=<IP>允許指定 IP 以 root SSH 登入

本教材另外會出現的兩個 impctl 指令

  • impctl gateway ngrp enable|disable:Bridge 模式轉 ABR 的步驟之一(完整流程見第 4 章,官方建議優先用 impcfg)。
  • impctl teardown:拆除設定,屬破壞性操作,只在原廠指示下執行。

重要提醒:重啟會中斷服務

impctl gateway restart 會中斷 inline 流量。Fail Open 只在有實體 bypass 網卡的硬體上生效,虛擬機只支援 Fail Close(第 5 章);在 VM 上重啟 Gateway,單台或沒有 VRRP 冗餘時等於停機;有 VRRP 時要先確認已切到另一台。要排維護時段。

六、備份

MX 是設定的正本。Site Tree、政策、Web Profile 都存在 MX 資料庫,所以備份重點在 MX【推論】。

完整匯出(升級前必做)

官方 Backing Up the System。

SSH / console:mx01(10.0.30.10)
# 先以 CLI 使用者登入,再用 admin 指令切換成 root impcli> admin # 執行完整匯出 # full_expimp.sh Operation: 1 Password: ******** Export Type: 1 Export failed archived data? (default n): n Backup file name (default /var/tmp/SecureSphere_<date>.tgz): Confirm? Y ... full_expimp completed successfully on <date>
示意畫面:提示文字依官方文件步驟整理,英文提示字樣待實機確認。Password 為 system 使用者密碼;Export failed archived data 為是否匯出失敗的封存資料;Confirm 為最後確認。
  1. 1以 root 登入 MX(由 impcli 執行 admin 切換)。
  2. 2執行 full_expimp.sh。
  3. 3依提示輸入:Operation 選 1;Password 輸入首次設定時的 system 使用者密碼;Export Type 選 1。
  4. 4是否匯出失敗的封存資料(預設 n)。
  5. 5備份檔名:預設 /var/tmp/SecureSphere_<日期>.tgz;自訂時要寫完整路徑。
  6. 6輸入 Y 確認,等待完成。事件量大時會很久,可在另一個 shell 用 tail 看同目錄的記錄檔;成功時結尾會出現 full_expimp completed successfully on <date>。
  7. 7把備份檔複製到其他機器。
  8. 8另外複製報表目錄 /opt/SecureSphere/server/SecureSphere/jakarta-tomcat-secsph/webapps/SecureSphere/WEB-INF/reptemp。

其他方式

  • 匯出可用 GUI、互動式 CLI 或非互動式 CLI;匯入不能用 GUI,因為匯入時必須停止 MX 服務。
  • impcli 的 export-local / export-remote 適合排程或在 Sealed 模式下使用。
  • VMware 上的 WAF Gateway,升級前另拍 VM snapshot。
  • 告警的長期保存用封存工作搭配 Archive to SCP Location 或 Archive to Amazon S3(第 12 章)。

建議週期

每週一次例行匯出 + 每次重大變更與升級前加做;備份檔保留至少兩份、放在 WAF 以外的位置,並每季做一次匯入演練(在測試 MX)。

七、升級路徑

升到 v15.5

官方 Upgrade Path - Minimum Upgrade Version。

目前版本升級路徑
v14.7.x先升到最新 v14.7 LTS patch,再升 15.5
v14.0 – v14.6先升到 v14.7(最新 LTS patch),再升 15.5
更舊版本或 v15.0 – v15.4路徑以官方 v15.5 Upgrade Guide(Minimum Upgrade Version)為準【待實機確認】
  • 7G 硬體要先確認版本在 14.7.0.50 以上。
  • 升級前要跑官方的 Mandatory Pre-Upgrade Checklist 與 Feature Specific Pre-Upgrade Checklist。
  • 元件升級順序(MX、SOM、Gateway 誰先)見 v15.5 Upgrade Guide 的「Upgrade Sequence - What to Upgrade First」【待實機確認】。
  • MX-HA 環境的升級程序另有規範【待實機確認】。

升到 v16.0

  • 必須從任一 v15.5 LTS patch 起跳。
  • 改用新的 client-server 升級程序:Gateway 先升、MX 後升,需要另外部署「s7 server」。
  • OS 由 CentOS 7.9 改為 Oracle Linux 9.5。
  • v16.0 只有 Controlled Availability,只支援 NGRP / ABR、VRRP;不支援 Bridge、Sniffing、IMPVHA(GW)、MX-HA、SOM、雲端 VM;M100、M150 不能升 16.0。目前跑 Bridge 或 Sniffing 的環境不要規劃升 16.0。

升級前檢查

  1. 1讀目標版本 Release Notes 的「不再支援」項目(例如 KRP 已移除、Onebox 不支援、Hyper-V 不支援)。
  2. 2對照 EOS 表確認目標版本支援期(第 1 章)。
  3. 3完成第六節的完整匯出,VM 拍 snapshot。
  4. 4安排維護時段;VM 只有 Fail Close,升級期間 inline 流量會中斷。
  5. 5升級後:確認 Gateway 全部在 MX 上線、ADC 內容版本、政策套用、送 Syslog 正常。

九、開案前收集資訊

支援入口已改為 Thales Support Portal;2026-02-15 起不再直接以 email 寄送產品通知,要自行在入口訂閱。開案前備齊:

  1. 1版本:MX、Gateway(含 SOM)的版本與 patch 號(impctl status、GUI)。
  2. 2平台:硬體型號或虛擬型號、hypervisor / 雲端平台。
  3. 3部署:Gateway Group 的 Gateway Mode、Fail Mode、HA 方式,附簡單拓撲圖。
  4. 4時間軸:問題開始時間(註明時區)、最近一次變更(對照系統事件記錄,第 12 章)。
  5. 5證據:相關告警 / 違規 ID、錯誤訊息、截圖。

十一、常見踩坑

impcfg 改完沒按 A

只存檔沒套用,以為改了其實沒生效。

在 VM 上重啟 Gateway 沒排停機

VM 只有 Fail Close,重啟就是斷線。

用 seal --strict

永久封存無法解除,之後原廠要 root 協助也進不去。

root 密碼過期

root 每 90 天要換,緊急時才發現過期。把換密碼排入例行工作。

備份只放在 MX 本機

預設路徑 /var/tmp,MX 壞掉時備份一起不見。

跳版升級

v14.0–14.6 不能直接升 15.5,要先升到 v14.7(最新 LTS patch);更舊版本或 15.0–15.4 的路徑以官方 v15.5 Upgrade Guide 為準【待實機確認】。
