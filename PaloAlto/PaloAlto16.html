Palo Alto Networks NGFW 實戰課程

進階篇 - 單元 16：GlobalProtect 與 VPN

講師導言

前面的章節處理的都是「已經走到防火牆面前」的流量。這一章要談的是另一件事：怎麼讓不在同一個網路裡的人與據點，安全地走進來。 VPN 在防火牆上有兩種完全不同的情境：兩個據點之間的站對站 IPsec，以及個別使用者遠端連回公司的 GlobalProtect。 前者像是把幾塊積木依序疊好（設定檔、Gateway、通道、介面、路由、政策），後者則是 Portal、Gateway、App 三個角色分工。 學完這一章，你會知道每一塊要放在哪、彼此怎麼相依，也會知道通道一旦建好，VPN 流量是從哪個區域進入第 8 章的安全政策、又如何和第 14 章的 User-ID 接上。

Goals 本章學習目標

  • 分辨站對站 IPsec VPN 與 GlobalProtect 遠端存取的使用情境與設定位置
  • 說明 IKE 兩個階段，以及 IKE Crypto、IKE Gateway、IPsec Crypto、IPsec Tunnel、Tunnel Interface 的相依關係，並依順序完成設定
  • 為通道介面指定區域與虛擬路由器，補上路由與安全政策，並說明 Proxy ID 何時需要
  • 在 Network > IPSec Tunnels 判讀三種狀態燈號，並用 CLI 與錯誤訊息縮小問題範圍
  • 說明 GlobalProtect 的 Portal、Gateway、App 各自的職責，以及內部與外部 Gateway 的差別
  • 說明 Agent 設定如何被挑選、全通道與分流的差異、HIP 檢查與授權的概況，以及 VPN 流量與 User-ID 的銜接

Concept 一、VPN 兩種情境

比較項目 站對站 IPsec VPN GlobalProtect 遠端存取
連線的兩端兩個網路（LAN）之間，可以是兩台 Palo Alto 防火牆，也可以是一台防火牆加第三方設備個別使用者的設備（App）連到防火牆上的 Gateway
誰在驗證兩個 VPN 對等端（peer）互相驗證，使用預共享金鑰或憑證使用者向 Portal 與 Gateway 驗證（本機、外部伺服器、憑證、雙因素等）
主要設定位置Network > IPSec Tunnels 與 Network > Network ProfilesNetwork > GlobalProtect > Portals 與 Gateways
授權PAN-OS 的站對站 VPN 不需授權基本的遠端存取 VPN 不需授權；HIP 檢查等進階功能需要 GlobalProtect Gateway 授權（見第四節）

🏢 生活化比喻：兩棟大樓的專用通道，與出差員工的訪客證

  • 站對站 IPsec：兩棟辦公大樓之間蓋一條專用的封閉通道。兩邊的管理室要先對暗號（IKE 驗證），再談好貨物用什麼箱子、什麼鎖來運送（IPsec 參數）。通道蓋好之後，大樓裡的人不用知道通道怎麼運作，照一般路線走進去就行（路由）。
  • GlobalProtect：員工出差在外，先到總機（Portal）領取通行設定與可用的入口清單，再到合適的閘門（Gateway）刷證進入。進門之後看得到他是誰（User-ID），還能順便檢查他帶的設備狀況（HIP）。

PAN-OS 的站對站 VPN 是「路由式」

原廠說明：IPsec 會把原始封包再包進一個新的 IP 標頭（來源是本地 VPN 對等端、目的是遠端對等端），遠端防火牆收到後拆掉外層標頭，原始封包再繼續送往目的地。 防火牆是依目的 IP 做路由決定，被路由進通道的流量，就當成 VPN 流量處理。原廠只描述路由式（route-based）VPN，並說明防火牆能與第三方的政策式（policy-based）VPN 設備互通。

介面名稱、位址與區域名稱僅為示意，請換成你自己環境的值。

承接前面的章節

通道介面（Tunnel Interface）、Layer 3 區域（建議另建一個 VPN 專用區域）、虛擬路由器，第 5、6 章已經介紹過基本概念。這一章不重講，而是把它們接到 VPN 的積木鏈上：通道介面就是路由與安全政策看到 VPN 的那個「門」。

注意：區域類型裡的 Tunnel 是給通道內容檢查（Tunnel Content Inspection）用的，不是拿來放 IPsec 通道介面的區域；通道介面所屬的區域，請建立 Layer 3 類型（實際選項以實機為準）。

Building Blocks 二、站對站 IPsec 的積木

要建立 VPN 通道，兩端要先互相驗證，驗證成功之後才協商資料要怎麼加密。在 PAN-OS 裡，這兩個階段各有一份設定檔： IKE Crypto 設定檔管第一階段（IKE phase 1，驗證對方並交換金鑰），IPsec Crypto 設定檔管第二階段（IPsec，也就是資料通道本身）。

積木 選單路徑 負責什麼
IKE Crypto 設定檔Network > Network Profiles > IKE Crypto第一階段參數：DH Group、Authentication（雜湊）、Encryption、Key Lifetime（預設 8 小時）
IKE GatewayNetwork > Network Profiles > IKE Gateways通道兩端的身分：本地介面與位址、對方位址、驗證方式；並在進階選項中掛上 IKE Crypto 設定檔
IPsec Crypto 設定檔Network > Network Profiles > IPSec Crypto第二階段參數：IPSec Protocol（ESP 或 AH）、Encryption、Authentication、DH Group（PFS）、Lifetime
Tunnel InterfaceNetwork > Interfaces > Tunnel邏輯介面；放進區域、掛上虛擬路由器，路由與安全政策都靠它看見通道
IPsec TunnelNetwork > IPSec Tunnels把上面幾塊接起來：選 Tunnel Interface、Type（Auto Key）、IKE Gateway、IPSec Crypto 設定檔；另有 Tunnel Monitor 與 Proxy IDs

箭頭由被引用者指向引用者：箭頭起點的積木要先建好，終點才能選到它。這也決定了建置的先後順序。路由與安全政策引用的是 Tunnel Interface（靜態路由選它當出口介面，安全政策看它所屬的區域），所以 Tunnel Interface 有兩支箭頭：一支指向 IPsec Tunnel，一支指向路由與安全政策。

IKE Gateway 要設定哪些東西

Version

IKEv1 only、IKEv2 only，或 IKEv2 preferred（對方不支援 IKEv2 時退回 IKEv1）。所選版本會決定進階選項頁籤出現哪些項目。

本地端點

選 Address Type（IPv4 或 IPv6）、對外的實體 Interface，以及作為通道端點、可從外部路由到的 Local IP Address。

Peer IP Address Type

IP、FQDN 或 Dynamic。對方位址會變動時，用 FQDN 可以免去逐次改位址；Dynamic 用於不知道對方位址、由對方主動發起協商。

Authentication

Pre-Shared Key（最多 255 個字元，原廠建議用難以被字典攻擊破解的金鑰）或 Certificate。還有 Local / Peer Identification，留白時以本地、對方的 IP 位址作為身分。

  • Passive Mode：啟用後，防火牆只回應 IKE 連線要求、不主動發起。
  • NAT Traversal：兩個 Gateway 中間有設備做 NAT 時啟用，用 UDP 封裝讓通道穿過 NAT 設備。
  • IKEv1 專屬：Exchange Mode（auto、aggressive、main），不選 auto 時兩邊必須一致；Dead Peer Detection（Interval 2 到 100 秒、Retry 2 到 100）。
  • IKEv2 專屬：Liveness Check（Interval 預設 5 秒）。

加密演算法怎麼選：原廠的建議

以下為原廠對 IKE Crypto 與 IPSec Crypto 設定檔的建議大意

  • 選對方能支援的最強驗證與加密演算法；不確定對方支援什麼時，可以依「由強到弱」的順序放入多個演算法，雙方會協商出共同支援的最強者。
  • 驗證（雜湊）演算法用 SHA-256 以上，長時間存在的連線偏好 SHA-384 以上；不要用 SHA-1 與 MD5。
  • 加密演算法用 AES；DES 與 3DES 屬於弱演算法。
  • IPsec 協定方面，原廠最佳實務是選 ESP 而不是 AH。
  • DH Group：為了最高安全性，選編號最高的群組。

本課程不另外列出「推薦組合」，實際選擇請對照你這台防火牆的版本與對方設備支援的清單。

設定順序檢查清單

建議的設定先後順序如下，兩端防火牆各做一遍。

  1. 1. 對外的 Layer 3 介面：作為 IKE 第一階段端點，放進外部區域、指定虛擬路由器與位址。Network > Interfaces > Ethernet
  2. 2. 通道介面：新增 tunnel 介面，放進專屬的 VPN 區域（Layer 3 類型），指定虛擬路由器；若要做通道監控或動態路由，要給它位址。Network > Interfaces > Tunnel
  3. 3. 路由：靜態路由把對方網段指向通道介面，或使用動態路由。Network > Virtual Routers
  4. 4. IKE Crypto 與 IPsec Crypto 設定檔：兩端的值必須相容。Network > Network Profiles
  5. 5. IKE Gateway：介面、本地位址、對方位址、金鑰或憑證，並在進階選項掛上 IKE Crypto 設定檔。
  6. 6. IPsec Tunnel：選 Tunnel Interface、Auto Key、IKE Gateway、IPSec Crypto 設定檔；視需要加 Tunnel Monitor 與 Proxy IDs。
  7. 7. 安全政策：範例放行外部區域與 VPN 區域之間所需的流量；兩端 LAN 互通的流量，還要放行 VPN 區域與內部區域之間（講師補充）。Policies > Security
  8. 8. Commit 並驗證：到 Network > IPSec Tunnels 看狀態燈號。

最常見的踩坑：兩邊的提案對不上

  • IKE 要成功，兩端必須交換相容的 IKE 參數；第二階段也一樣要有相容的 IPsec 參數。IKE Crypto 設定檔中，兩邊要至少有一組共同的 Encryption、Authentication 與 DH Group，否則會看到 no proposal chosen 或 Unable to process peer's SA payload 這類訊息。
  • PFS 設定要兩邊一致（同時啟用或同時停用，DH Group 也要有交集）。原廠特別提醒：PFS 不會在初次建立通道時協商，所以不一致的問題要等到第一次 rekey 才會讓通道失敗，建置時就要在兩邊逐一核對。
  • Pre-shared Key 兩邊要一模一樣；Local / Peer Identification 若有指定，兩邊也要彼此對應。

版本差異

  • IKE Crypto 設定檔的 DH Group 21、16、15，以及 IPsec Crypto 的 group15、16、21，需要 PAN-OS 10.2.0 以上；其中 IKE 這三個群組僅限 IKEv2 only 模式。
  • IKE Crypto 的 AES-GCM（aes-128-gcm、aes-256-gcm）自 PAN-OS 10.0.3 起提供，需 IKEv2，且 Authentication 必須選 non-auth，否則 Commit 會失敗。
  • IKE Gateway 的 Interface 欄位，自 PAN-OS 11.1.5 起可選用 DHCPv6、PPPoEv6 或 5G 數據機設定的介面。
  • 後量子密碼的 IKEv2 VPN 設定（Quantum Resistant IKEv2 VPN）不在本課程範圍。Strata Cloud Manager 與 Prisma Access 的欄位清單與 PAN-OS 不完全相同，本章只談 PAN-OS。

Routing & Policy 三、通道介面、路由與政策

通道介面：區域與虛擬路由器

新增通道介面時，在 Network > Interfaces > Tunnel 輸入介面編號尾碼（例如 .2），在 Config 頁籤指定Security Zone與Virtual Router。 區域可以直接用內部的 trust 區域，但原廠建議另建一個專屬的 VPN 區域（名稱自訂，例如 vpn_tun），這樣才能用安全政策精確管控 VPN 進出的流量。IP 位址則是選填，但要做通道監控或動態路由時就需要。

示意圖。把第 1 章的「查來源區域、查路由決定目的區域、比對安全政策」套在 VPN 上：通道介面所屬的區域，就是安全政策裡的來源或目的區域。

站對站與 GlobalProtect 的通道介面不一樣

項目站對站 IPsec 通道介面GlobalProtect 外部 Gateway 通道介面
Virtual Router範例指定為 default（要掛上虛擬路由器，靜態路由才能指向它）原廠建議將 Virtual Router 設為 None
IP 位址選填；要做通道監控或動態路由時需要除非用動態路由，否則不需要；可作為疑難排解之用
區域建議專屬 VPN 區域建議專屬區域（例如 corp-vpn）並啟用 User Identification

路由：靜態或動態

  • 靜態路由：到 Network > Virtual Routers，選擇通道介面所在的虛擬路由器，在 Static Route 新增「對方網段，介面選通道介面」。原廠範例：Peer A 把 192.168.69.0/24 指向 tunnel.10。
  • 動態路由：原廠範例使用 OSPF（IPv6 用 OSPFv3），範例同時有靜態與動態路由，並要求每個通道介面都有固定 IP 位址。
  • 在這個範例中，Peer B 同時跑靜態路由和 OSPF，所以需要重新分發設定檔（Redistribution Profile）把靜態路由匯入 OSPF，否則兩種路由協定在同一個虛擬路由器上不會互通路由資訊。
  • 驗證 OSPF 時，原廠範例用 show routing protocol ospf neighbor 與 show routing route。
  • 以上路徑與指令以傳統路由引擎為準；若啟用 Advanced Routing Engine，路由改在 Logical Router 設定（見第 6 章）。

安全政策：通道區域也要放行

通道建好、路由也有了，流量還是要通過安全政策。到 Policies > Security，原廠範例建立的是外部（untrust）區域與 VPN 區域之間、兩個方向的規則。 實務上，兩端 LAN 互通的流量要通過 VPN 區域與內部（trust）區域之間的規則，這一條一定要有（講師補充）。 使用專屬 VPN 區域的好處，就是這些規則的範圍可以只針對 VPN 流量寫，寫法與第 8、9 章完全相同。

Proxy ID：只有對方是政策式設備時才需要

  • 在 Network > IPSec Tunnels > Proxy IDs 頁籤，可新增 Proxy ID：名稱、Local、Remote 網段，以及 Protocol（Number、Any、TCP、UDP）。
  • 原廠寫明「只有在 VPN 對方使用政策式 VPN 時才需要」。沒有設定時，防火牆預設 Proxy ID 是來源 0.0.0.0/0、目的 0.0.0.0/0、應用程式 any（預設值以實機為準），與政策式對方交換時會導致 VPN 建立失敗。
  • Proxy ID 兩端必須互為鏡像。例如（範例位址）這邊 local 是 192.0.2.0/24、peer 是 198.51.100.0/24，另一邊就必須 local 198.51.100.0/24、peer 192.0.2.0/24；子網路遮罩不同（例如一邊 /32、一邊 /16）也會讓通道建不起來。
  • Proxy ID 有數量上限；超過時 Commit 會出現 tunnel binding 上限錯誤。原廠的處理是再建一條使用相同第一、二階段設定的通道，並把 Proxy ID 的位址合併成超網路（supernet）來減少項目。

通道監控與狀態燈號

Tunnel Monitor

在 IPsec Tunnel 的 Show Advanced Options 勾選 Tunnel Monitor，輸入通道對端的 Destination IP，選一個監控設定檔。通道介面必須有 IP 位址才能監控。

設定檔在 Network > Network Profiles > Monitor：Action 可選 Wait Recover（仍把通道介面當成存在）或 Fail Over（停用通道介面及其路由，讓流量改走備援路徑）；Interval 預設 3 秒，Threshold 預設 5 次。

Network > IPSec Tunnels 的三種狀態

  • Tunnel Status：綠色代表有有效的 IPsec SA（第二階段），紅色代表不存在或已過期。
  • IKE Gateway Status：綠色代表有有效的第一階段 SA，紅色代表不存在或已過期。
  • Tunnel Interface Status：綠色代表介面是 up；紅色是啟用通道監控、且監控狀態為 down 而讓介面 down。

常見踩坑：通道是綠的，流量卻不通

  • 沒有指向通道介面的路由：封包根本不會被送進通道，IKE 與 IPsec 狀態再漂亮也沒用。
  • 漏了通道區域的安全政策：用專屬 VPN 區域時，必須明確寫出 VPN 區域與內部區域（以及外部區域）之間的規則；否則流量會被擋在政策這一關。
  • 與其他廠牌設備對接時 Proxy ID 對不上：對方是政策式時，要把對方定義的本地、遠端網段與協定，鏡像填進 Proxy ID，連遮罩都要一致。
  • 靜態與動態路由混用時，忘了做重新分發，會造成其中一邊學不到對方網段。

原廠文件說法不一：Tunnel Interface Status

有的說明只寫「紅色代表啟用通道監控且狀態為 down」；有的則補充：沒有啟用通道監控時，介面也顯示綠色。不同說明的描述詳略不一，實際燈號請以實機為準。

Components 四、GlobalProtect 元件

Portal

管理中心：把設定下發給終端，包含可用的 Gateway 清單與連線所需的客戶端憑證；控制 App 的行為與散布方式；若使用 HIP，也定義要收集哪些主機資料。

Gateway

對來自 App 的流量執行安全政策；可提供遠端使用者 VPN 通道，也可以只對內部資源套用政策。啟用 HIP 時，由主機回報的資料產生 HIP 報告，並用於政策判斷。

App（Agent）

安裝在終端上的程式，經由 Portal 與 Gateway 存取網路資源。Windows、macOS 的 App 由 Portal 散布；行動版 App 來自官方應用程式商店，或經由 MDM 部署。

Portal 與 Gateway 可以放在同一台防火牆上，也可以把多個 Gateway 分散部署。兩者都能設定在任何 Palo Alto Networks NGFW 的介面上。

🏨 生活化比喻：飯店櫃檯與房門

  • Portal：大廳櫃檯。先在這裡確認身分，領到房卡規則與可用的樓層清單。
  • Gateway：各樓層的門禁。再次確認身分，並決定你這張卡能進哪些房間（安全政策），必要時還看你的行李是否合規（HIP）。
  • App：你手上的房卡。刷卡的方式、能不能自己停用，都是櫃檯在設定裡事先決定的。

內部與外部 Gateway

種類位置與用途App 如何選用
內部 Gateway設定在內部網路的介面上，對內部資源套用安全政策；可搭配 User-ID 與 HIP 檢查，通道模式或非通道模式均可App 先做內部主機偵測（對 Portal 設定中指定的內部主機做反向 DNS 查詢）判斷自己是否在內網；偵測成功就連內部 Gateway
外部 Gateway（自動探索）位於企業網路之外，提供安全強制與／或 VPN 存取預設連到最佳的一台，依 Gateway 的優先順序、來源區域與回應時間判斷
外部 Gateway（手動）同樣位於外部，可以有不同的驗證要求只在使用者主動發起時才連線；需在 App 設定中標示為 Manual

只有內部 Gateway 的部署，所有終端都必須設為 User-logon（Always On），不支援 On-Demand。內部主機偵測對 Portal 的 Internal 頁籤另有 Source Address 欄位：只有 IP 位址落在該位址範圍內的 App，才能向該內部 Gateway 驗證與回報 HIP。

使用者驗證

App 第一次連線時先向 Portal 驗證，成功後 Portal 下發設定（含 Gateway 清單，必要時有客戶端憑證），App 再連到 Gateway，Gateway 同樣要驗證。可用的方式：

  • 本機（Local）：帳號建在防火牆上，原廠說明僅適合小型部署。
  • 外部驗證：LDAP、Kerberos、TACACS+、SAML、RADIUS，包含 OTP 等雙因素。Portal 與各 Gateway 可以各用不同的 Authentication Profile。
  • 客戶端憑證：由憑證取得使用者名稱並驗證；智慧卡也透過 Certificate Profile 處理。
  • 雙因素：同時設定憑證設定檔與驗證設定檔。
  • 單一登入（SSO）：Windows 與 macOS 上預設啟用，使用作業系統登入憑證（SAML SSO 在 macOS 不支援）。
  • 原廠另提醒：GlobalProtect 不支援 802.1X；若要依 AD 群組寫政策，改用 User-ID 加群組對應。

Portal 的 Authentication 頁籤可以依 OS 建立多組 Client Authentication，同一個 OS 有多組時，防火牆一律採用清單最上面的那一組。「Allow Authentication with User Credentials OR Client Certificate」選 No 時，使用者必須同時提供帳密與客戶端憑證，這時 Certificate Profile 為必填。

客戶端設定如何被挑選

  • Portal 端：Agent 頁籤裡有一份設定清單，Portal 依使用者或群組名稱與用戶端 OS 挑選要下發哪一份，並由清單最上方開始比對。比對條件在 Config Selection Criteria 頁籤：OS、User/User Group（需先設定群組對應；可選 any 或 pre-logon），另有 Device Checks 與 Custom Checks（Windows 登錄檔、macOS plist）。特定使用者或特定 OS 的設定要放在較一般的設定上面，可用 Move Up、Move Down 調整。
  • Gateway 端：Agent > Client Settings 也有一組條件：Source User、OS、Source Address。使用者、OS、來源位址三者同時符合，該設定才會下發。

連線方式（Connect Method）

方式行為
On-demand使用者手動啟動 App 並連到 Portal；原廠說明主要用於遠端存取
User-logon (Always On)使用者登入作業系統後，App 自動連到 Portal 取得設定，再與 Gateway 建立通道
Pre-logon (Always On)使用者登入前就先連線，以預先安裝的機器憑證驗證，登入後自動維持連線
Pre-logon then On-demand登入前先連線，登入後使用者需手動啟動連線

設定位置：Network > GlobalProtect > Portals > 選擇 Portal > Agent > 選擇設定 > App，欄位為 Connect Method。行動裝置不支援 pre-logon，會自動退回對應的方式。

全通道與分流（Split Tunnel）

沒有設定分流時，所有流量都走進 VPN 通道（全通道）。分流則讓部分流量不進通道。設定位置：Network > GlobalProtect > Gateways > 選擇 Gateway > Agent > Client Settings > 選擇設定 > Split Tunnel。

Access Route（依網段）

  • Include：要走通道的網段；放入 0.0.0.0/0 與 ::/0 代表全部。
  • Exclude：不走通道、使用實體網卡的網段；Exclude 的網段應該比 Include 更具體，否則可能排除到超出預期的範圍。
  • No direct access to local network：連線期間封鎖對本地網路資源（如印表機）的直接存取，原廠建議用於不受信任的網路。

Domain and Application

  • Include / Exclude Domain（可加連接埠，例如 *.office365.com），各最多 200 筆。
  • Include / Exclude Client Application Process Name（程序完整路徑），各最多 200 筆。
  • Linux 終端僅支援網域與網段型分流，不支援應用程式型。

踩坑：走分流的流量，防火牆看不到

原廠明確說明：走分流的流量不會經過 Gateway 防火牆檢查，也就拿不到 Palo Alto Networks 的威脅防護。決定要把哪些流量排除之前，要想清楚這是風險取捨。原廠列出適合分流的情境，例如：延遲敏感的 VoIP、影音串流，以及 Microsoft 365 的特定最佳化網段。

HIP（主機資訊檢查）概觀

  • HIP Objects 是用來過濾 App 回報之原始資料的比對條件；HIP Profiles 是 HIP Objects 的集合，可用 AND、OR、NOT 與括號組合。路徑：Objects > GlobalProtect > HIP Objects 與 HIP Profiles。
  • HIP Profile 掛在安全政策規則上；流量符合該 HIP Profile 就套用這條規則，不符合則繼續比對下一條。原廠內部 Gateway 範例，就是用「缺少修補程式」的 HIP Profile 搭配使用者或群組。
  • 原廠建議 HIP Objects 保持單純，每個只比對一件事（例如某個必要軟體、網域成員資格、OS）。

授權概觀

授權情形
不需要 GlobalProtect 授權以單一或多個內部／外部 Gateway 提供遠端存取 VPN，以及 Windows、macOS 的 App，原廠寫明不需要任何 GlobalProtect 授權

版本差異

  • 原廠文件現在稱終端程式為「GlobalProtect app」，但 Portal 設定畫面的頁籤仍叫 Agent（Agent Config Selection Criteria、Agent App 等），舊教材與現行介面兩種用語會並存。
  • GlobalProtect 現行的 App 版本線為 6.x（目前可見 6.3、6.2、6.1、6.0）。部分功能與 App 版本綁定，例如應用程式路徑可用萬用字元（*）設定分流，自 App 6.3.1 起提供，Intelligent Internal Host Detection 也需要 App 6.3.1 以上；實際可用功能要同時看 PAN-OS 與 App 版本。
  • Portal、Gateway 欄位以 PAN-OS 12.1、12.2 為準，兩版在 Connect Method 與 Tunnel Settings 的描述一致；12.2 的 Tunnel Settings 把 IKEv2 only 與 IKEv2 preferred 的標籤寫成相同文字，疑似原廠筆誤，操作時以畫面為準。
  • 在 Tunnel Settings 勾選 Enable IPSec 後，IPsec 成為主要通道方式、SSL-VPN 為備援。GlobalProtect 有自己專用的 IPSec Crypto 設定檔，與前面站對站的 IPsec Crypto 設定檔不同；原廠建議把加密順序調整為 aes-256-gcm、aes-128-gcm、aes-128-cbc，驗證選項目前只有 sha1，預設內容以實機為準。

Flow 五、連線流程與疑難排解

GlobalProtect 的連線流程

原廠對 Always On 的描述是：App 先連 Portal，送出使用者與主機資訊並取得客戶端設定，接著依設定連到 Gateway。若 Portal 設定了內部主機偵測，App 會先判斷自己在內網還是外網。

若設定中有多個外部 Gateway，App 會嘗試連線到清單中所有 Gateway，依優先順序和回應時間挑選。現行 App（4.0.3 起）會先嘗試 Highest、High、Medium 優先順序的 Gateway，不論回應時間；同一優先順序才比較回應時間。App 6.3.1 起，Portal 可設定 Best Gateway Selection 的挑選準則。

VPN 流量從哪裡進入處理流程

  • 通道終止的那個區域，就是安全政策裡看到的來源區域；原廠建議建立專屬區域（如 corp-vpn），並在該區域啟用 User Identification。使用獨立通道區域時，必須另寫安全政策允許它與 trust 區域之間的流量。
  • 與第 14 章 User-ID 的銜接：原廠指出，對行動與遠端使用者，GlobalProtect 終端會把使用者對應資訊直接提供給防火牆；每位使用者都要輸入帳密才能 VPN，所以位址與使用者名稱的對應是確切已知的。原廠也建議以 GlobalProtect 作為使用者對應的來源，因為它能確保使用者對應準確。
  • 因此在 VPN 區域的規則裡，可以直接用使用者或群組、再加 HIP 設定檔當條件，不必再靠 IP 位址去猜人。

站對站疑難排解：CLI 與錯誤訊息

步驟指令作用
啟動第一階段test vpn ike-sa gateway <gateway_name>開始與該 Gateway 做 IKE 協商（也可以由通道內 ping 觸發）
確認第一階段show vpn ike-sa gateway <gateway_name>沒有看到 SA 時，到系統日誌查失敗原因
啟動第二階段test vpn ipsec-sa tunnel <tunnel_name>開始該通道的 IPsec 協商
確認第二階段show vpn ipsec-sa tunnel <tunnel_name>確認第二階段 SA 出現
看整體流量show vpn flow顯示各通道名稱、狀態、本地與對方 IP、通道介面等

其他原廠列出的指令包含 show vpn ike-sa、show vpn ipsec-sa、show vpn gateway、show vpn tunnel、clear vpn ike-sa gateway <gateway> 等。clear 與 IKE Gateway、IPSec Tunnel 的重啟（restart）會中斷既有連線，操作前先確認時機。

症狀原廠建議的檢查方向
第一階段逾時，或找不到該對方位址的設定確認 IKE Gateway 裡兩端的公開 IP 正確；確認兩端能互相 ping、路由沒問題
no proposal chosen／Unable to process peer's SA payload檢查 IKE Crypto 設定檔，兩邊要有共同的 Encryption、Authentication 與 DH Group
第二階段 PFS 或 DH 群組不一致兩邊 PFS 同為啟用或同為停用，且 DH Group 要相符
對方是政策式 VPN，Proxy ID 失敗在 Palo Alto 防火牆設定 Proxy ID，並確認兩端互為鏡像

GlobalProtect 疑難排解：先看哪裡

  • 終端紀錄檔：原廠分流驗證步驟以終端上的 PanGPS.log 確認 Gateway 是否下發了排除路由；Windows 可用 route print 確認被排除的網段是否改走實體網卡。
  • 設定挑選順序：使用者拿到的設定不如預期，先檢查 Portal Agent 清單的順序，特定設定是否放在一般設定上方。
  • 憑證與位址：Portal 的 SSL/TLS Service Profile 所用憑證，其 CN 與 SAN 必須符合 General 頁籤所選介面的 IP 位址或 FQDN；Portal 與 Gateway 共用同一個介面時，需使用 CN 符合該介面 FQDN 的同一份伺服器憑證。
  • HIP 比對：Gateway 收到 App 回報的 HIP 資料後，只要符合你定義的 HIP Object 或 HIP Profile，就會寫一筆 HIP Match 日誌；沒有符合任何物件就不會有紀錄。
  • 通道區域：政策看不到使用者，先確認通道終止的區域是否已啟用 User Identification；流量被擋，先確認該 VPN 區域與內部區域之間有沒有寫規則。
