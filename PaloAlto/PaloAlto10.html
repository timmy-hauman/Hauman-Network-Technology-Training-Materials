政策篇 - 單元 10：Source NAT

講師導言

內網主機用的是私有位址，這些位址在網際網路上根本無法路由。要讓大家上網，防火牆必須在封包離開前把來源位址換成公開位址，這就是 Source NAT。 這一章會先釐清 NAT 在處理流程中的位置，再逐一看三種轉換類型、DIPP 為什麼能讓很多人共用一個位址，最後做一個完整範例： NAT 規則和安全規則各填什麼。第 1 章提過的「位址看轉換前、區域看轉換後」，這章會用真正的規則表再練一次。

Goals 本章學習目標

  • 分辨 Source NAT 與 Destination NAT 各自解決什麼問題，並說出 NAT 在流量處理流程中的位置
  • 比較 Static IP、Dynamic IP、Dynamic IP and Port（DIPP）三種轉換類型，依需求選用
  • 說明 DIPP 超額訂閱（Oversubscription）的意義與設定位置
  • 在 NAT 規則與安全規則中，正確填寫轉換前的位址與轉換後的區域
  • 在 Policies > NAT 建立 Static 1:1、Dynamic IP、DIPP 三種 Source NAT 規則

Concept 一、NAT 類型與它在流程中的位置

NAT（Network Address Translation）依「改哪一端的位址」分成兩大類。Source NAT 改來源位址，常用於內部使用者往外上網； Destination NAT 改目的位址，常用於讓外部使用者連到內部伺服器（第 11 章）。

比較項目 Source NAT Destination NAT
改變的欄位來源 IP（DIPP 還會改來源連接埠）目的 IP（可另外轉換目的連接埠）
典型情境內部使用者存取網際網路（出站流量）外部使用者存取內部伺服器（入站流量）

NAT 在流量處理流程中的位置

NAT 規則是用區域去比對的（教材投影片的流程圖也把 NAT 標在轉送查詢之後），所以防火牆先得知道封包「從哪個區域進、要往哪個區域出」。 選定 NAT 規則之後，安全政策才開始比對；真正改寫封包位址，是封包要離開防火牆的時候。

簡化流程，只畫出與 NAT 有關的步驟；完整流程見第 1 章。

重點

NAT 規則只負責「換位址」，不負責放行。有 NAT 規則但沒有對應的安全規則，流量一樣會被擋下；反過來，有安全規則但沒有 NAT 規則，封包會帶著私有位址出去，到了網際網路也回不來。上網要通，兩種規則缺一不可。

Types 二、Source NAT 的三種轉換類型

Source NAT 把原始來源位址換成另一個來源位址。依「一個位址能服務幾個人、有沒有動連接埠」，分成三種：

☎️ 生活化比喻：公司總機對外統一撥號

  • 私有位址：員工的分機號碼，只在公司內部有意義，外面的人撥不到。
  • Static IP：老闆的專線，一個分機固定對應一個外線號碼，外面的人也能反過來撥進來。
  • Dynamic IP：外線號碼池，誰要打電話就分配下一條空線，打完才歸還；一人占一條，線用完了，後面的人就打不出去。
  • DIPP：全公司共用一個總機代表號，每通電話再附上不同的通話編號（連接埠），對方回撥時總機靠編號找到是哪位同事。

三種類型比較

項目 Static IP Dynamic IP Dynamic IP and Port（DIPP）
對應方式一對一，固定對應一對一，取位址池中下一個可用的位址多對一，多台主機共用位址
來源連接埠不變不變會改變，用連接埠區分不同主機
所需公開位址每台主機一個位址池大小要等於需要轉換的主機數少量即可，甚至只用介面本身的位址
位址耗盡時不適用（固定對應）預設丟棄需要轉換的新連線，可設 Advanced（Dynamic IP/Port Fallback）備援受連接埠數量與超額訂閱設定限制（下一節）
雙向（Bi-directional）可選用不支援不支援
典型用途需要固定公開位址的伺服器，或需要被外部主動連入的主機公開位址夠多、又想保留原始連接埠的環境一般使用者上網常用

要選哪一種？簡化的選型思路

這是教學用的簡化判斷；實際還要看公司政策與位址規劃。

Dynamic IP 位址池用完：Advanced 備援

  • Dynamic IP 不改連接埠，一個位址同一時間只能給一台主機。位址池全部被占用時，預設會丟棄需要轉換的新連線。
  • 預防方式一：位址池大小設成和需要轉換的主機數相同。
  • 預防方式二：在 Translated Packet 頁籤選了 Dynamic IP 之後，按 Advanced（Dynamic IP/Port Fallback），另外指定一組備援位址池。主要位址池用完時，防火牆就改用 DIPP 繼續轉換。
  • 備援位址池可以用 Translated Address 或 Interface Address 指定，而且位址不能和主要位址池重疊。

DIPP 的位址來源：介面位址或轉換後位址

  • Translated Address：自己指定一個位址、一段範圍或一個子網路當作位址池。
  • Interface Address：直接用防火牆對外介面的位址。介面如果是 DHCP 取得、之後換了位址，NAT 規則會自動跟著更新，不必改設定。教材也提到可以把 DIPP 指派成介面位址或轉換後位址，兩種都可以。

Static IP 的雙向選項（Bi-directional）

Bi-directional 只有 Static IP 才能勾選。勾選後，同一條規則除了「內部主機出去時換成公開位址」，還會建立反方向的轉換： 外部連到那個公開位址時，換回內部位址。這樣內部伺服器就能同時收送流量，不必再另寫一條 Destination NAT 規則。

版本差異：教材與現行文件

  • 備援（Fallback）：教材備註已經提到 Advanced（Dynamic IP/Port Fallback，備註拼成 Failback）；現行文件另說明備援位址池可用 Translated Address 或 Interface Address 指定，且不得與主要位址池重疊（見上方小節）。
  • Persistent DIPP：教材沒有提到。PAN-OS 11.1.0 以前是全域設定，一次套用到所有 NAT 規則；11.1.1 起改成每條規則各自選用「Persistent Dynamic IP And Port」類型，用於 STUN 這類需要「同一組內部位址與連接埠，每次都對到同一組公開位址與連接埠」的應用。細節以你所用版本的文件為準。
  • 雙向規則的安全政策：現行文件提醒，啟用雙向轉換時，兩個方向都要有安全政策來管控；教材沒有提到這一點。
  • Dynamic IP 的用途：教材備註說 Dynamic IP 最常用在「有兩個以上公開位址，但不夠每台內部主機各配一個，想只在需要時才分配給外連主機」的情況；現行文件則建議位址池大小等於需要轉換的主機數。上方的選型流程採用現行說法。

補充：雙向規則在兩份教材的差異

新版教材（2017–2020）有雙向 Source NAT 的投影片；PAN-OS 8.0 時代的舊版教材沒有，只在類型清單提到 Static IP「支援隱含的雙向規則」。這是兩份教材之間的差異，不是版本變更。

DIPP 三、DIPP 超額訂閱（Oversubscription）

DIPP 靠「來源連接埠」區分不同主機，所以一個公開位址能被很多人共用。但連接埠總數有限，如果每個「公開位址加連接埠」組合只能給一條連線用，連線一多就不夠。 超額訂閱的做法是：同一組轉換後位址與連接埠，可以同時給多條工作階段重複使用，前提是這些連線的目的地不同。

怎麼算同時能撐多少連線

  • 教材用一個簡化的算式：並行工作階段數 ＝ 超額訂閱倍率 × 位址池大小。這裡的「位址池大小」指的是位址與連接埠組合的總數，不是位址的個數。
  • 換成比較精確的計算方式：可同時使用的工作階段數 ≈ 轉換後位址數 × 每個位址約 64,000 個連接埠組合 × 超額訂閱倍率（實際倍率與上限依機型而定）。
  • 每個轉換後位址約可支援 64,000 個並行工作階段（教材的計算：65,536 減去 1,024 個知名埠，約 64,512 個）；開啟超額訂閱的機型，可再乘上倍率。
  • 設定位置：Device > Setup > Session > Session Settings 的 NAT Oversubscription Rate。下拉選單有 Platform Default、1x、2x、4x、8x。
  • 選 1x 等於不做超額訂閱。選 Platform Default 則採用該機型原本的預設值。
  • 倍率可以是 8、4、2；實際可用的倍率依機型而不同，預設值也依機型而定。本章不列出各機型的數字，請查原廠的產品選擇工具或規格資料。
  • 舉例：預設 64K 並行工作階段，乘以倍率 8，得到 512K。這只是舉例，不是每台設備都一樣。
  • 這是全防火牆共用的設定，不是每條規則各自設定。
  • 倍率調低，能支援的 DIP 與 DIPP 規則容量會增加，但可同時轉換的來源裝置數會減少；公開位址夠多的話，可以考慮調低。

版本差異：現行文件新增的限制

  • 每條 NAT 規則最多可放 256 個轉換後位址。若超額訂閱使規則超過上限，防火牆會自動調低倍率，讓 Commit 能成功。教材沒有提到這個上限。
  • PA-7500 系列從 PAN-OS 12.1.8 起，單一 DIPP 規則的轉換後位址上限提高，詳見原廠文件。

Policy 四、NAT 政策與安全政策如何配合

第 1 章已經說過：安全政策比對時，位址用轉換前（pre-NAT）的，區域用轉換後（post-NAT）的。這裡用教材的實際拓撲做一次完整推演。

位址為教材使用的私有位址與文件保留位址。回程封包的目的位址是 198.51.100.22，防火牆依既有工作階段換回 192.168.15.47，不需要另寫規則。

實例：同一條上網需求，兩張規則表

需求：Users_Net（192.168.15.0/24）的使用者可以用 SSL 與網頁瀏覽連到 Internet 區域，並使用防火牆對外介面的位址上網。

NAT 規則（Policies > NAT）

Name Original Packet（轉換前） Translated Packet（轉換後）
Source Zone Destination Zone Source Address Destination Address Service Source Translation Destination Translation
Source_Users_Net_to_Internet Users_Net Internet 192.168.15.0/24 any any dynamic-ip-and-port，Interface Address：ethernet1/4（198.51.100.22） none

對應的安全規則（Policies > Security）

Name Type Source Zone Source Address Destination Zone Destination Address Application Service Action
Users_to_Internet universal Users_Net 192.168.15.0/24 Internet any ssl、web-browsing application-default Allow

這條安全規則怎麼填

  • Source Address：填轉換前的 192.168.15.0/24（pre-NAT），不是 198.51.100.22。
  • Source / Destination Zone：Users_Net 到 Internet。
  • Source NAT 只改來源位址，路由與區域判斷不受影響，所以本例轉換前後的區域相同。

Pre-NAT 與 Post-NAT 一覽

  • 安全規則的位址欄：轉換前（來源 192.168.15.47，目的 203.0.113.38）。
  • 安全規則的區域欄：轉換後的區域。
  • 封包實際送出：來源變成 198.51.100.22。
  • 位址與區域真正會「對不上」的情境是 Destination NAT，第 11 章再練。

常見踩坑：安全規則誤填轉換後的位址

  • 把安全規則的 Source Address 寫成轉換後的公開位址（198.51.100.22），規則比對不到，內部使用者的流量會落到預設規則被擋下。看到這種症狀，先檢查規則裡填的是不是轉換前位址。
  • 只建 NAT 規則、忘了建安全規則，或反過來。NAT 不放行，安全規則不換位址，兩者獨立運作。
  • NAT 規則同樣由上而下比對，第一條符合的規則生效，之後的 NAT 規則不再套用。建議由最精確排到最廣泛；把範圍大的規則放在上方，下面精確的規則就永遠用不到。

Config 五、設定 Source NAT 規則

路徑：Policies > NAT > Add。規則視窗有三個頁籤：General（名稱、說明、標籤）、Original Packet（比對條件）、Translated Packet（轉換方式）。 教材把 Original Packet 標為「Match Criteria」（比對條件），把 Translated Packet 標為「Translation」（轉換），意思是：先說「什麼封包要換」，再說「換成什麼」。

Original Packet 比對條件

  • Source Zone / Destination Zone：轉換前封包的來源與目的區域，預設為 Any。
  • Destination Interface：選用，可在雙 ISP 環境用來讓不同出口使用不同的轉換位址。
  • Service：選用，限定哪些服務才換位址。
  • Source Address / Destination Address：轉換前的位址條件。

Translated Packet 轉換方式

  • Source Address Translation：Translation Type 選 None、Dynamic IP And Port、Dynamic IP、Static IP；較新的版本另有 Persistent Dynamic IP And Port（見上方版本差異）。
  • 選 Dynamic IP And Port 時，Address Type 可選 Translated Address 或 Interface Address（欄位名稱以實機畫面為準）。
  • 選 Static IP 時，會出現 Bi-directional 核取方塊。
  • Destination Address Translation：Source NAT 規則通常保持 None（第 11 章才會用到）。

三個範例（皆為 Users_Net 到 Internet）

三個範例是各自獨立的教學情境，公開位址可能重複出現，請不要放進同一台設備同時使用。

範例 Source Address（轉換前） Source Translation（轉換後） 說明
Static 1:1 192.168.15.47 static-ip，Translated Address 198.51.100.22，bi-directional：yes 一台主機固定對一個公開位址，雙向皆可轉換
Dynamic IP 192.168.15.2 至 192.168.15.50 dynamic-ip，198.51.100.102 至 198.51.100.150 49 台主機對 49 個位址，位址池大小與主機數相同

建立步驟（以 DIPP 加介面位址為例）

  1. 先建好位址物件（例如 192.168.15.0/24），路徑：Objects > Addresses。
  2. Policies > NAT > Add，在 General 頁籤輸入名稱。
  3. Original Packet 頁籤：Source Zone 選 Users_Net，Destination Zone 選 Internet，Source Address 加入剛建的物件，Destination Address 保持 Any。
  4. Translated Packet 頁籤：Translation Type 選 Dynamic IP And Port，Address Type 選 Interface Address，再選對外介面（ethernet1/4）。
  5. 到 Policies > Security 確認有對應的允許規則（位址填轉換前），最後 Commit。

常見踩坑：Dynamic IP 位址池用完

Dynamic IP 不改連接埠，一個位址同一時間只能給一台主機。位址池全部被占用時，預設會丟棄需要轉換的新連線，使用者看到的是「部分人能上網、部分人不行」。 解法有兩種：把位址池加大到與主機數相同，或在 Advanced（Dynamic IP/Port Fallback）設定備援的 DIPP 位址池。一般上網需求，直接用 DIPP 通常更省事。

補充：教材範例中的介面名稱

教材簡報的範例，位址 198.51.100.22 所屬的介面，在拓撲圖與規則截圖上分別標成 ethernet1/4 與 ethernet1/1，兩處不一致。這是教材內部的前後不一，不是版本差異。本章統一寫成 ethernet1/4（外部介面）。實際設定時請以自己設備上的對外介面名稱為準。
