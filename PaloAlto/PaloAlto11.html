政策篇 - 單元 11：Destination NAT 與 U-Turn NAT

講師導言

第 10 章我們處理的是「內部主機連出去」，改的是來源位址。這一章倒過來：外面的人要連進來找你的內部伺服器， 防火牆要改的是目的位址，這就是 Destination NAT。 它的設定本身不難，真正會卡人的是安全政策該怎麼寫：位址要填「轉換前」的，區域要填「轉換後」的。 接著我們會學一個公開位址後面放好幾台伺服器的連接埠轉送，最後看一個經典情境：公司內部的使用者，用「公開位址」去連自己 DMZ 裡的伺服器，也就是 U-Turn NAT。

Goals 本章學習目標

  • 說明 Destination NAT 的用途，並分辨 Static IP、連接埠轉換與 Dynamic IP 三種屬性
  • 寫出 Destination NAT 對應的安全規則：位址用轉換前（pre-NAT），目的區域用轉換後（post-NAT）
  • 在 Policies > NAT 建立一條 Destination NAT 規則，並說明 Original Packet 與 Translated Packet 兩個頁籤各放什麼
  • 用服務物件與 Translated Port 完成連接埠轉送，並寫出配套的兩條安全規則
  • 說明三區域 U-Turn NAT 的情境、兩條規則怎麼寫，以及為什麼規則順序會決定成敗

Concept 一、Destination NAT 的用途與屬性

Destination NAT 會把封包的原始目的 IP 位址，轉換成另一個目的位址。 最典型的用途：伺服器放在 DMZ，使用私有位址，但對外只公布一個公開位址；外部使用者連公開位址，防火牆在中間把目的位址換成內部伺服器。

☎️ 生活化比喻：大樓總機轉分機

  • 公開位址：公司對外公布的總機號碼。訪客只知道這個號碼，不知道誰坐哪裡。
  • Destination NAT 規則：櫃檯桌上的轉接表。訪客說「找業務部」，櫃檯就轉到業務部的分機。
  • 內部伺服器位址：分機號碼。只在大樓內部用，外面的人從頭到尾不需要知道。
  • 安全政策：門禁。櫃檯願意轉接，不代表訪客能進大樓，仍要有門禁規則放行。

Destination NAT 的三種屬性

設定位置：Policies > NAT > Add，在 Translated Packet 頁籤選擇轉換型態。

Static IP

  • 一對一的固定轉換
  • 只改目的位址，目的連接埠不變
  • 教材也提到：Static Source NAT 開啟 Bi-directional 選項，同樣能讓外部連進來（第 10 章）

連接埠轉換

  • 在 Translated Packet 填 Translated Port
  • 用於伺服器聽的不是標準連接埠
  • 搭配 NAT 規則的 Service 欄位，可讓一個公開位址依連接埠分流到多台伺服器（第四節）

Dynamic IP

  • 轉換後的目標位址會變動（例如雲端環境，或伺服器位址由 DHCP 發放、且 DNS 會跟著更新）
  • 轉換後的位址可用 FQDN、位址物件或位址群組（要以 FQDN 為基礎，才跟得上位址變動）
  • 型態選 Dynamic IP

版本差異：Dynamic IP 與「連接埠轉送」的說法

  • 名稱不同：教材只寫 Dynamic IP。現行原廠文件的完整名稱是 Dynamic IP (with session distribution)，轉換後的位址可以是 FQDN、位址物件或位址群組；當一個 FQDN 解析出多個位址，防火牆會把新的工作階段分散到這些位址。
  • 分配方式：現行版提供 Round Robin（預設）、Source IP Hash、IP Modulo、IP Hash、Least Sessions 五種。
  • 只支援 IPv4：現行版的 Dynamic IP (with session distribution) 只支援 IPv4 位址；FQDN 若只解析出 IPv6 位址，該規則視同尚未解析。若 DNS 回傳超過 32 個 IPv4 位址，只用前 32 個。教材備註對 IPv6 的說法與此不同，以實機為準。
  • 何時用：原廠的最佳作法是靜態位址用 Static IP，只有 FQDN 這類動態位址才用 Dynamic IP。另外，若轉換前的位址（Original Packet 的 Destination Address）是 FQDN 物件，轉換型態也必須是 Dynamic IP (with session distribution)，不能選 Static IP。
  • 用詞：教材把「依埠分流」稱為 port forwarding；換埠的設定頁，舊版教材叫 Port Forwarding Configuration，新版教材已改叫 Port Translation Configuration。原廠現行版把兩者分開：Port Forwarding 是公開位址與埠轉成私有位址、埠號不變；Port Translation 才是換成不同的埠，作法是在 Translated Packet 填 Translated Port。本章依原廠分法。
  • 原廠另有 DNS Rewrite 功能（Static IP 的 IPv4 情境），用來處理內外 DNS 回應不同位址的狀況；本章不展開。

Policy 二、Destination NAT 對應的安全政策怎麼寫

第 1 章與第 10 章都提過：防火牆先查路由、比對 NAT 規則，再比對安全政策，真正的轉換要等封包離開防火牆時才發生。 所以安全政策比對時，看到的是「轉換前」的位址；但它判斷區域時，用的卻是「轉換後」位址所在的區域。 換句話說，安全政策依據原始（pre-NAT）的來源與目的位址，但使用 post-NAT 區域。

一句話記法

位址看轉換前，區域看轉換後。 NAT 規則的目的區域，是用「轉換前目的位址」查路由得到的區域；安全規則的目的區域，是用「轉換後目的位址」查路由得到的區域（也就是伺服器實際所在的區域）。

最常見的踩坑：安全規則的目的位址寫成「轉換後」的內部位址

直覺上會想：「伺服器在 192.168.16.2，那安全規則就放行 192.168.16.2。」這樣寫，規則不會命中。 因為安全政策比對時，封包的目的位址還是轉換前的公開位址 198.51.100.22。 症狀通常是：NAT 規則本身沒錯，但外部連線被預設規則擋下。 反過來，目的區域卻不能寫成公開位址所在的 Untrust-L3，而要寫伺服器所在的 DMZ。 檢查方式：被預設規則擋下的流量，要先對 interzone-default 做 Override 並開啟日誌，才會出現在 Monitor > Logs > Traffic（怎麼開啟見第 9 章）；也可以在連線後用 CLI show session all filter destination 198.51.100.22 確認轉換是否發生，或用 Test Policy Match（第 9 章）確認封包會命中哪一條安全規則。

Config 三、設定一條 Destination NAT 規則

規則都在 Policies > NAT > Add。視窗上有三個頁籤：General、Original Packet、Translated Packet。 教材用兩個動作概括：Match Criteria（在 Original Packet 頁籤寫「什麼流量要轉」）與 Translation（在 Translated Packet 頁籤寫「轉成什麼」）。

1 General

  • Name：有意義的名稱，例如 DST-NAT
  • NAT Type 選 ipv4（新增規則時通常已是 ipv4，以畫面為準）

2 Original Packet

  • Source Zone：流量來源的區域
  • Destination Zone：公開位址所在的區域
  • Destination Address：公開位址（建議先建立位址物件）
  • Service：要轉換的服務；any 代表全部，連接埠轉送時才指定

3 Translated Packet

  • Destination Address Translation 的 Translation Type：Static IP 或 Dynamic IP (with session distribution)
  • Translated Address：內部伺服器位址
  • Translated Port：要換埠才填，範圍 1 到 65535；留空代表不改埠

建立步驟

  1. Objects > Addresses > Add：建立「公開位址」物件，例如 Webserver-public 為 198.51.100.22；伺服器位址也可建成物件。
  2. Policies > NAT > Add：General 頁籤填名稱。
  3. Original Packet 頁籤：Source Zone 選來源區域，Destination Zone 選公開位址所在區域，Destination Address 選公開位址物件。
  4. Translated Packet 頁籤：Translation Type 選 Static IP，Translated Address 填內部伺服器位址。
  5. Policies > Security > Add：依上一節寫配套的安全規則（pre-NAT 位址、post-NAT 區域）。
  6. Commit（第 4 章），再用外部主機實際連線測試，並以 show session all 確認位址轉換。

用 FQDN 或位址群組做 Dynamic IP

當內部伺服器的位址會變動（例如雲端或 DHCP 環境），改在 Translated Packet 頁籤把轉換型態選成 Dynamic IP (with session distribution)， 並替伺服器建立 Type 為 FQDN 的位址物件、確保 DNS 會跟著更新，再把它（或包含它的位址群組）選為 Translated Address。原廠建議 Dynamic IP 只用在以 FQDN 為基礎的動態位址；以 IP Netmask 建立的位址物件內容固定，不會跟著位址變動。 分配方式預設為 Round Robin，也可改選其他方式。

版本差異：視窗長相與欄位名稱

  • 教材的截圖與說明是勾選 Destination Address Translation 核取方塊後，直接填 Translated Address 與 Translated Port；其中 Dynamic IP 的投影片寫「把轉換型態設為 Dynamic IP」。
  • 較新版把它整理成 Translation Type 選單：None（預設）、Static IP、Dynamic IP (with session distribution)。Static IP 可輸入單一位址或位址範圍。
  • 各版本的實際視窗排版可能略有不同，請以你手上的版本為準；欄位的意義不變。PAN-OS 12.x 畫面本章未逐一比對。

NAT 規則由上往下比對

防火牆依順序由上往下評估 NAT 規則，封包一旦符合其中一條，就不會再套用後面的 NAT 規則。 所以規則順序會決定誰先生效，這一點在第五節的 U-Turn NAT 會變成關鍵。

Port 四、連接埠轉送與連接埠轉換

公司通常只有一個公開位址，卻有好幾台伺服器要對外提供服務：郵件轉送、網站、收信。 做法是在 NAT 規則的 Service 欄位指定「哪些連接埠」，讓不同連接埠對應到不同的內部伺服器。 如果內部網站不聽標準的網頁埠，還可以同時用 Translated Port 換埠。 這個情境的兩個重點：用服務物件包住連接埠，以及配套寫兩條安全規則。

教材範例將伺服器所在區域標為 Trust-L3，本章為了與前後章一致，統一稱為 DMZ；區域名稱不影響原理。

NAT 規則：三條規則共用一個公開位址

三條規則的 Source Zone 與 Destination Zone 都是 Untrust-L3，Destination Address 都是公開位址物件（203.0.113.22），差別在 Service 與轉換結果：

什麼時候要填 Translated Port？

只有伺服器「聽的埠」跟使用者連的埠不同才需要。範例中使用者連標準網頁埠，但內部網站實際聽 TCP 8080，所以 Translated Port 填 8080； SMTP 與收信伺服器聽的就是標準埠，Translated Port 留空即可。留空等於不改目的埠。

踩坑：換埠之後，安全規則的 Service 欄位該填哪個埠，務必實測

安全規則的 Service 欄位比對的是轉換前還是轉換後的埠，原廠範例沒有明說；依「封包離開防火牆時才轉換位址與埠」推論，應為轉換前。 教材的規則用涵蓋 TCP 80 與 8080 的 service-http，兩種情況都能放行。以實機為準：若想改回 application-default，請先用 Traffic 日誌實測，確認命中再決定。

版本差異：一台防火牆、多台伺服器的說法

教材簡報把「一個公開位址依原始目的埠對應多台內部伺服器」寫成 Destination NAT 的選用功能（Optional port forwarding）。 原廠現行文件則把「埠號不變」稱為 Port Forwarding，把「換成另一個埠」稱為 Port Translation（填 Translated Port）；而 NAT 規則的 Service 欄位，原廠文件對這個欄位的說明是「指定要轉換來源或目的位址的服務」。教材範例用 Service 欄位搭配多條規則達成分流，兩種說法描述的是同一組設定，只是分類方式不同。

U-Turn 五、三區域 U-Turn NAT：內部使用者連自己的公開伺服器

情境：公司網站放在 DMZ，對外的 DNS 把 www.example.com 解析成公開位址。 外部使用者連公開位址沒問題（前面四節已設定）。但內部使用者也會問到同一個公開位址， 封包從 Trust 區域進入防火牆，目的位址是公開位址。為了讓它連到 DMZ 伺服器，就要再加一條 Destination NAT 規則， 讓封包「進來又繞回內側」，所以稱為 U-Turn NAT（教材：When internal traffic needs to access DMZ resources using public IP addresses）。

位址取自教材的三區域示意圖；使用者位址 192.168.1.50 是本章為了說明而假設的主機，教材圖中只標示 Trust 介面 192.168.1.1。外部 DNS 的位址，教材用的是公用 DNS，這裡改用文件保留位址 192.0.2.53。

規則 2 就是第 10 章的「一般上網」Source NAT（DIPP）。Destination Zone 填 Untrust-L3，是因為公開位址是往外部介面路由的。規則 1 的 Translated Port 填 8080，與第四節的網站設定一致（網站聽 TCP 8080）；若你的網站直接聽 TCP 80，這個欄位留空即可。

為什麼順序不能反？

內部使用者連公開位址時，這個封包同時符合規則 1 與規則 2（Trust 到 Untrust，目的位址 any 也包含公開位址）。 NAT 由上往下比對，第一條命中後就不再看後面的規則，所以誰在前面誰就決定結果：

規則順序內部使用者連公開位址的結果
UTurn-NAT 在前（正確）命中規則 1，目的位址被改成伺服器位址，並停止比對。
Outbound NAT 在前（錯誤）命中規則 2，只套用來源轉換；目的位址仍是公開位址，沒有被送回 DMZ，連線不會成功。

安全規則：只需要一條

名稱 Source Zone Destination Zone Destination Address Service Action
Internal access to web serverTrust-L3、Untrust-L3DMZ（post-NAT）203.0.113.22（pre-NAT）service-httpAllow

這條規則同時放行「內部使用者（Trust-L3）」與「外部使用者（Untrust-L3）」連到公開位址的流量，兩者轉換後都落在 DMZ，所以目的區域是 DMZ，目的位址是 pre-NAT 的公開位址。 也就是說，原則與第二節完全相同，只是來源區域多了一個 Trust-L3。

踩坑：U-Turn 規則放在「一般上網」規則之後

這是 U-Turn NAT 最經典的錯誤。一般上網的 NAT 規則通常寫得很寬（Trust 到 Untrust、any 到 any），而內部使用者連公開位址，剛好也符合這個條件。 若寬鬆規則排在前面，U-Turn 規則永遠輪不到，症狀是外部使用者連得上，內部使用者卻連不上。 要養成習慣：越具體的 NAT 規則放越上面，越寬的放越下面。新增 U-Turn 規則後，別忘了檢查它是不是排在寬鬆規則之前。

版本差異：U-Turn 的轉換後位址可用 Dynamic IP

  • 教材的三區域範例（Trust、Untrust、DMZ 各自獨立網段）只用一條 Destination NAT 規則，轉換後的伺服器位址是靜態位址。
  • 現行版本的轉換後位址除了 Static IP，也可選 Dynamic IP (with session distribution)，轉換後位址為位址物件或位址群組，可以是 IP 網段、IP 範圍或 FQDN。

規則的寫法（Source Zone 選內部區域、Destination Zone 選外部區域、Destination Address 選公開位址物件）與教材一致。本章只教只轉換目的位址的三區域版；其他變化版本（例如同時轉換來源位址）未逐一查證，請依自己的網路架構評估。
