網路篇 - 單元 6：Layer 3 介面與虛擬路由器

講師導言

上一章我們把流量切成一個個區域（Zone），也看過 Tap 與 Virtual Wire 這類「不碰路由」的接法。 這一章要進入實際最常用的部署：Layer 3 介面。防火牆自己有 IP、自己查路由，像一台會檢查封包的路由器。 你會學到介面怎麼設、為什麼一定要搭配虛擬路由器、怎麼用子介面切 VLAN、怎麼設備援預設路由， 以及出問題時去哪裡看路由表。

Goals 本章學習目標

  • 依序完成一個 Layer 3 介面的設定：介面類型、虛擬路由器、區域、IP 位址
  • 說明 Interface Management Profile 的用途，並避免在不受信任的介面開放管理服務
  • 說明 Layer 3 子介面如何依 802.1Q VLAN tag 分流，並分辨它與 Virtual Wire 子介面的差別
  • 建立虛擬路由器與靜態預設路由，並設定多條預設路由與 Path Monitoring 達成備援
  • 在 Web 介面查看 RIB、FIB 與路徑監控狀態，進行路由疑難排解
  • 說明 Loopback 介面的用途與設定重點

Interface 一、Layer 3 介面設定三步驟

Layer 3 介面讓防火牆能在多個網段之間做路由，並同時檢查與控制流量。 它比 Virtual Wire 多了 Layer 3 服務（虛擬路由器、VPN、路由協定），代價是必須有虛擬路由器， 而且相鄰設備可能需要配合新的 IP 位址調整設定（例如把預設閘道改指向防火牆）。

圖中位址為示意用的私有位址與文件保留位址，實際請換成自己環境的網段。

三個步驟，都在同一個視窗

路徑：Network > Interfaces > Ethernet > 選取介面

1 Config 頁籤

  • Interface Type 選 Layer3
  • 選擇 Virtual Router
  • 選擇 Layer 3 類型的 Security Zone

2 IPv4 / IPv6 頁籤

  • Static：以 CIDR 格式輸入位址，可輸入多個
  • DHCP Client：由上游 DHCP 伺服器指派位址
  • PPPoE：用於 DSL 線路的撥接式連線
  • IPv6：先在介面啟用，再設靜態位址或 DHCPv6 Client

3 Advanced 頁籤（選用）

  • 指定 Interface Management Profile（下一節）
  • 預載 ARP（IPv4）或 ND（IPv6）快取
  • LLDP、NDP Proxy、DDNS

提醒：HA Active/Active 的限制

Active/Active 不支援 DHCP Client 與 PPPoE；原廠文件對 PPPoE 另有不同說法，以實機為準。（HA 於第 17 章說明。）

🚦 生活化比喻：路口、路標與交通號誌

  • Layer 3 介面：路口的各個入口，每個入口都有自己的門牌（IP 位址）。
  • Zone：這個入口屬於哪一個管制區（內部、外部、DMZ）。
  • Virtual Router：路口的路標，告訴車子（封包）要往哪個出口走。
  • Security Policy：交通號誌，決定哪些車可以過。有路標但號誌是紅燈，車一樣過不去。

版本差異：IPv6 全域開關

  • 教材（PAN-OS 8.0 與較新的訓練簡報）寫「要支援 IPv6 位址，必須在防火牆上啟用 IPv6」，位置是 Device > Setup > Session > Session Settings。
  • 這個設定現行版本仍然存在，名稱為 IPv6 Firewalling。即使介面已啟用 IPv6，沒有啟用 IPv6 Firewalling 時，防火牆會忽略所有 IPv6 相關設定。
  • 此功能預設就是啟用的（PAN-OS 7.1 以上），CLI 為 set deviceconfig setting session ipv6-firewalling yes|no。所以教材的「必須啟用」應理解成「確認已啟用」：實務上通常不必自己打開，但設定 IPv6 前仍要確認它的狀態。

最常見的踩坑：介面設好 IP 卻不通

未指派 Virtual Router 的介面，不會參與路由；未指派 Zone 的介面，不處理流量（上一章已說明）。 另外，即使路由正確，沒有安全政策允許的跨區流量仍會被預設規則擋下。症狀看起來都是「ping 不通」，請依序檢查：介面 → Zone → Virtual Router → 路由 → 安全政策；要連上網際網路，還需要 Source NAT（第 10 章）。

Management 二、Interface Management Profile

第 2 章的 MGT 介面是專用管理口。但有時你希望從一般流量介面也能 ping 防火牆、用 SSH 登入，或讓監控系統用 SNMP 查詢。 這時要建立 Interface Management Profile，定義「哪些管理服務可以從這個介面連進來」。

  • 建立路徑：Network > Network Profiles > Interface Mgmt > Add
  • 可套用到 Layer 3 乙太網路介面（含子介面），以及 Aggregate、VLAN、Loopback、Tunnel 等邏輯介面（在介面的 Advanced 頁籤選取）。
  • 沒有套用任何 Profile 的介面，預設拒絕所有位址、通訊協定與服務。MGT 介面不需要 Profile。
項目說明
Ping讓對方 ping 這個介面，常用來測試連線，也用來確認介面能連到更新伺服器。
SSH、HTTPSCLI 與 Web 介面的加密管理通道。
Telnet、HTTP明文傳輸。原廠明確建議不要啟用。
SNMP讓監控系統輪詢。可只開 SNMP、關閉 HTTP 與 HTTPS，不給 Web 管理權限。
HTTP OCSP讓防火牆擔任 OCSP 回應者（OCSP responder），回覆憑證狀態查詢（解密與 VPN 章節會再遇到憑證議題）。
Response PagesAuthentication Portal（舊稱 Captive Portal）與 URL Admin Override 所需的回應頁面服務。
User-ID 相關服務User-ID：讓其他防火牆經由這個介面取得（重新發布）使用者對應；User-ID Syslog Listener（SSL 或 UDP）：接收 syslog 訊息，用來建立使用者對應（第 14 章）。
Permitted IP Addresses選用。列出允許連入的來源位址（IPv4 或 IPv6）；不填就代表沒有來源限制。

重點：它管的是「連到防火牆本身」的流量

Interface Management Profile 只決定誰能連到防火牆自己的這個介面位址，不影響「穿越」防火牆的一般流量，穿越流量由安全政策管。 教材的實驗（Lab 5）剛好示範這個順序：先在沒有 Profile 時測試存取，再建立 Profile、套用到介面，最後再測一次，對照前後差異。

踩坑：把管理服務開在對外介面

原廠明確提醒：不要在可從網際網路或其他不受信任區域到達的介面啟用 HTTP、HTTPS、SSH 或 Telnet。 把 HTTPS 與 SSH 開在 untrust 介面，等於把管理介面直接放到網路上讓人掃描與嘗試登入。 真有需要時，至少用 Permitted IP Addresses 限縮到固定來源，並確認已換掉預設 admin 密碼、設好密碼規則（第 2 章）；管理員角色與驗證設定檔本課程不另外說明。只需要 ping 測試時，只勾 Ping 就好。

Subinterface 三、Layer 3 子介面

Layer 3 Subinterface 讓你把一個實體介面切成多個邏輯介面，常見於上游交換器以 Trunk（802.1Q）送來多個 VLAN 的情境。 每個子介面各有自己的 IP 位址、Zone，並加入虛擬路由器；因此不同 VLAN 之間的流量要穿過防火牆，由安全政策決定放不放行（跨區預設會被擋）。 這種做法也很適合多租戶網路。

子介面 802.1Q VLAN tag IP 位址 Zone
ethernet1/2.11192.168.1.1/24Eng
ethernet1/2.22192.168.2.1/24HR
ethernet1/3.33192.168.4.1/24DC

改寫自教材的子介面拓撲示意，位址與 Zone 名稱僅供練習。

子介面怎麼認流量

路徑：Network > Interfaces > Ethernet，選取實體介面後 Add Subinterface，填入 Subinterface ID 與 802.1Q VLAN tag，其餘選項與一般 Layer 3 介面相同。

  • 依 802.1Q VLAN tag（1 到 4094）分類：進來的封包帶哪個 tag，就由對應的子介面處理，每個子介面各屬於自己的 Zone。
  • 若上游送來的是沒有 tag 的流量，要在上層實體介面的 Advanced 頁籤勾選 Untagged Subinterface，才能建立無 tag 的子介面。教材提到它常用於多租戶環境，且此時流量須做 Source NAT。
  • 常見用途：讓安全規則更細緻、把網路流量在邏輯上切開。

Subinterface ID 只是名稱的一部分（例如 .1、.2），不必等於 VLAN tag，但為了好維護，實務上常刻意讓兩者一致。

版本差異：IP classifier 只屬於 Virtual Wire 子介面

教材把 IP classifier（依來源 IP 分類）寫在 Layer 3 子介面；現行文件只在 Virtual Wire 子介面提供 IP classifier（見第 5 章）。Layer 3 子介面的設定頁沒有 IP Classifier 欄位，只依 VLAN tag 分流。看到教材的 Layer 3 子介面示意圖寫「VLAN tag 加來源 IP」時，請以實機畫面為準。

踩坑：上游交換器沒有放行對應的 VLAN

防火牆子介面只會處理帶有對應 tag 的封包。上游交換器連到防火牆的那一埠必須是 Trunk，且允許這些 VLAN 通過； 否則子介面 IP 設得再對也收不到流量。另外，若要由防火牆自己做 Layer 2 交換（VLAN 物件），那是下一章（第 7 章）的主題，兩種做法不要混在同一個介面上。

Routing 四、虛擬路由器與靜態路由

Virtual Router 是防火牆內部的路由實體，保存路由表並決定封包往哪個介面送。 每個介面只能屬於一個虛擬路由器，但一個虛擬路由器可以同時跑多種協定與靜態路由；防火牆出廠就內建一個名為 default 的虛擬路由器。 多個虛擬路由器各有自己的路由表，彼此之間要通訊，可以用靜態路由的 Next VR 選項。

類別支援項目（傳統路由引擎）
靜態路由一條或多條
動態路由RIPv2、OSPFv2、OSPFv3、BGPv4
多播路由PIM-SM、PIM-SSM（舊版簡報另列 IGMP）

建立虛擬路由器與靜態預設路由

  1. Network > Virtual Routers > Add（或編輯 default），在 General 設定頁籤把要使用的介面加入。
  2. 進入 Static Routes > Add，新增靜態路由。預設路由的目的網路就是「所有網路」（IPv4 為 0.0.0.0/0）。
  3. 設定 Next Hop：可選 IP Address、Next VR、FQDN、Discard（丟棄）或 None（無下一跳）；並指定出口 Interface。
  4. 設定 Admin Distance（10 到 240，預設 10）與 Metric（1 到 65535）。

管理距離（Admin Distance）預設值

不同來源的路由競爭同一個目的網路時，先比 Admin Distance，小者優先。各來源的預設值：靜態 10、EBGP 20、OSPF 內部 30、OSPF 外部 110、RIP 120、IBGP 200。 只有在 Admin Distance 相同時，才比較 Metric。所以要讓靜態路由當動態路由的備援，就把靜態路由的 Admin Distance 調得比動態路由大。

版本差異：Advanced Routing Engine 與 Logical Router

  • 教材與本章操作都是傳統路由引擎（Legacy Routing Engine）：Network > Virtual Routers。
  • 較新的 PAN-OS 提供另一種 Advanced Routing Engine（ARE）。啟用後改用 Logical Router 取代 Virtual Router，路徑為 Network > Routing > Logical Routers。
  • 啟用位置為 Device > Setup > Management > General Settings。同一時間只有一種引擎生效，切換需要 Commit 並重新啟動防火牆，且 ARE 不會自動建立預設的 Logical Router，需自行建立至少一個。啟用時可選擇由遷移腳本把既有的 Virtual Router 轉成 Logical Router；切換前請先備份組態。
  • ARE 支援：靜態路由、BGP、OSPFv2、OSPFv3、RIPv2、IPv4 多播路由，另有 BFD、路由過濾與路由圖（route map）等功能；詳細功能清單以實機為準。
  • 兩者概念相當，但部分設定細節不同（例如路由設定檔在 ARE 可跨 Logical Router 共用）。新環境採用哪一種，請依機型、版本與原廠建議決定；本課程的指令與畫面以傳統路由引擎為主，ARE 的細節以實機為準。

設定順序檢查表

這份順序也是疑難排解時的檢查順序，建議背下來。

  • 1. 介面：Network > Interfaces，類型選 Layer3，設定 IP 位址（Static 或 DHCP Client）。
  • 2. 區域：Network > Zones，建立 Layer3 類型 Zone 並指派介面（也可在介面的 Config 頁籤直接建立）。
  • 3. 虛擬路由器：Network > Virtual Routers，加入介面並設定靜態預設路由。
  • 4. 安全政策：Policies > Security，允許需要的跨區流量（第 8、9 章）；要連上網際網路，還需要 Source NAT（第 10 章）。
  • 5. Commit：提交組態（第 4 章），接上線路後確認介面連線狀態為綠燈。

踩坑：忘了把介面加入 Virtual Router 或 Zone

介面沒加入虛擬路由器，路由表裡就不會有它的直連網段，也就無法轉送；沒指派 Zone，流量根本不被處理。 Commit 成功不代表通：它只代表設定通過驗證，不代表你的網路設計已完整。

Failover 五、路徑監控、疑難排解與 Loopback

多條預設路由與 Path Monitoring

同一個目的網路可以設定多條預設路由，例如兩家 ISP。Metric 最低的那條會被使用。 但光靠 Metric 只能判斷「路由存在」，不能判斷「線路真的通」，所以要搭配 Path Monitoring： 防火牆定期 ping 上游穩定的設備，路徑失敗就把這條靜態路由從路由表移除，流量自動改走次佳路由； 失敗後監控仍持續進行，恢復後路由會被重新加回（Failback）。

Path Monitoring 欄位說明
Source IP / Destination IPping 的來源位址與監控目標。目標應是穩定可靠的設備，且位址類型（IPv4 或 IPv6）需與路由相同。一條路由最多 8 個目標，最多可監控 128 條靜態路由。
ICMP Ping Interval探測間隔，1 到 60 秒，預設 3 秒。
ICMP Ping Count連續未回應幾次算失敗，3 到 10，預設 5。預設值下約 15 秒偵測到失敗。
Failure ConditionAny：任一目標失敗就算失敗；All：所有目標都失敗才算失敗。原廠建議選 All，避免單一目標維修就誤判整條路由失敗。
Preemptive Hold Time失敗的路徑恢復後，要先持續正常多久（0 到 1440 分鐘，預設 2 分鐘）才把路由重新加回；設 0 則一恢復就立刻加回。期間若又斷線，計時重來。

踩坑：監控目標選得不好

監控一台自己常關機、或會限制 ICMP 的主機，會讓路由無故被移除，造成斷線。請選上游路由器或穩定的對外位址。 只設一個目標又選 Any，等於這一台一有狀況就整條切換；多個目標搭配 All 比較穩。另外，這個機制靠 ICMP，上游的設備若不回應 ping，路徑會被誤判為失敗。

疑難排解：看 RIB、FIB 與監控狀態

路由不如預期時，到 Network > Virtual Routers，在該虛擬路由器的列點選 More Runtime Stats：

  • Route Table（RIB）：所有已知的路由。找不到預期的路由，先看這裡。
  • Forwarding Table（FIB）：流量實際會依據哪些路由轉送。RIB 有、FIB 沒有，表示該路由沒被選中或未生效。
  • Static Route Monitoring（在 Routing 頁籤）：Path Monitoring 是否啟用，以及每條路由的狀態（Up、Down 或 Disabled），游標移到狀態上可看到監控的 IP 與最近的 ping 結果。
  • 事件紀錄：Monitor > Logs > System 會有 path-monitor-failure 與 path-monitor-recovery 事件。

Loopback 介面

Loopback 是有 IP 位址的邏輯介面，行為像一台主機的介面，用來提供對防火牆自身服務的存取。 不論流量從哪個 Zone 進來，只要能路由到這個位址，就能存取同一組服務；它不依賴任何一個實體埠的連線狀態。 設定路徑：Network > Interfaces > Loopback > Add，輸入 Loopback 介面 ID（名稱為唯讀）、選擇 Virtual Router 與 Layer 3 類型的 Zone， 並可在 Advanced 套用 Interface Management Profile。

  • 教材提到的用途：讓不同 Zone 的使用者，經由同一個位址連到防火牆提供的服務。
  • 另一種用例：兩個虛擬路由器之間要跑動態路由時，各建一個 Loopback，用靜態路由互通後再建立鄰居。

版本差異：Loopback 的遮罩

教材（資安院較新的簡報）投影片寫「Do not assign a netmask to the IP addresses」，也就是不要指定網路遮罩（講者說明則寫不設遮罩或 /32）。 現行 PAN-OS 12.x 的 Loopback 設定只接受 /32 子網路遮罩。 教材的「不設遮罩」與 /32 實質上都是單一主機位址，實務上請直接填 /32，並以實機畫面為準。
