網路篇 - 單元 7：Layer 2/VLAN 介面與 PBF

講師導言

上一章的 Layer 3 介面，是讓防火牆扮演「會檢查封包的路由器」。這一章換個角色： 有些環境不想動 IP 規劃、也不需要路由，只希望防火牆插進同一個網段裡當交換器，順便檢查流量，這就是 Layer 2 介面。 當這個網段還想連到別的網段時，再用 VLAN 介面把 Layer 2 接到 Layer 3。 最後一個主題是 Policy-Based Forwarding（PBF）：路由表說往 A 走，但你偏要讓特定流量走 B，該怎麼設、斷線時怎麼切換、回程怎麼不走歪。

Goals 本章學習目標

  • 說明 Layer 2 介面的用途，並完成 Layer 2 介面、Zone 與 VLAN 物件的設定
  • 建立 Layer 2 子介面，說明 VLAN tag 的作用，以及不同 Zone 之間為何預設不通
  • 說明 VLAN 介面如何把 Layer 2 網段接到 Layer 3，並指出 VLAN 介面編號不等於 VLAN tag
  • 說明 PBF 與路由表的關係，並建立一條 PBF 規則（比對條件、動作、出口介面與下一跳）
  • 說明為什麼不建議用應用程式（Application）當 PBF 比對條件
  • 設定 PBF 的路徑監控與 Enforce Symmetric Return，並用指令確認規則狀態

Layer 2 一、Layer 2 介面：讓防火牆當交換器

Layer 2 介面讓防火牆在兩個以上的介面之間做交換：裝置接在同一個 Layer 2 網段，防火牆依訊框中的目的 MAC 位址決定從哪個埠送出去。 它通常用在不需要路由的環境；區域（Zone）與安全政策仍然照常檢查與控管流量。 多個 Layer 2 介面要互相交換，必須歸屬於同一個 VLAN 物件。

Layer 2 介面的設定重點

路徑：Network > Interfaces > Ethernet > 選取介面

1 類型與區域

  • Interface Type 選 Layer2
  • 在 Config 頁籤指派 Security Zone（可直接建立新的）
  • Zone 的類型也要是 Layer2，介面類型與 Zone 類型必須一致

2 VLAN 歸屬

  • Config 頁籤有 VLAN 欄位，未加入時為 None
  • 要互相交換的介面，放進同一個 VLAN 物件（下一節建立）
  • 每個 Layer 2 介面只能屬於一個 VLAN，同一個 VLAN 可以有多個介面

3 選用與收尾

  • 可套用含 protocol protection 的 Zone Protection Profile，控制 Layer 2 區域之間的非 IP 通訊協定封包
  • 設定完成後 Commit（第 4 章）

重點：Layer 2 不等於「不檢查」

防火牆做 Layer 2 交換，不代表放行一切。介面屬於哪個 Zone、Zone 之間有什麼安全政策，仍決定流量能不能通過（第 8 章）。 與 Virtual Wire（第 5 章）相比，Layer 2 介面多了 MAC 位址學習與依 MAC 交換的行為，因此能把多個介面串在同一個網段；Virtual Wire 則是一進一出的「透明線」。

版本差異：STP 與新的 Layer2 Switch 介面

  • 教材（PAN-OS 8.0）的示意圖只寫「STP forwarding」，也就是防火牆把 STP 訊框轉送出去，自己不參與生成樹運算。
  • 現行版本：這個預設行為沒變，Layer 2 介面預設會把 BPDU 轉送（flood）到同一個廣播網域。
  • 較新的 PAN-OS 12.2.2 起，可在特定機型上設定 STP（支援 IEEE 802.1s MSTP），預設為停用；啟用位置在 Network > Network Profiles > STP Profile 與介面的 STP 頁籤。
  • 支援的機型要看型號：PA-550、PA-560、PA-545-POE、PA-555-POE（新款 PA-500 系列），以及 PA-1510-POE、PA-1520-POE、PA-1530-POE（PA-1500 系列）。不要和教材機型表上的舊款 PA-500 混為一談。
  • 同一版另有新的 Layer2 Switch 介面類型，可在 access／trunk 埠上以硬體交換（支援 RSTP 與 MSTP）。這不是本章教材的範圍，也不適用所有機型；你的環境用哪一種介面，請以機型與版本為準。
  • 此外，防火牆可以改寫 Cisco PVST+ 與 Rapid PVST+ BPDU 內的 Port VLAN ID，細節本章不展開。

踩坑：把兩個 Layer 2 介面接回同一台交換器

防火牆預設只轉送 STP 訊框，並不會替你阻斷環路。若把防火牆兩個 Layer 2 介面都接回同一個網段，而周邊交換器又沒有妥善處理，就可能形成環路、造成廣播風暴。 接線前先畫出拓撲，確認每個網段只有一條路徑通過防火牆。另外，介面沒指派 Zone 就不處理流量，這點和 Layer 3 介面相同（第 5、6 章）。

Subinterface 二、Layer 2 子介面與 VLAN 物件

上游交換器以 Trunk（802.1Q）送來多個 VLAN 時，可以把實體 Layer 2 介面切成多個子介面，每個子介面帶一個 VLAN tag，並各自指派 Zone。 這樣不同 VLAN 的流量在防火牆內是隔離的：VLAN 之間要通，必須經過路由；而不同 Zone 之間，安全政策預設會擋下。這種切法也很適合多租戶網路。

建立子介面

  1. Network > Interfaces > Ethernet，把實體介面的 Interface Type 設為 Layer2，Config 頁籤的 VLAN 保持 None，並指派 Zone，按 OK。
  2. 選取該介面，按 Add Subinterface。介面名稱前半固定，句點後輸入子介面編號（1 到 9999）。
  3. 輸入 VLAN Tag（1 到 4094），並為子介面指派 Zone。
  4. Commit。
子介面 VLAN tag Zone（Layer2） 所屬 VLAN 物件（練習命名）
ethernet1/2.11Engvlan-eng
ethernet1/3.11Engvlan-eng
ethernet1/2.22HRvlan-hr
ethernet1/3.22HRvlan-hr

改寫自教材的子介面示意圖（Eng 與 HR 各有一個 VLAN，分別出現在兩個實體介面上）。VLAN 物件的名稱與歸屬是為了練習而假設的。

VLAN 物件：決定誰跟誰交換

路徑：Network > VLANs > Add

欄位說明
Name最多 31 個字元，區分大小寫、不可重複，只能用字母、數字、空格、連字號與底線。
Interfaces屬於這個 VLAN 的防火牆介面（含子介面，以實機為準）。同一個 VLAN 裡的介面彼此交換。
VLAN Interface選一個 VLAN 介面，讓流量能被路由到 VLAN 之外（下一節）。
Static MAC Configuration指定某個 MAC 位址要從哪個介面到達，會蓋過防火牆學到的介面與 MAC 對應。

與第 6 章 Layer 3 子介面的差別

Layer 3 子介面：每個子介面有自己的 IP 與路由，防火牆是閘道。Layer 2 子介面：沒有 IP，同一個 VLAN 內由防火牆交換，只有跨 VLAN 時才需要路由。 實體介面是 Layer 2 還是 Layer 3，由它的 Interface Type 決定，同一個實體介面下的子介面類型要和它一致，不要混用。

補充：編號範圍與管理方式

教材沒有寫出子介面編號與 VLAN tag 的範圍。現行 PAN-OS：子介面編號為 1 到 9999，VLAN Tag 為 1 到 4094；若改用 Strata Cloud Manager 管理，子介面編號範圍是 1 到 4094，且建議與 VLAN Tag 取相同數字以利維護。 子介面編號只是名稱的一部分，不必等於 VLAN tag，但實務上刻意讓兩者一致比較好維護。

踩坑：子介面通了，但跨 VLAN 不通

兩個子介面屬於不同 Zone，跨區預設被安全政策擋下；即使放行政策，VLAN 之間仍是不同廣播網域，必須有人做路由（例如下一節的 VLAN 介面，或上層的 Layer 3 設備）。 另外，防火牆子介面只處理帶有對應 tag 的訊框，上游交換器連到防火牆的埠必須是 Trunk，並允許對應的 VLAN 通過。

VLAN Interface 三、VLAN 介面：把 Layer 2 接到 Layer 3

VLAN 介面是有 IP 位址的邏輯介面，用來連接 Layer 2 與 Layer 3。 它一邊接上 VLAN 物件（Layer 2 側），另一邊加入虛擬路由器（Layer 3 側），成為這個 Layer 2 網段對外的閘道。 Layer 2 網段上的主機把預設閘道指向 VLAN 介面的位址，就能離開本網段，防火牆再依路由表轉送。

圖中位址為示意用的私有位址；Zone 名稱僅供練習。注意 VLAN 介面所在的 Zone 是 Layer 3 類型，與兩個 Layer 2 介面的 Zone 不同。

設定步驟

路徑：Network > Interfaces > VLAN > Add

  • Interface Name：前半唯讀為 vlan，後面輸入一個介面編號（例如 10）。這個編號只是名稱，不是 VLAN tag。
  • VLAN：選擇要連接的 VLAN 物件，這是接到 Layer 2 網路的一端。
  • Virtual Router 與 Security Zone：接到 Layer 3 網路的一端；Zone 為 Layer 3 類型（若已啟用 Advanced Routing Engine，此處改設定 Logical Router，見第 6 章，以實機為準）。
  • IPv4／IPv6 頁籤：設定 Static 位址（CIDR 格式）等，作法與第 6 章 Layer 3 介面相同。
  • VLAN 介面的 VLAN 欄位，與 Network > VLANs 裡 VLAN 物件的 VLAN Interface 欄位，指的是同一個關聯，在任一處設定即可，不必設兩次（兩邊是否同步，以實機畫面為準）。設定完成後，可以到 Network > VLANs 確認該 VLAN 物件已顯示這個 VLAN 介面；有了這個關聯，流量才能被路由到網段外。

🏢 生活化比喻：辦公大樓的樓層與櫃台

  • Layer 2 介面與 VLAN 物件：同一層樓的共用走廊，同事在走廊上直接找到彼此，不必經過任何人。
  • VLAN 介面：這一層樓的櫃台，有自己的門牌（IP）。要去別層樓或出大樓，就得先到櫃台。
  • Virtual Router：櫃台後面的指路員，告訴你別的樓層和大門各往哪走。

補充：編號範圍與限制

  • 教材只標示「介面編號（不是 VLAN tag）」，沒有寫範圍。現行 PAN-OS 的 VLAN 介面編號範圍是 1 到 9999。
  • 另外，DHCP Client 位址類型不支援 HA active/active（HA 於第 17 章說明）。

踩坑：Layer 2 側與 Layer 3 側是不同 Zone

VLAN 介面自己在 Layer 3 Zone，而成員介面在 Layer 2 Zone，主機走 VLAN 介面出去其實是「跨區」，必須有安全政策放行。 同一個 VLAN 內的主機互相通訊（只走 Layer 2 交換），兩端介面若在同一個 Zone，適用同區規則；若分屬不同的 Layer 2 Zone（像教材圖上的 Zone A、Zone B），仍然是跨區，需要安全政策放行。 另外，VLAN 介面沒有加入 Virtual Router 就沒有路由能力；主機的預設閘道若還指向舊設備，流量根本不會送到防火牆。

PBF 四、Policy-Based Forwarding 規則

平常防火牆用封包的目的 IP去查虛擬路由器的路由表，決定出口介面。 Policy-Based Forwarding（PBF）讓你依其他條件，指定一個和路由表不同的出口介面，理由可能是效能，也可能是安全。 教材的例子：總公司與分公司之間有一條網際網路線路和一條專線，對頻寬敏感或未加密的應用走專線，其餘（例如已加密的、對頻寬不敏感的）走網際網路。 實作時，請改用服務（連接埠）或目的位址來描述這些流量，原因見本節的踩坑框。

建立一條 PBF 規則

路徑：Policies > Policy Based Forwarding > Add。必填的只有三樣：規則名稱、來源（Zone 或介面）、出口介面，其餘有預設值或可省略。

頁籤內容
General規則名稱（建議有描述性）。
SourceType 選 Zone 或 Interface；可再加來源位址（可 Negate 排除）與來源使用者。要啟用 Symmetric Return，必須選 Interface。
Destination/Application/Service目的位址（預設 any，可 Negate）、應用程式、服務（Layer 4 連接埠）。
ForwardingAction、出口介面、下一跳、Monitor、Enforce Symmetric Return、Schedule。

Forwarding 頁籤的動作與下一跳

Action 四種

  • Forward：把封包送到指定的出口介面。
  • Forward to VSYS：送到另一個虛擬系統（多 VSYS 機型）。
  • Discard：直接丟棄符合的封包。
  • No PBF：符合的流量不套用 PBF，改走路由表（常用來排除例外流量）。

Next Hop 三種

  • IP Address：IP Netmask 位址物件，IPv4 要 /32，IPv6 要 /128。
  • FQDN：解析結果必須與 PBF 介面在同一網段，否則不採用。
  • None：以封包的目的 IP 當下一跳；目的不在出口介面網段時會轉送失敗。

Schedule 可讓規則每日、每週或單次生效。多筆規則由上而下比對，第一筆符合者生效。

🚚 生活化比喻：貨運分流員

  • 路由表：郵遞區號對照表，只看「寄到哪裡」決定走哪條路。
  • PBF：站在路口的分流員，看的是「誰寄的、寄什麼」。急件（對頻寬敏感）走專車，一般件走平價貨運，不管郵遞區號怎麼說。
  • Discard：違禁品直接銷毀；No PBF：這批貨照郵遞區號走，不經過分流員。

補充：教材沒講的 PBF 細節

  • 教材（PAN-OS 8.0）只示範 Forward：指定來源、目的、應用程式、連接埠，以及出口介面與下一跳位址。Discard、No PBF、Forward to VSYS 與 Next Hop 的 FQDN／None 選項，是補充現行做法。
  • 現行做法不建議使用應用程式比對（見下方踩坑）；自訂應用程式、Application Filter 與 Application Group 也不能用在 PBF 規則。
  • 只有 Layer 3 介面支援 PBF，Loopback 介面不支援。

版本差異：FQDN 下一跳

原廠文件對 FQDN 下一跳說法不一：有的地方列出 FQDN 這個選項，有的地方卻寫下一跳只能是 IP 位址。FQDN 下一跳從哪個版本開始支援，本次未能確認，請以你使用的版本與實機為準。

踩坑：用應用程式當比對條件

PBF 在工作階段的第一個封包（SYN）就要決定出口，這時防火牆往往還認不出是什麼應用程式。結果是：第一次連線無法套用規則；之後的連線可能因為快取而被誤套用；應用程式在連線中途改變時，PBF 也無法跟著改。 能用服務（連接埠）比對就不要用應用程式。另外，做網際網路分流時，記得把內部目的網段用 Negate 排除，否則內網流量可能被送往 ISP。

Failover 五、路徑監控、Symmetric Return 與驗證

PBF 規則只管「去程」要走哪裡，但線路可能斷，從另一條 ISP 連進來的流量，回應也可能走錯線路。教材指出 PBF 有路徑監控，讓防火牆確認網路路徑的連通性。 最常見的實例是雙 ISP：主要 ISP 由 PBF 規則負責，備援 ISP 則是虛擬路由器裡的一條預設路由。

路徑監控（Monitor）

路徑：PBF 規則 Forwarding > Monitor；監控設定檔在 Network > Network Profiles > Monitor

  • 防火牆用 ICMP ping 當心跳，檢查指定位址是否可達。沒有指定 target IP 時，就監控下一跳位址。
  • Monitor Profile 定義失敗時的動作與判定門檻，預設的 Interval 為 3、Threshold 為 5（範圍都是 2 到 10）。
  • 勾選 Disable this rule if nexthop/monitor ip is unreachable：位址不可達時規則停用，由虛擬路由器的路由表接手（備援預設路由生效）；恢復後規則重新啟用。
Profile 的 Action行為
Wait Recover失敗時繼續等待恢復，封包仍依 PBF 規則轉送。
Fail Over改走備援路徑；該工作階段其餘封包改查路由表。

和第 6 章靜態路由的 Path Monitoring 不一樣

第 6 章是替靜態路由設監控，失敗時把路由移出路由表。本章是替PBF 規則設監控，失敗時是規則被停用（或依 Profile 動作處理），之後由路由表決定出口。兩者的設定位置與觀念都不同，不要混用。

Enforce Symmetric Return

雙 ISP 這類非對稱路由的環境，同一台內部伺服器可能從兩條 ISP 都被連入。從預設路由沒有指向的那條 ISP 連進來的工作階段（例如本節圖中只靠 PBF 轉送的主要 ISP-1），回應封包若照路由表走預設路由，就會從另一條 ISP（備援的 ISP-2）送出。進來與出去不在同一個介面，防火牆無法追蹤整個工作階段的狀態，連線就會失敗。 這時要針對從那條 ISP 的介面進來的流量建一條 PBF 規則（Source 選 Interface，指定該 ISP 的入口介面），在 Forwarding 頁籤啟用 Enforce Symmetric Return，並加入 Next Hop Address List（填該 ISP 路由器的位址）：

示意：預設路由指向備援 ISP-2，主要 ISP-1 只靠 PBF 轉送，所以從 ISP-1 連進來的流量，就是「預設路由沒指向」的那一條。

  • 回應流量會略過一般的路由查詢，改送回遞送第一個封包（SYN）的 MAC 位址，也就是從原本進來的介面出去。
  • 這個選項管的是防火牆自己送出的回應，不能決定 ISP 從哪條線把封包送回來。內網主機連出網際網路的工作階段，回應能不能從正確的 ISP 回來，靠的是每個 ISP 各一條 Source NAT（第 10 章），不是這個選項。
  • 規則的 Source 必須選 Interface，不能只選 Zone（原廠文件對這一點說法不一，以實機為準）。
  • Next Hop Address List 最多 8 個位址；Tunnel 與 PPPoE 介面的位址不能當下一跳。
  • 若目的 IP 與入口或出口介面在同一網段，防火牆會做一般的路由查詢，不強制對稱回程，以免封包被默默丟棄。
  • 防火牆是用 ARP 表記住回程的下一跳，表的大小依機型固定、無法調整，可用 show pbf return-mac all 查看。

驗證

  • show pbf rule all：確認規則狀態是 Active（正常）或 Disabled（監控判定失敗）。
  • 流量日誌（Monitor > Logs > Traffic）與 show session id <ID>：確認實際的出口介面與 NAT 轉換。
  • 每個出口 ISP 都要有對應的 Source NAT 規則（第 10 章），否則回應封包回不到正確的介面與位址；以及安全政策放行這些 Zone 之間的流量（第 8 章）。

補充：教材的 PBF 路徑監控只有一句話

教材（PAN-OS 8.0）只寫「PBF path monitoring 讓防火牆驗證網路路徑連通性」，沒有 Monitor Profile、Disable 勾選、Symmetric Return 與驗證指令的細節，這幾項是補充現行做法。 Monitor Profile 的 Interval 單位、不同 Action 對新舊工作階段的詳細影響，說明不夠明確，請以實機為準。

踩坑：從非預設 ISP 連入的流量沒啟用 Symmetric Return，或監控目標選錯

伺服器同時可從兩條 ISP 連入，卻沒有對非預設 ISP 進來的流量啟用 Symmetric Return，常見症狀是「從那條 ISP 連進來的連線失敗」，原因是回應照預設路由從另一條 ISP 送出，進出不同介面。外連流量的回程對稱不靠這個選項，而是每個 ISP 各一條 Source NAT。 監控目標也要選穩定的設備：目標常關機或不回應 ping，會讓規則被無故停用、流量改走備援。 最後別忘了 PBF 只決定「出口」，仍然要有安全政策與 NAT 規則配合。
