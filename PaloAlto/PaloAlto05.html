網路篇 - 單元 5：網路分段、安全區域與介面類型

講師導言

防火牆接上線之前，先要決定兩件事：網路要切成哪幾塊，以及每個實體介面要用哪一種身分接進來。 前者是「安全區域（Zone）」，後者是「介面類型（Interface Type）」。這一章把兩者的關係講清楚： 介面放進哪種區域、區域之間為什麼預設不通、旁路監看（Tap）與串接線路（Virtual Wire）各適合什麼場合。 三層介面（Layer 3）與虛擬路由器留到第 6 章，二層與 VLAN 留到第 7 章。

Goals 本章學習目標

  • 說明網路分段的目的，以及 Zero Trust「從不信任、一律驗證」的基本想法
  • 解釋安全區域（Zone）是什麼，並說出區域內與區域間的預設流量行為
  • 依介面類型選出對應的區域類型，並知道介面一定要先放進區域才會處理流量
  • 描述 Tap 介面的用途與限制（只能看、不能擋）
  • 設定並解釋 Virtual Wire 物件、介面與子介面，包含 VLAN 標籤 0 的意思

Concept 一、為什麼要分段？Zero Trust 的想法

網路分段（Network Segmentation） 的目的是「保護資料的存取」。規劃時先問業務與組織的問題： 誰需要存取什麼？採最小權限原則（Principle of Least Privilege），並把法規要求（例如信用卡資料）一併考慮進去。 如果整個內網是一大塊平面，攻擊者只要攻破一台電腦，就能在內網裡橫向移動（lateral movement）去找重要資料； 把網路切成多個區域、區域之間由防火牆檢查，就能縮小受攻擊面（attack surface）。

圖例：實線代表有安全規則允許的跨區流量；虛線代表沒有規則、被預設拒絕。此例取自教材：B2B 區的 Bob 與 Accounting 區的 Accounting-Grp 可以存取 PCI 區，其餘跨區流量一律被預設擋下。

Zero Trust：從不信任，一律驗證

Zero Trust 的核心是「Never trust, always verify」。白話一點：不信任任何使用者、裝置、應用程式或封包，每一項都要驗證。 落實在防火牆上，就是兩個方向都要檢查：

流量方向 名稱 說明
進出邊界南北向（north-south）網際網路與內部之間，包含入站（inbound）與出站（outbound）
內部之間東西向（east-west）內部區域之間，例如 web-int、app-int、db-int 之間的往來，同樣要檢查

🏢 生活化比喻：社區大樓的門禁與樓層管制

  • 只管大門的舊做法：進了大門就能搭電梯去任何一層。壞人混進來，整棟都走得到。
  • 分段（Zone）：每一層樓是一個區域，住戶在自己樓層走動不受限（同區域預設放行）。
  • Zero Trust：要去別的樓層，電梯每次都要刷卡驗證（跨區預設拒絕，要有規則才放行）。大門和電梯兩處都有管制，才是南北向加東西向。

重點

要完整保護網路，所有流量都必須流經防火牆。區域切得越細，控制力越強，受攻擊面也越小；功能、應用程式用法或使用者權限能清楚劃分的地方，就可以各自成為一個區域。

Zone 二、安全區域（Security Zone）

Security Zone 是「一個或多個防火牆介面，加上接在這些介面後面的網路區段」的集合，用來把安全需求相近的裝置與使用者歸成一組，通常與網路分段對應。 安全政策規則是寫在區域與區域之間的，不是直接寫在介面上。

四條基本規則

  • 一個介面只能屬於一個區域；一個區域可以包含多個實體或邏輯（子介面）介面。
  • 沒有放進區域的介面不會處理流量。
  • 管理介面（MGT）與 HA 介面不放進區域。
  • 區域有類型（Zone Type），只收對應類型的介面，下一節會整理。

預設行為：區域內放行、區域間拒絕

區域內（Intrazone）

同一個區域內的流量，預設允許，不需要另外寫規則。

區域間（Interzone）

不同區域之間的流量，預設拒絕，直到你寫一條規則允許它。

這兩個行為是由規則庫最底部的預設規則（intrazone-default 與 interzone-default）提供的：它們預先定義為允許所有區域內流量、拒絕所有區域間流量，預設唯讀，但可以覆寫（override）動作、日誌設定、標籤與安全設定檔。 安全規則的類型（Rule Type）分 Universal（預設，同時涵蓋區域內與區域間）、Intrazone 與 Interzone 三種，第 8、9 章會再細談。

建立區域

選單路徑：Network > Zones > Add。最基本要做三件事：

  1. 指定區域名稱（Name）。
  2. 指定區域類型（Type）。
  3. 指派介面（Interfaces）：必須是對應類型的介面。

區域設定頁上還有幾個欄位，本章只點到名字，細節留到對應章節：

欄位用途
Zone Protection Profile決定防火牆如何回應來自該區域的攻擊（如洪水、偵察）。原廠建議每個區域都套用，作用在流量進入的入口（ingress）區域。
Enable User Identification啟用該區域的 User-ID 使用者對應。原廠建議只在受信任（trusted）的區域啟用（第 14 章 User-ID）。
Log Setting選擇 Log Forwarding 設定檔，把區域防護日誌轉送到外部系統。

最常見的踩坑一：介面沒進區域，流量就是不通

介面接好線、燈也亮，但沒有指派到區域，就不會處理任何流量。排查「接上去卻完全不通」時，先到 Network > Interfaces > Ethernet 確認介面類型與所屬區域，別急著懷疑安全規則。

最常見的踩坑二：以為跨區預設會通，或以為同區也會被擋

跨區要通，一定要有明確的 Allow 規則；同一區域內則預設就通。因此「把所有主機放進同一個區域」等於放棄區域內的隔離，要隔離就得拆區域。 另外，如果你在規則庫上方放了一條 any 到 any 的拒絕規則，同區域內的流量也會被擋，因為它排在預設放行規則之前。

Mapping 三、介面類型與區域類型對應

防火牆的資料平面負責處理 in-band 網路介面（走業務流量的介面）。實體乙太網路介面可以設成不同的部署模式，能力由簡到繁：

部署模式 能做什麼 典型用途 對應區域類型
Tap 不必串在線路上，就能看到應用程式、使用者與內容；不能阻擋、不能流量整形 評估與稽核既有網路 Tap Zone
Virtual Wire App-ID、Content-ID、User-ID、SSL 解密，也含 NAT；不需要 IP 與 MAC，不做路由與交換 插入既有線路，不想改動前後設備 Virtual Wire Zone
Layer 3 具備 Virtual Wire 的所有能力，再加上三層服務：虛擬路由器、VPN、路由協定（第 6 章） 邊界閘道、多網段路由 Layer 3 Zone
Layer 2 以 VLAN 為單位做二層交換並檢查（第 7 章） 需要防火牆承擔二層交換的場合 Layer 2 Zone

「不同類型的區域只收特定類型的介面」

對應關係依教材（PAN-OS 9 / 10 時代簡報）整理；橘色為本章要實作的兩種。MGT 與 HA 介面不屬於任何區域。教材的圖只畫了前五種區域類型（圖中虛線框的 External 是第六種）；區域類型下拉選單實際共有六種：Tap、Virtual Wire、Layer2、Layer3、External、Tunnel。第六種 External 區域用於控制「同一台防火牆上多個虛擬系統（virtual system）之間」的流量，只有多虛擬系統的機型才看得到，一般單一系統環境用不到。Tunnel 區域是給通道內容檢查（Tunnel Content Inspection）用的，不指派介面；VPN 的 tunnel 介面則放進 Layer 3 區域。

版本差異

  • 教材兩份簡報對 Loopback 與 Tunnel 介面的標示略有出入：較舊的簡報（PAN-OS 8.0）把它們列在 Layer 3 區域，同時又用星號另註「Not in a zone」，兩處並列，說法不明確；較新的簡報只把它們列在 Layer 3 區域，且 Loopback 設定畫面要求選 Layer 3 類型的區域。實作時請以新簡報為準，並以實機為準。
  • Layer 2 與 Layer 3 區域類型會列出該類型的所有乙太網路介面與子介面；上表其餘對應關係以教材為準，並以實機為準。

最常見的踩坑三：區域類型與介面類型對不上

例如把一個設成 Tap 的介面，硬塞進 Layer 3 區域，在下拉選單裡就找不到它。順序是先決定介面類型，再建立或選擇同類型的區域。同一台防火牆可以在不同的實體介面上混用不同類型，所以混合部署時，要先規劃好每個介面的類型與所屬區域。

Tap 四、Tap 介面：旁路被動監看

Tap 介面把防火牆當成「錄影機」：交換器的 SPAN 或鏡射埠（mirror port）把流量副本送給防火牆的 Tap 介面，防火牆在不影響實際線路的情況下，辨識應用程式與威脅，並寫進日誌與 ACC（應用程式指揮中心）報表。

上半：流量照原路走，防火牆只收副本。下半（第五節）：流量實際穿過防火牆，可檢查也可阻擋。

能做的事

  • 辨識應用程式與威脅
  • 記錄並出報表（日誌、ACC）
  • 用流量日誌（Traffic log）的內容，規劃之後正式上線時的安全規則

不能做的事

  • 控制流量：不能阻擋有威脅的流量
  • 流量整形（QoS）
  • Block 與 Reset 動作都不可用

設定步驟

  1. 把防火牆的一個埠接到交換器的 SPAN 或鏡射埠。
  2. 到 Network > Interfaces > Ethernet，點選該介面，Interface Type 選 Tap。
  3. 在 Security Zone 欄位選一個 Tap 類型的區域（可在此新建，也可事先到 Network > Zones 建好）。
  4. 到 Policies > Security 建立規則：來源區域與目的區域都選這個 Tap 區域，動作 Allow，並啟用 Log at Session End。
  5. 安全設定檔（Security Profiles）的動作設成 alert，Commit 之後到 Monitor > Logs 與 ACC 觀察。

最常見的踩坑四：在 Tap 模式期待「擋住」攻擊

Tap 只看得到副本，無法執行 block 或 reset，安全設定檔要用 alert 動作，日誌裡看到「已偵測到威脅」不代表它被擋下。 Tap 安全規則的來源區域與目的區域必須是同一個 Tap 區域。要真正阻擋，必須改用 Virtual Wire 或 Layer 3 串接。

小提醒：Tap 區域什麼時候建立都可以

Tap 區域可以先在 Network > Zones 建立，也可以在介面設定頁的 Security Zone 欄位直接 New Zone，兩種做法結果相同。本章只談 PAN-OS 本機 Web 介面；Strata Cloud Manager 的選單名稱與本章不同。

Virtual Wire 五、Virtual Wire 與子介面

Virtual Wire（虛擬線）把防火牆上的兩個介面綁成一條「看不見的線」，用一個 Virtual Wire 物件連起來。介面本身沒有 IP 位址也沒有 MAC 位址，所以前後的網路設備完全不必改設定。適合「不需要交換、也不需要路由」，只想把防火牆插進既有線路的情況。

1. Virtual Wire 物件

Network > Virtual Wires > Add：建立物件、選兩個介面，並設定允許的 VLAN 標籤。

2. Virtual Wire 介面

Network > Interfaces > Ethernet：Interface Type 選 Virtual Wire，指定物件（可先留空、之後再加）。

3. 區域

兩個介面各放進一個 Virtual Wire 類型的區域（例如 Zone A 與 Zone B），規則寫在兩區之間。

Virtual Wire 物件的主要設定

設定項目說明
Tag Allowed允許通過的 802.1Q VLAN 標籤，可列多個值或範圍並以逗號分隔。0 代表沒有標籤（untagged）的流量（例如 BPDU 這類二層控制流量）。預設值 0，範圍 0 至 4094。
Multicast Firewalling勾選後，安全規則才能套用到穿越虛擬線的多播流量；沒勾選時，多播流量直接透明轉送。
Link State Pass Through勾選後，一側斷線時防火牆會把另一側介面也關閉，兩側設備看到一致的連線狀態，彷彿中間沒有防火牆。

另外，構成一條虛擬線的兩個介面必須有相同的連線速率（Link Speed）與雙工模式（Link Duplex）。

Virtual Wire 子介面（Subinterface）

一條實體虛擬線上若跑著好幾個 VLAN 或網段，可以建立子介面，讓不同標籤的流量歸到不同區域，達成更細的規則與邏輯分流。子介面能依下列條件分類流量：

  • VLAN 標籤（1 至 4094）
  • VLAN 標籤 + IP 分類器（IP classifier，來源 IP）
  • 只用 IP 分類器（處理無標籤流量，依來源 IP）

設定時要填 Subinterface ID、802.1Q VLAN tag、（選填）IP Classifiers、Virtual Wire 物件，以及 Virtual Wire 類型的區域。子介面一樣在 Network > Interfaces > Ethernet 新增。

教材範例：兩組 VLAN 各自成對（VLAN 1 與 VLAN 2），每一對的外側與內側分屬不同的區域，跨區仍需要安全規則放行；這種做法適合多租戶（multi-tenant）網路。圖中只有成對的子介面彼此相連：VLAN 1 的流量只在 ethernet1/2.1 與 ethernet1/3.1 之間往來，VLAN 2 同理，兩組之間不會互通。

最常見的踩坑五：標籤重複或兩側不成對

  • 虛擬線不會改寫 VLAN 標籤，所以進線與出線的成對子介面必須使用相同的標籤。
  • 已經指派給子介面的標籤，不可以又出現在上層 Virtual Wire 物件的 Tag Allowed 清單裡。
  • IP 分類器只能用在虛擬線其中一側的子介面。
  • Virtual Wire 不適合需要交換、VPN 隧道或路由的介面。要路由請改用 Layer 3（第 6 章）。

小提醒：投影片上的說明文字對應哪些選項

  • 教材投影片只用標註文字（例如「多播流量會被轉送」「連線狀態會被轉送」）說明，實際對應到物件上的兩個選項：Multicast Firewalling（勾選後安全規則才管得到多播）與 Link State Pass Through。
  • Virtual Wire 物件除了在 Network > Virtual Wires 建立，也可以在 Ethernet 介面設定頁的 Virtual Wire 欄位選 New Virtual Wire 當場建立；先建立介面、之後再補物件也可以。
