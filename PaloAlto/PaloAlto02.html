Palo Alto Networks NGFW 實戰課程

基礎篇 - 單元 2：管理網路與初始存取

講師導言

防火牆從箱子拿出來、插上電之後，你要怎麼第一次連得進去？這一章就是在回答這個問題。 我們會從專用的管理埠 MGT 與 Console 線開始，完成首次登入、換掉預設密碼，再把管理位址、主機名稱、DNS、NTP 與 Service Route 一次設好。 最後補上一個救命招：設定搞砸或要轉手設備時，怎麼把防火牆重置回預設狀態。

Goals 本章學習目標

  • 說明專用管理埠 MGT 的特性，以及初始設定可用的兩種入口（MGT、Console）
  • 說出出廠預設的管理位址與帳號，並知道首次登入必須變更 admin 密碼
  • 在 Web 介面設定 MGT 介面、主機名稱、DNS 與 NTP
  • 解釋 Service Route 的用途：讓防火牆改從資料埠連外部服務
  • 分辨 request system private-data-reset 與維護模式（maintenance mode）出廠重置的差別

Concept 一、專用管理埠 MGT 與初始存取

Palo Alto 防火牆有一個專用的帶外（out-of-band）管理乙太網路埠，面板上標示為 MGT。 它只負責管理用的連線，不能當成一般的資料埠使用，直接連到第 1 章提到的管理平面。 第一次設定防火牆，只能從下面兩個入口擇一：

入口一：MGT 乙太網路埠

  • 用網路線接電腦與 MGT 埠
  • 電腦網卡要設成與預設管理位址同網段
  • 用瀏覽器（HTTPS）或 SSH 連入

入口二：序列 Console 連線

  • 用終端機軟體連 Console 埠，參數 9600-8-N-1
  • 不依賴任何 IP 設定，網路設錯時的最後一道門
  • 登入提示會顯示防火牆名稱（預設為機型名稱），例如 PA-440 login
項目 出廠預設 備註
MGT 管理位址192.168.1.1／24（網段 192.168.1.0/24）PA 系列硬體防火牆。電腦網卡可暫設成同網段的其他位址，例如 192.168.1.2
預設管理員帳號 admin／密碼 admin出廠時唯一預先建立的管理員帳號。首次登入必須變更密碼（下一節）
Console 參數9600-8-N-1鮑率 9600、8 個資料位元、無同位檢查、1 個停止位元
VM-Series視平台而定沒有硬體上固定的預設位址，見下方說明

🏢 生活化比喻：大樓的管理員專用側門

  • 資料埠：像大樓的正門，訪客（使用者流量）進進出出，由防火牆逐一檢查。
  • MGT 埠：像管理員專用的側門，只讓維運人員進出機房，跟正門的人潮完全分開。
  • Console 線：像機房鑰匙孔，門禁系統壞了、網路設錯時，還能用它直接開門。

VM-Series 與其他管理方式的補充

  • 教材寫「VM-Series 的 MGT 為 DHCP client」。原廠文件說法不一：有的寫 VM-Series 管理介面預設以 DHCP 取得位址，有的寫預設關閉 DHCP（只有 AWS 與 Azure 例外）。部署 VM-Series 前，請看你那個平台的部署文件並在實機確認，不要假設一定拿得到位址，也不要假設一定拿不到。
  • 任何機型的 MGT 都可以自己改成 DHCP client 或靜態位址。
  • 除了本章這種「直接連 MGT」的方式，也可以在一般資料埠上開放管理服務，需搭配 Interface Mgmt 設定檔（第 6 章會用到）。

Flow 二、第一次登入 Web 介面

典型的第一次連線流程如下：先把管理電腦設到同網段，接上 MGT 埠，用預設帳號登入，立刻換掉 admin 密碼，再把 MGT 改成你網路裡真正要用的位址。

預設 admin 的密碼規則

條件要求
長度至少 8 個字元
大寫字母至少 1 個
小寫字母至少 1 個
數字或特殊字元至少 1 個

教材說明：這組規則是針對預設 admin 帳號，無法調整，也不會套用到你之後建立的其他管理員；其他帳號的全域密碼規則可到 Device > Setup > Management > Minimum Password Complexity 設定， 並可用 Device > Password Profiles 針對個別帳號設定密碼有效期限。

Web 介面的填寫提示

  • 紅色底線或紅框的頁籤：該頁裡還有必填項目沒完成。
  • 紅色醒目的欄位：必填欄位；缺少必填資料或內容無效時，OK 按鈕無法按。
  • 右下角的 Tasks 按鈕列出執行中與已完成的工作，確認設定變更是否真的跑完很好用。
  • Help 按鈕會在新分頁開啟說明文件，視窗裡每個選項都有對應說明。

版本差異

  • 教材寫「PAN-OS 9.0.3 起」強制變更預設密碼；現行原廠文件寫的是「PAN-OS 9.0.4 起，預設 admin 密碼必須在首次登入時變更」。兩者差一個小版號，以原廠現行文件為準。你現在遇到的 12.x 一定會要求變更。
  • PAN-OS 10.2 起，管理員使用者名稱也有規定：至少包含一個英文字母或符號（底線、句點、連字號），不能只有數字，連字號不能放在開頭。這是教材（PAN-OS 9/10 年代）沒有的內容。

Config 三、設定 MGT 介面與基本資訊

路徑：Device > Setup > Interfaces > Management。最少必填的是 IP 位址、遮罩（Netmask）、預設閘道（Default Gateway）。

設定項目說明
TypeStatic（靜態位址）或 DHCP Client。用 DHCP 時，建議在 DHCP 伺服器上為這台防火牆做 MAC 位址保留，重新開機後才會拿到同一個位址。
Speed預設自動協商（auto-negotiate），要與對端交換器的埠設定一致。
MTU範圍 576 至 1500，預設 1500。
Administrative Management ServicesHTTP、HTTPS、Telnet、SSH。HTTP 與 Telnet 是明碼傳輸，建議只開 HTTPS 與 SSH。
Network ServicesPing、SNMP、User-ID 等。Ping 建議開啟，方便檢查 MGT 連通性。
Permitted IP Addresses只允許這份清單內的位址來管理防火牆。清單留空（預設）等於任何位址都能連。

一般資訊（Device > Setup > Management）

  • Hostname 與 Domain：主機名稱預設為機型名稱；網域預設為空（教材內的說法不一：講師備註寫網域預設為空，投影片本文卻寫兩者都預設為機型名稱，以實機為準）。MGT 若使用 DHCP，才會出現「接受 DHCP 提供的主機名稱／網域」選項。
  • Login Banner（選填）：登入頁面顯示的警語，例如提醒未經授權不得存取。
  • Latitude 與 Longitude：用來把防火牆標到 ACC 與 Monitor 的地圖上，不影響轉送功能。

踩坑：改了 MGT 位址就連不上了

  • 你正透過 MGT 連著 Web 介面時修改它的位址，目前這條連線就會斷。設定完要用新位址重新連入，電腦的網卡也要換到新網段。
  • 遮罩或閘道填錯，管理網路就進不去了，這時要靠 Console 救援，所以 Console 線和終端機軟體要先準備好。
  • Permitted IP Addresses 留空，管理介面就對整個網路敞開；請只填管理員會使用的位址或網段。
  • 設定要執行 Commit 才會生效，Commit 與組態管理的細節在第 4 章。

Config 四、DNS、NTP 與 Service Route

路徑：Device > Setup > Services。兩種外部服務的重要性不一樣：

DNS：必須設定

  • 防火牆要解析名稱、連到更新伺服器都靠它
  • 至少要手動設定一台 DNS 伺服器，防火牆不會自動借用其他來源（例如 ISP）的 DNS 設定
  • 型式可選 Servers（填 Primary、Secondary）或 DNS Proxy Object
  • 用途包括：找到更新伺服器、解析日誌中的 DNS 項目、解析 FQDN 型位址物件

NTP：選填，但建議設定

  • 可設 Primary 與 Secondary 兩台，Primary 失聯時才有備援
  • 時間一致，排程工作才能準時執行，跨設備比對日誌時間也才對得上
  • 例如可用 pool.ntp.org 當作 Primary NTP Server
  • 驗證方式預設為 None，也可改用 Symmetric Key 或 Autokey

同一頁還有 Update Server，預設是 updates.paloaltonetworks.com，除非技術支援指示，否則不要更改； 勾選 Verify Update Server Identity 會驗證更新伺服器的 SSL 憑證是否由受信任單位簽發。 授權啟用與軟體更新的流程，留到第 3 章。

Service Route：改變防火牆「從哪裡出去」

預設情況下，防火牆是從 MGT 埠去連外部服務，例如 DNS、內容更新、授權取得、NTP。 如果不想讓管理網路直接上網，可以設定 Service Route，改由某個資料埠（in-band port）代為出去。

📮 生活化比喻：公司寄信的窗口

公司預設所有信件都交給總務室（MGT）寄出。Service Route 就像你告訴總務：「這幾種信，改交給業務部的窗口（資料埠）寄。」信的內容不變，只是出門的路不同。

設定步驟

  1. 進入 Device > Setup > Services > Service Route Configuration（支援多虛擬系統的機型要先點 Global 分頁）。
  2. 選 Customize，勾選要改走資料埠的外部服務，按 Set Selected Service Routes（部分版本的按鈕文字是 Set Selected Routes，以畫面為準）。
  3. 在對話框選擇 Source Interface 與 Source Address（介面有多個位址時，可指定用哪一個）。
  4. Commit 之後，防火牆才會改用該資料埠連這些服務。建議優先調整 DNS、Palo Alto Networks Services、URL Updates 與 AutoFocus 這幾項，授權與內容更新才會正常。

踩坑：沒設 DNS，或 Service Route 路徑不通

  • 沒設 DNS：防火牆解析不了名稱，連更新伺服器都找不到，之後第 3 章的授權與更新會全部卡住。
  • Service Route 的來源位址不會跟著介面位址自動變：改了介面 IP 之後，若沒同步更新 Service Route，Commit 可能失敗（以實機為準）。
  • 作為 Service Route 來源的資料埠，必須設定靜態 IP 位址。
  • 改走資料埠後，該資料埠必須有路由與安全政策放行這些外部服務，否則更新與授權會斷。路由與政策分別在第 6、8 章。

版本差異

  • 教材只有 DNS 伺服器與 NTP 伺服器的簡單欄位。現行 PAN-OS 12.x 的 Services 頁面在 NTP 驗證多了 SHA256 與 SHA512 演算法（較舊版本只列 MD5、SHA1）。
  • PAN-OS 11.2.1 之後的 DNS 設定新增加密 DNS 連線選項（DoH 與 DoT）與退回非加密 DNS 的選項，預設為 None。

Recovery 五、重置為出廠設定

設定改到無法收拾，或設備要轉交給別人之前，你會需要把防火牆重置。要用哪一種方法，取決於你還記不記得 admin 密碼；知道密碼時，還要看你要的是「只清除設定與日誌」，還是「完整出廠重置」：

方式適用情境與效果
CLI：
request system private-data-reset		需要登入 CLI（知道 admin 密碼）。會清除所有日誌、將設定還原成預設值，並重新開機。教材提醒：包含 IP 位址在內的設定都會被重置，所以遠端操作時連線會斷。
維護模式：
Console 進入 Maintenance Mode		需接 Console。知道密碼時：登入後執行 debug system maintenance-mode，防火牆會重新開機進入維護模式（要完整出廠重置，例如設備退役，就走這條路）。不知道密碼時：教材的做法是開機過程由 Console 輸入 maint 進入維護模式，實際提示依機型與版本而異，以實機為準。進入後選擇 Factory Reset（教材寫 Reset to Factory Default）。完成後若預設帳號一時登不進去，可能是自動 Commit 還沒跑完，稍候再試。
改載入其他組態教材也提到可把另一份組態載入到執行中記憶體，不一定要整台重置；載入與還原組態是第 4 章的內容。

踩坑：private-data-reset 不等於出廠重置

  • 這個指令的效果不同於在維護模式做的出廠重置；它不做資料零化（zeroization），也不會抹除系統磁碟，理論上仍可能以位元層級的復原程序取回資料。設備要退役或轉手時，不要只靠它。
  • 已安裝的內容更新（content）與目前的 PAN-OS 版本會保留。
  • 執行前先匯出一份組態備份。防火牆會重新開機，管理位址也會回到預設，遠端連線一定會斷，請確認人在現場或有 Console 可用。
  • 重置之後若要重新上線，要把組態、授權與軟體、內容更新依序補回（授權與更新見第 3 章）。

版本差異

教材（PAN-OS 8.0 版簡報）列出這兩種做法。request system private-data-reset 目前找到的說明只標註適用 PAN-OS 9.1 至 11.0；現行 12.x 是否有任何行為變動，本章未逐一查證，實作前請以你機器上的 CLI 說明為準。
