Ivanti Connect Secure SSL VPN 實戰課程

單元 4:初始化與基本設定

講師導言

設備剛拆封時,誰也連不上它。這一章要把它從「一台空白的機器」變成「管理員能登入、時間正確、有授權、有正式憑證」的狀態。 順序是這樣的:先用 Console 設好最小限度的網路與管理員帳號,接著全部改用瀏覽器完成。 照著官方建議的順序走,後面每一步才不會被前面的錯誤卡住,例如時間沒校準,TOTP 與 SAML 就會莫名其妙失敗。

Goals 本章學習目標

  • 說出初始化的八個步驟與先後順序
  • 備妥 Console 初始化要輸入的值,並說明為什麼 Console 只設 Internal port
  • 用瀏覽器登入管理介面,找到 Guidance 按鈕
  • 設定 Internal、External、Management 三個網路介面
  • 說明為什麼要先把時間設對,以及時間不準會連鎖出哪些問題
  • 找到授權與憑證的操作位置,並完成設備憑證的申請流程
  • 說出管理介面應該限制從哪裡登入

本章承接第 3 章規劃好的三個網路介面;升級的細節放在第 16 章。

一、初始化的八個步驟

用新店開張來想

  • Console 像先把水電接通:只做到「店裡能亮燈、老闆進得去」的最小程度。
  • 進了店(瀏覽器開 /admin),再慢慢布置:設網路、對時鐘、申請營業登記(授權)。
  • 自簽憑證像手寫的臨時招牌,開幕前一定要換成受信任單位核發的正式招牌(受信任 CA 簽發的憑證)。

官方建議的順序是先設定系統與網路(一開始要靠 Console 初始化),第二步就是設定日期時間,接著升級 Service Package、安裝授權。官方建議的順序到安裝授權為止,換正式憑證是本教材加上的一步。完整的八個步驟如下圖:

名詞小卡

Console

用 console 線接到設備的文字管理畫面,只在初始化或救援時使用。日常管理都在瀏覽器的 /admin。

Guidance

管理介面右上角的導引按鈕。第一次登入會自動跳出,之後可以隨時重新開啟,它會帶你升級 Service Package 與安裝授權。

Service Package

設備的版本更新。官方建議在安裝授權之前先升到最新(第 16 章會講怎麼升)。

自簽憑證

設備自己簽給自己的憑證。瀏覽器不認得它,會出現警告,所以只能在初始化階段使用,上線前要換成受信任 CA 簽發的憑證。

二、動手做:實體設備的 Console 初始化

目標:讓設備有一個可以連得到的 Internal port 位址,以及一組管理員帳號。以下依 ISA6000 硬體指南整理,ISA6500 / 8500 的 Console 畫面是否完全相同,以實機為準。

External port 不在 Console 設定

Console 只問 Internal port。External port 之後到網頁管理介面設定(第五節)。和舊版設定手冊的 Console 流程相比,大方向一樣,新版多了選擇產品身分、REST API 權限、註冊 Ivanti Neurons for Secure Access 三項。

三、虛擬版與雲端的初始化

VMware

  1. 在 vCenter 對 inventory 按右鍵,選 Deploy OVF Template,選擇本機的 OVF 檔。
  2. 依序指定名稱、運算資源、儲存空間,並對應三個網路。
  3. 開機後點 Launch Web Console,設定網路與管理員帳密。

Launch Web Console 不是 ICS 的管理介面

這顆按鈕是 vSphere 提供的虛擬機主控台,相當於實體設備的 console 線。ICS 的網頁管理介面要用瀏覽器開 https://10.0.20.10/admin。

四、第一次登入管理介面

  1. 1瀏覽器開 https://10.0.20.10/admin,也就是 Internal port 位址後面加 /admin。
  2. 2這時用的是自簽憑證,瀏覽器會出現警告,確認後繼續。這是正常的,第八節會換成正式憑證。
  3. 3用剛才在 Console 建立的管理員帳號登入。
  4. 4第一次登入會跳出初始設定導引。之後想再看,按右上角的 Guidance 按鈕就能重新開啟,它會引導你升級 Service Package 與安裝授權。

六、為什麼時間要先設好:日期時間與 NTP

用火車票來想

車票上印著「幾點幾分的車次」。如果售票系統的時鐘亂跳,票上的時間就沒有意義,驗票的人也沒辦法判斷票是不是過期。ICS 的驗證碼、憑證、授權和日誌都靠時間判斷,時鐘不準,這些東西會一起出狀況。

官方建議的第二步就是設定時間(NTP 是讓設備自動向時間伺服器校時的機制)。時間不準會連鎖出問題:

  • ISA-V 與 License Server 的授權同步,官方建議兩者使用同一台 NTP。
  • 手機上的驗證 app 也要有準確的時間,雙方差距超過容許範圍,驗證碼就會被判定錯誤。

日期時間設定的選單位置以實機為準

新版的日期時間 / NTP 設定選單位置,本教材沒有取得官方頁面可以對照,所以這一章不示範設定畫面。上機時請在管理介面的 System 底下找對應的設定頁,或從 Guidance 的導引進入。

重點提醒

SAN 要涵蓋所有網址

22.8R2.1 起(全新安裝與升級),預設啟用 Host header 驗證。憑證的 SAN(Subject Alternative Name,憑證上列出「這張憑證適用哪些主機名稱」的欄位)要包含使用者會用到的每個主機名稱,否則連線會被拒絕。也就是說,設備會檢查瀏覽器網址上的主機名稱,是否列在憑證的 SAN 裡。第十節有小練習。

  • 多網域:為每個網域建立 Virtual Port,再在憑證的 Present certificate on these ports 勾選要在哪些介面出示這張憑證。也可以用一張萬用字元憑證(*.example.com)涵蓋全部。
  • 金鑰與演算法:官方明寫支援 3072-bit,使用 SHA-2,不支援 DSA。
  • 到期提醒:Certificates Validity Check 可設定提前 7–999 天通知(預設 60 天),通知會出現在管理介面橫幅、SNMP trap 與事件日誌。
  • 續約:官方建議產生新的 CSR(新的金鑰對)。直接用 Renew Certificate 也可以,但官方稱較不安全。

九、管理介面該從哪裡登入?

ICS 是直接面對 Internet 的設備,管理介面一旦外露,風險極高(第 17 章會專門談)。初始化完成前,先把存取範圍收緊:

  • 不要從 External port 登入管理介面:22.7R2.9 起不支援,升級作業也不要從 External port 進行。
  • 管理員能從哪裡登入,由 Administrators > Admin Realms > (realm) > Authentication Policy > Source IP 控制。範例環境只放行管理網段 10.0.30.0/24。
  • 預設有兩個管理角色:Administrators(全權)與 Read-Only Administrators(只能看),位於 Administrators > Admin Roles。需要分工時另建委派角色(第 6 章)。
  • 建議管理員也加上第二因素驗證(第 11 章)。

十一、常見踩坑與版本差異

閘道和 IP 不在同一個網段

輸入錯誤時,若管理介面連不上,要回 Console 重新設定;連得上就可以到 System > Network > Internal Port > Settings 修改(以實機為準)。填完先心算:IP 與遮罩算出網段,閘道必須落在同一個網段裡。範例環境 10.0.20.10/24 的閘道是 10.0.20.1,不是管理網段的 10.0.30.1。

等 CA 簽發時刪掉 Pending CSR

刪除 CSR 會連同本機私鑰一起刪掉。CA 簽好的憑證要和這把私鑰配成一對才能匯入,私鑰沒了就得重新申請。

正式環境用 DHCP

OVF 參數的 IP 欄位留空,會改用 DHCP 自動設定。但 ICS 假設租約長期有效、不會續租,正式環境請用固定 IP。

隨手更換產品身分

更換產品身分(personality)會清除所有設定。要回復出廠,在 Console 選 4(System Operations)→ 1(重新開機),重開後選 Factory Reset。

把授權碼貼進文件或截圖

舊版教材的截圖裡出現過授權碼、客戶名稱與公網 IP。做教材、回報問題或寄截圖給別人時,授權金鑰與 hardware ID 都先遮起來。

版本差異

  • 22.7R2.9 起不支援從 External port 登入管理介面。
  • 22.8R2.1 起(全新安裝與升級)預設啟用 Host header 驗證,憑證 SAN 要涵蓋所有網址。
  • 新版 Console 比舊版設定手冊多了選擇產品身分、REST API 權限、註冊 Ivanti Neurons for Secure Access 三項。
  • ISA6500 / 8500 的 Console 畫面、日期時間設定的選單位置,以實機為準。
