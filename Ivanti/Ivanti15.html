Ivanti Connect Secure SSL VPN 實戰課程

單元 15:日誌、監控與疑難排解

講師導言

VPN 出狀況時,你手上的線索只有三樣:日誌(發生了什麼事)、告警(系統會不會主動通知你)、診斷工具(怎麼追到根因)。 新手最常犯的錯是一上來就開最詳細的偵錯記錄、或是亂猜原因。這一章教你照固定順序查: 先看日誌、再用工具、最後把結果對回第 2 章的登入評估流程,判斷卡在哪一關。

Goals 本章學習目標

  • 說出五種日誌各記什麼、在哪裡看,以及目前在線的使用者去哪裡查
  • 把日誌送到 Syslog / SIEM,並記得三個分頁要各設一次
  • 說出 SNMP 能做什麼,以及哪些叢集告警一定會送
  • 依固定順序排查「使用者登入失敗」:日誌、Policy Tracing、鎖定狀態、Debug Log、用戶端日誌
  • 把排查結果對應回第 2 章登入評估流程的第幾項

本章的排查練習會用到第 2 章「登入評估流程」的第 5、6、9、10 項;用戶端日誌的收集方式見第 13 章。

一、日誌種類:先知道去哪裡看

用大樓管理來想

  • User Access 像門禁刷卡紀錄:誰什麼時候進來、去了哪些地方。
  • Admin Access 像維修登記簿:哪位管理員什麼時候改了什麼設定。
  • Events 像設備運轉日誌:系統自己發生了什麼事,例如授權、連線請求、系統錯誤。

日誌都在 System > Log/Monitoring:

分類內容
Events系統事件、連線請求、系統錯誤、授權事件等
User Access使用者登入登出、VPN Tunneling、SAML、網頁與檔案存取。檢視頁只顯示最近 5,000 筆
Admin Access管理員登入、設定變更、授權變更
Sensors與 IDP sensor 的通訊記錄
Client Logs使用者上傳的用戶端日誌(預設關閉)

嚴重度與容量

每筆日誌有嚴重度,數字越大越嚴重:

Critical(10) Major(8–9) Minor(5–7) Info(1–4)
  • 本機日誌預設上限 200 MB,寫滿後輪替(舊的被新的蓋掉)。要長期保存,就送到 Syslog / SIEM(第四節)。
  • 日誌設定畫面的排列依版本而不同,細節見第八節的版本差異,一律以實機為準。

「現在誰在線」不是看日誌

要看目前在線的使用者,到 System > Status > Active Users。可以篩選,也可以踢除單一或全部 Session。

三、日誌與告警往哪裡去

ICS 本機的日誌空間有限,資安與維運團隊通常需要集中收集。出口有兩個: Syslog 把日誌一筆一筆送給 Syslog 伺服器或 SIEM;SNMP 讓監控系統收到告警(trap)。

  • Syslog 的訊息格式遵循 RFC 5424。
  • 範例環境啟用了 Management port(10.0.30.10),所以 Syslog 與 SNMP 都會從 Management port 送出。防火牆要放行的是這個來源位址。

四、動手做:送到 Syslog 伺服器

目標:把 User Access 日誌送到集中的 Syslog 伺服器。Events、User Access、Admin Access 三個分頁要各設定一次,這裡先示範 User Access,另外兩個照做。

範例環境沒有定義 Syslog 伺服器,本節用 syslog.corp.example.com 當教學範例值。

示意畫面:欄位名稱依 Ivanti 官方文件,版面、按鈕位置與配色以實機為準。日誌設定畫面的分頁排列依版本不同,Fault tolerance 的呈現方式也以實機為準。
  1. 1Server name/IP 填 Syslog 伺服器的名稱或位址。用 TLS 時,這個名稱要和伺服器憑證的 CN 相符。
  2. 2Facility 從 LOCAL0 到 LOCAL7 擇一,讓收端能依這個值分類。
  3. 3Type 選 UDP、TCP 或 TLS。要加密就選 TLS;要在伺服器斷線時補送日誌,至少要用 TCP 或 TLS。
  4. 4Filter 決定格式:Standard 是預設值,另有 WELF 等格式,依收端系統選擇。
  5. 5Source Interface 選從哪個介面送出(Internal、External、Management 等)。啟用 Management port 時,Syslog 會從 Management port 送出。
  6. 6Fault tolerance(進階設定):Syslog 伺服器斷線時,暫存最多 4 小時的日誌,恢復後補送。只有 TCP / TLS 能用。
  7. 7按 Save Changes,再到 Events 與 Admin Access 分頁各設一次。叢集時,Fault tolerance 要在每台各自設定。

五、SNMP:讓監控系統收到告警

位置:System > Log/Monitoring > SNMP。

項目說明
版本支援 v2c 與 v3(v3 最多 2 個使用者)
MIB 檔從同一頁下載
叢集專用 trap介面中斷、節點停用、VIP 變更、節點被刪除。一律啟用、無法關閉(第 14 章的叢集故障,監控系統會收到這些)
暴力登入告警超過帳號鎖定門檻時,送出 iveTooManyFailedLoginAttempts

六、排查「使用者登入失敗」

排查要有順序,從最便宜、最不影響系統的做法開始:

步驟做法
1看 System > Log/Monitoring > User Access 的日誌,確認有記錄 Login/logout 類別
2對該使用者開 Policy Tracing:Maintenance > Troubleshooting > User Sessions > Policy Tracing。按 Start Recording、請使用者重試、Stop Recording,再存檔。設定來源 IP 可以抓到輸入帳號前的事件
3檢查是不是被鎖定(Local Authentication 的 Account Lockout、TOTP 的 Locked 狀態)
4開 Debug Log:Maintenance > Troubleshooting > Monitoring > Debug Log(預設 2 MB、最大 250 MB),重現問題後存檔並關閉
5請使用者從用戶端存日誌(第 13 章)

對照第 2 章的登入評估流程

症狀評估流程卡在
驗證失敗(密碼錯、第二驗證沒過)第 5 項
帳密正確,但沒有任何角色第 6 項
登入成功,但打不開資源第 9–10 項

七、動手玩:登入問題排查練習

選一個情境,每按一次「下一步」就揭露一個發現,看這類問題該先看哪個日誌、再用哪個工具,最後給出結論並對應到登入評估流程。練習中的日誌與追蹤結果是教學用的假設情境,訊息文字為示意。

操作

八、常見踩坑與版本差異

Syslog 只設了一個分頁

Events、User Access、Admin Access 要各設定一次。只設其中一個,另外兩類日誌在 SIEM 上就完全看不到。另外,叢集時 Fault tolerance 要在每台各自設定。

用 UDP 卻期待斷線補送

Fault tolerance 只限 TCP / TLS。用 UDP 送的話,Syslog 伺服器斷線期間的日誌不會替你暫存。TLS 還要注意 Server name 必須和伺服器憑證的 CN 相符。

Debug Log 開了不關

Debug Log 預設 2 MB、最大 250 MB。正確做法是重現問題、存檔、然後關閉。Remote Debugging 更要等原廠要求再開。

只靠本機日誌

本機日誌上限 200 MB、寫滿輪替,User Access 檢視頁也只顯示最近 5,000 筆。需要回頭查幾天前的事件,就要事先送到 Syslog / SIEM。

版本差異:日誌設定畫面的排列

  • 22.8R2.2 與 25.x 的官方文件寫成:System > Log/Monitoring 底下先有 Settings 分頁,Events、User Access、Admin Access 是其中的子頁。這和舊版畫面的排列不同。
  • 本章的示意畫面依教材的選單路徑繪製。你的設備日誌設定要從哪一層點進去,以實機為準。欄位名稱(Server name/IP、Facility、Type、Filter、Source Interface)則是通用的。
