Ivanti Connect Secure SSL VPN 實戰課程

單元 14:高可用性(叢集)

講師導言

一台 VPN 閘道出事,全公司就連不進來。這一章要把兩台 ICS 組成叢集,讓其中一台倒下時另一台接手。 叢集有兩種做法:Active/Passive(一主一備,共用一個 VIP)和 Active/Active(兩台同時服務,前面放負載平衡器)。 真正要搞懂的不是「會不會切換」,而是「切換的那一刻,使用者會不會斷線」。答案取決於模式、上游網路設備和同步設定,本章最後的模擬器會讓你親手試。

Goals 本章學習目標

  • 說出 Active/Passive 與 Active/Active 的差別:有沒有 VIP、要不要負載平衡器
  • 建立叢集並加入第二個節點,知道新節點原本的設定會被蓋掉
  • 看懂 System > Clustering > Properties 的四個區塊,知道哪一區不能亂改
  • 說明主機故障時 VIP 怎麼移到備機,以及上游設備為什麼必須接受 gratuitous ARP
  • 辨認舊版簡報裡「Heartbeat」與「節點 IP 等於 VIP」兩個錯誤觀念

本章接在第 3 章之後:叢集的狀態同步只走 Internal port,兩台之間要放行 17425(使用者記錄同步,埠號不可修改)。

一、叢集是什麼?兩種模式

用客服中心來想

  • Active/Passive 像一支客服專線配兩位值班客服:平常主機接電話,備機待命。主機倒下,備機接手同一個號碼,客戶不必換號碼重打。
  • Active/Active 像兩個服務櫃台,前面站一位引導員(負載平衡器):看哪個櫃台有空就請客人過去。其中一個櫃台關了,引導員把人帶去另一個。兩個櫃台各有自己的門牌,沒有共用的號碼。

叢集(Cluster)是把兩台同軟體版本、同硬體平台的設備綁成一組,讓設定與使用者 Session 可以互相同步。 VIP(Virtual IP)是兩台共用的虛擬位址,使用者連的是它,不是任何一台的真實位址。

兩種模式比較

Active/Passive(A/P)Active/Active(A/A)
架構兩台,一主一備,共用 VIP兩台,前面放外部負載平衡器
VIP有。內部 VIP 必設;啟用 External port 時另需外部 VIP沒有,每台用自己的 IP
外部設備不需要需要負載平衡器
增加容量不會提高尖峰吞吐量,但不增加授權使用者數
網路需求兩台在同一個 IP 網段建議雙臂架構(負載平衡器的使用者端與伺服器端各走一個介面)、不做 source NAT

兩種模式共同的條件

  • 兩台要有相同的軟體版本、相同的硬體平台。
  • 狀態同步只走 Internal port。
  • 要用 IPv6 的話,建叢集之前兩台都要先設好。
  • 節點數:官方建議單機或最多 2 台叢集。實體 ISA 與 ISA-V 都限 2 台,本章一律以 2 台為準。

本章使用的叢集範例位址

範例環境原本只定義了單機的 10.0.20.10(Internal)與 203.0.113.10(External),沒有定義節點位址。為了教學,本章自訂兩個節點的位址,並把原本那兩個位址改當 VIP,這樣對外網址 vpn.example.com 不用改。實際位址依你的環境規劃。

名詞小卡

VIP

A/P 兩台共用的虛擬位址。誰是主機,VIP 就在誰身上。使用者與外部設備認的是 VIP,不是節點自己的位址。

gratuitous ARP

備機接手 VIP 後,主動對網路廣播「這個位址現在由我負責」,讓路由器、防火牆更新它們的對照表。

Network Healthcheck

叢集用來偵測網路介面是否正常的機制,靠 ARP ping 判斷。Properties 頁有對應的設定。

負載平衡器

A/A 才需要的外部設備,負責把使用者流量分給各節點,並偵測哪一台故障了就改導到另一台。

新增成員:先在既有成員登記,再到新節點加入

  1. 在既有成員上(ics-node1):System > Clustering > Cluster Status > Add Members,填新節點名稱 ics-node2 與它的 Internal IP 10.0.20.12,按 Add,最後 Save Changes。
  2. 在新節點上(ics-node2):先設好 System > Network > Management Port。
  3. 在新節點上:System > Clustering > Join,填叢集名稱、叢集密碼,以及任何一台現有成員的 IP(這裡是 10.0.20.11),按 Join Cluster,再按 Join。
  4. 回到 System > Clustering > Cluster Status 確認狀態。同步過程中短暫出現 Transitioning 屬於正常。

加入叢集前,新節點不要先設定任何東西

新節點加入叢集時,它原本的設定會被叢集的設定蓋掉。官方的提醒是:加入前不要在新節點上做設定。需要保留的內容,請在加入前先備份(第 16 章)。

五、容錯切換:故障時發生什麼事

Active/Passive

  • 主機故障時,備機接手 VIP 並送出 gratuitous ARP。
  • 上游路由器或防火牆必須接受 gratuitous ARP,部署前要先測。
  • 偵測靠 Network Healthcheck 的 ARP ping,以及網路介面的 ARP Ping Timeout。
  • 管理員可以在 Cluster Status 頁手動切換 VIP。

Active/Active

  • 由負載平衡器偵測節點故障,並改導流量。
  • 負載平衡器要能偵測成員故障。
  • 建議依來源 / 目的 IP 分流,不要依目的埠。
  • 建議雙臂架構、不做 source NAT。

切換的那一刻,使用者會看到什麼?

依官方疑難排解頁(經摘要):進行中的 SSH、大檔案傳輸可能要重新開始,一般網頁請求可以無縫延續。這個說法尚未在實機驗證,實際情況以實機為準。是否保留使用者 Session,則取決於 Properties 的同步方式(第三節)。

七、常見踩坑與版本差異

以為有 Heartbeat 設定可以調

舊版簡報有「Heartbeat」的觀念,新版介面沒有叫 Heartbeat 的設定。偵測機制是 Network Healthcheck 的 ARP ping,以及網路介面的 ARP Ping Timeout。在 A/P 叢集裡,ARP Ping Timeout 同時也是 VIP 切換的計時器,不要隨意調整。

節點的 Internal IP 和 VIP 用同一個位址

舊版簡報的叢集圖把主機、備機的 Internal IP 都標成和 VIP 一樣的位址,這是圖片沿用的錯誤。正確做法是:兩台各有自己的 Internal IP,再共用一個 VIP,就像本章的 10.0.20.11、10.0.20.12 與 10.0.20.10。

上游設備不接受 gratuitous ARP

備機明明接手了 VIP,使用者卻還是連不進來,多半是上游路由器或防火牆沒有更新位址對照表。這一點在正式上線前一定要實際關掉主機測一次,模擬器的紅色結果就是這個情境。

有使用者在線時開 Configuration only cluster

這個選項只同步設定,沒有 Session 容錯。開了之後主機一故障,所有在線使用者都要重新登入。

舊版簡報也有畫對的地方

舊版簡報的 A/A 圖沒有標 VIP,這是對的:A/A 本來就沒有 VIP,每台用自己的 IP。

版本差異與文件矛盾

  • A/A 的官方頁面另有「最多 8 台」的說法,和「最多 2 台」互相矛盾。本教材以 2 台為準。
  • 上一節的虛擬版與雲端支援表,依據 22.x 的虛擬版部署指南,25.x 是否有變動以實機為準。
  • 切換時 SSH、大檔案傳輸會怎麼樣,出自官方疑難排解頁的摘要,尚未在實機驗證。
