單元 7:使用者領域(User Realm)與角色對應(Role Mapping)

講師導言

上一章我們建好了角色,可是系統怎麼知道「王小明登入後該拿到哪個角色」?答案就是這一章的兩個主角: User Realm 決定「用哪台伺服器驗證這群人」,Role Mapping 決定「驗證通過後發給他哪些角色」。 很多「明明登入成功,卻什麼都打不開」的問題,都出在這一章的設定。

Goals 本章學習目標

  • 說出 User Realm 與 User Role 各自負責什麼
  • 建立一個用 AD 驗證、加上 TOTP 第二因素的 Realm
  • 用群組建立 Role Mapping 規則,並說明規則順序與 Stop 的作用
  • 分辨 Realm 的 Authentication Policy 與角色的 Restrictions,沒通過時結果有什麼不同
  • 選擇使用者拿到多個角色時的處理方式

本章對應第 2 章「登入評估流程」的第 5 到第 8 項。

一、Realm 與 Role:一群人、一組權限

用公司大樓來想

  • Realm 像大樓的入口:員工走員工通道刷識別證,訪客走訪客櫃台登記。不同的人,用不同的方式驗明身分。
  • Role 像門禁卡的權限等級:一般卡只能進辦公區,資訊部的卡還能進機房。
  • Role Mapping 像櫃台人員:看你是哪個部門,決定發你哪張卡。

一句話記住:Realm 是「一群使用者」,Role 是「一組權限」。 使用者先進入某個 Realm、通過驗證,再由 Realm 裡的 Role Mapping 規則決定他拿到哪些 Role。

名詞小卡

User Realm

一群使用者的登入設定:用哪台伺服器驗證、去哪裡查群組、要不要第二因素、怎麼對應角色。選單在 Users > User Realms。

User Role

一組權限:啟用哪些存取功能、Session 多久、有什麼限制。第 6 章已建好。

Role Mapping

Realm 裡的一份規則清單,依帳號、群組、屬性或憑證,決定發哪些角色。

Stop processing

規則上的勾選框。勾了之後,這條規則一旦命中,後面的規則就不再比對。

三、兩道關卡:Authentication Policy 與 Restrictions

「只准公司電腦登入」「只准從公司固定的對外 IP 連線」這類條件,可以設在兩個地方。兩者看起來很像,沒通過時的結果卻完全不同。

Authentication PolicyRestrictions
設在哪裡Realm 的 Authentication Policy 分頁角色的 General > Restrictions
可檢查的項目Source IP、Browser、Certificate、Password、Limits、Host CheckerSource IP、Browser、Certificate、Host Checker
沒通過的結果進不了這個 Realm,登入失敗拿不到這個角色,但可能拿到其他角色
適合用在整群人都必須符合的條件,例如管理員只能從管理網段登入依裝置狀態給不同權限,例如公司電腦才有完整 VPN

六、使用者拿到多個角色時

選項行為適合
Merge settings for all assigned roles把所有角色合併成一個(permissive merge)大多數情境,使用者不必多做選擇
User must select from among assigned roles登入時讓使用者自己挑一個角色同一人有截然不同的身分,例如平常是一般員工、值班時是資訊人員
User must select the sets of merged roles assigned by each rule讓使用者挑「某一條規則發的那組角色」一條規則會發多個角色,又要讓使用者切換時

permissive merge 的三條規則

  • 任何一個角色啟用的功能就會生效(功能取聯集)。
  • Session 逾時取最大值。
  • UI 選項採用第一個角色的設定。

VPN 的路由優先權不建議靠合併決定。同一位使用者可能拿到的角色,VPN 選項最好設成一致(第 9 章)。

七、常見踩坑

萬用規則放第一條又勾 Stop

舊版設定手冊的範例:第一條規則是 username is * 並勾了 Stop,結果第二條規則永遠比對不到,每個人都只拿到第一條的角色。萬用規則要放在最後,或者不要勾 Stop。

拿 AD 內建群組發 VPN 角色

舊版安裝教材把 AD 內建的 Users 與 Administrators 群組都對應到有 VPN 的角色,等於全公司都能連 VPN。請建立專用群組(例如 VPN-Users),只把需要的人加進去。

Directory/Attribute 沒設

用群組寫規則,但 Realm 的 Directory/Attribute 留空,系統查不到群組,這類群組規則就不會命中;如果也沒有其他規則命中,使用者拿不到角色,登入會失敗。

版本差異

  • Realm、Role、Role Mapping 的選單位置,從 9.1R17、22.x 到 25.1 都沒有變。舊教材的觀念可以直接沿用。
  • 25.1.3.0 起,用 Entra ID 這類 OAuth 登入時,可以在 Custom Expressions 比對 token 裡的群組,例如 groups = ('123' OR '456')。Entra 回傳群組 GUID 時,只能比對 GUID。
