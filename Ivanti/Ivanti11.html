Ivanti Connect Secure SSL VPN 實戰課程

單元 11:多因素驗證

講師導言

帳號密碼只要外洩一次,別人就能冒用你的身分連進公司。多因素驗證(MFA)的想法很簡單:除了「你知道的東西」(密碼),再加上「你擁有的東西」(手機)。 Ivanti Connect Secure 內建 TOTP,不必另外買伺服器;公司如果已經有 Entra ID 或 Okta,也可以把驗證交給它們。 這一章先認識幾種做法,再一步步建好內建的 TOTP,最後用模擬器親眼看看「手機時間不準」會發生什麼事。

Goals 本章學習目標

  • 說出使用者第一次登入時,TOTP 註冊的 5 個步驟
  • 建立 TOTP Server,並說明 Time Skew、Number of attempts allowed 的作用
  • 說明「外部註冊」為什麼是資安上的取捨,並選出比較安全的做法
  • 在 TOTP Server 的 Users 分頁分辨 Active / Locked / Unregistered,並知道 Unlock 與 Reset 該用哪一個
  • 分辨內建 TOTP、RADIUS、RSA、SAML 各自適合什麼情境

本章對應第 2 章「登入評估流程」第 5 項的「有第二驗證伺服器時再驗一次」。

一、密碼之外,再加一道鎖

用大門鑰匙來想

  • 密碼像大門鑰匙:被複製了,別人就能開門。
  • TOTP 驗證碼像門口多裝的一個密碼鎖,號碼每 30 秒換一次,而且只顯示在你的手機上。就算有人拿到鑰匙,沒有手機也進不來。
  • 備援碼像備用鑰匙:救急用,而且每一把只能用一次。

TOTP(Time based One-Time Password)是「以時間為基礎的一次性密碼」:手機上的驗證 App 每 30 秒產生一組 6 位數驗證碼,登入時除了帳號密碼,還要再輸入這一組。 使用者用的 App 跟以前一樣,例如 Google Authenticator、Microsoft Authenticator。舊版簡報裡的「Google Authenticator 驗證伺服器」,在新版叫做 TOTP Server。

使用者第一次登入的流程

使用者第一次登入時,要先把手機和 TOTP Server「配對」。配對只做一次,之後每次登入只要輸入驗證碼。

名詞小卡

TOTP Server

ICS 上的一種驗證伺服器。位置在 Authentication > Auth. Servers,下拉選 Time based One-Time Password (TOTP) Server 再按 New Server。

Time Skew

允許的時間誤差,範圍 1 到 5 分鐘。手機和伺服器的時鐘差距在這個範圍內,驗證碼才會被接受。

備援碼

註冊時一次給 10 組,每組只能用一次。管理員可以選擇不要產生(Disable generation of backup codes),預設會產生。

第二因素

在 Realm 裡用 Additional authentication server 掛上去的第二台驗證伺服器。第一台驗帳密,第二台驗驗證碼。

二、其他做法:RADIUS、RSA 與 SAML

內建 TOTP 是最快上線的選擇。如果公司已經有別的 OTP 系統或單一登入平台,不一定要另起爐灶。先看看有哪些做法,本章後半的實作都以內建 TOTP 為主。

做法適合的情境重點
內建 TOTP沒有現成的 OTP 系統,想直接上線Server Type 選 Local,使用者用 Authenticator 類的 App
RADIUS串接第三方 OTP 伺服器用 Radius Rules 處理 Access Challenge(例如 Next Token、New PIN)
RSA ACE公司已經有 RSA 的 OTP 系統匯入 sdconf.rec
SAML公司已用 Entra ID 或 Okta 做單一登入與 MFAICS 當 SAML 服務提供者(SP),把驗證交給外部身分提供者(IdP)

RSA ACE 在 25.x 的限制

  • 只允許 TCP。
  • ICS 的 Hostname(System > Network > Overview)必須和 RSA 端登記的 Agent Hostname 相同。

SAML:把驗證交給外部 IdP

SAML 是一種「身分驗證委託」的標準:ICS 自己不驗帳密,而是請外部的 IdP(身分提供者,例如 Entra ID)驗證,ICS 這一方叫 SP(服務提供者)。 設定的重點只有一件事:兩邊要互相交換對方需要的資料。

ICS 端的設定步驟

  1. 1System > Configuration > SAML > Settings:設定 Host FQDN for SAML,填 vpn.example.com。
  2. 2System > Configuration > SAML > New Metadata Provider:匯入 IdP 提供的 metadata。
  3. 3Authentication > Auth. Servers > SAML Server > New Server:SAML Version 選 2.0;Configuration Mode 選 Metadata(用剛匯入的 metadata)或 Manual。其他欄位有 Identity Provider Entity ID、Identity Provider Single Sign On Service URL、User Name Template、Allowed Clock Skew、SSO Method(POST 或 Artifact)、Authentication Context Classes。
  4. 4建立一個用這台 SAML Server 驗證的 Realm,再建立對應的 Sign-in Policy。一個 Sign-in Policy 只能對應這一個 Realm。

Entra ID 端要填的值

依 Ivanti 官方整合指南,Entra ID 的應用程式要填下面兩個值:

欄位值
Entity IDhttps://vpn.example.com/dana-na/auth/saml-endpoint.cgi?p=sp1
sp1 依 ICS 上的 SP 序號而變
Reply URLhttps://vpn.example.com/dana-na/auth/saml-consumer.cgi

Entra 的應用名稱與 Okta 的步驟,以實機為準

官方指南用的是 Entra 應用程式庫(Gallery)裡的「Pulse Secure ics」應用,而且沒有寫 Conditional Access 的設定步驟。目前 Entra 介面上這個應用叫什麼名字,請在實機確認。Okta 當 IdP 的官方專屬步驟查不到,請依上面的通用 SAML 流程設定。

Server Type 選 Remote 時,REST Authentication Realm 一定要填

Server Type 也可以選 Remote:這台 ICS 當代理,用 REST API 轉給另一台 ICS 上的 TOTP Server。此時 REST Authentication Realm 是必填,留空的話,升級之後使用者會登入失敗。

掛到 Realm 當第二因素

這個畫面在第 7 章已經示範過,這裡只列步驟。路徑:Users > User Realms > (realm) > General。

  1. 1勾選 Additional authentication server。
  2. 2Authentication #2 選 TOTP-Local。
  3. 3帳號欄維持預設 <username>,也就是沿用第一因素輸入的帳號。
  4. 4勾選 End session if authentication against this server fails:第二因素失敗就結束 Session,不放行。
  5. 5按 Save Changes。

資安重點:外部註冊的取捨

預設只允許使用者從內部網路註冊 TOTP。如果使用者第一次登入就是從 Internet 進來,必須開啟 Allow new TOTP user registration to happen via external port。

代價是:只要拿到帳號密碼的人,就可以搶先把自己的手機綁上去。員工本人反而被擋在外面,攻擊者卻成了「合法的第二因素持有者」。

做法取捨
維持關閉(預設)較安全。請使用者第一次在公司內完成註冊。
需要開啟時開放期間縮短時程,並監看日誌,確認註冊的都是預期的人。

TOTP 的三個限制

  • 第一次註冊必須透過網頁,桌面用戶端不能註冊新使用者。
  • 同一個叢集內會自動同步;跨叢集要手動匯出匯入。
  • TOTP 使用者不能透過 XML 匯入,要用 REST API 或管理介面。

七、常見踩坑與版本差異

驗證碼老是錯:先查時間

TOTP 靠時間算驗證碼。手機沒開自動校時、或 ICS 的 NTP 沒設好,時間差一大就會一直被拒絕,還可能因為錯太多次被鎖住。建議 Time Skew 維持 1 分鐘,並把 NTP 設好,而不是一律調成 5 分鐘了事。

手機遺失只做了 Unlock

Unlock 只是解除鎖定,使用者的手機還是舊的那台。手機遺失、換手機要用 Reset,讓使用者下次登入重新註冊。

外部註冊開著沒人管

為了讓遠端新人也能註冊而開啟外部註冊,結果一直忘了關。拿到帳密的人隨時可以搶先綁定自己的手機。開放期間要縮短,並看日誌。

SAML 登入失敗:時鐘與憑證鏈

兩邊時鐘不同步會出現「No valid assertion found」,請確認雙方都有 NTP。另外 25.x 的 SAML 2.0 簽章驗證預設啟用,要把 IdP 的完整 CA 鏈匯入 Trusted Client CAs,否則登入可能失敗。

版本差異(25.x)

  • SAML 1.1 已棄用:25.1.1.0 起,不能新增或匯入 SAML 1.1 伺服器。
  • SAML 2.0 簽章驗證預設啟用。
  • OAuth 群組宣告對應角色(25.1.3.0):Role Mapping 用 Custom Expressions 比對 token 裡的群組,例如 groups = ('123' OR '456')。Entra 回傳群組 GUID 而不是名稱時,只能比對 GUID,而且這種規則不能用 Group membership 類型。
  • 自訂登入頁:25.1.3.0 暫時移除了「上傳自訂登入頁」。舊環境如果依賴自訂登入頁(包含含有 TOTP 範本的自訂頁),升級前要先規劃。
  • TOTP Server 的名稱:舊版簡報叫「Google Authenticator」伺服器,新版叫 Time based One-Time Password (TOTP) Server。使用者端的 App 一樣是 Google Authenticator、Microsoft Authenticator 這類。
