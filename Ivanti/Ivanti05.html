單元 5:認證伺服器(Auth Server)

講師導言

設備架好了,但還沒有人能登入。登入的第一道關,就是問一句「這組帳號密碼對不對?」,負責回答的就是 Auth Server(認證伺服器)。 這一章先認識所有類型,再實際設定兩個最常用的:給外包人員用的本機帳號,以及給員工用的 AD(Active Directory)。 連 AD 這一段特別要小心:舊版安裝教材的範例有兩個今天不能再照做的地方,我們會一一改正。

Goals 本章學習目標

  • 說出 Auth Server 負責回答什麼問題,以及各類型的典型用途
  • 建立 Local Authentication,設定密碼規則與帳號鎖定
  • 區分連接 AD 的兩種做法:加入網域,或是當 LDAP 目錄查
  • 照新版建議值設定 LDAP 伺服器(636、LDAPS、唯讀服務帳號、備援)
  • 說明用 LDAPS 前為什麼要先匯入 CA
  • 認得 RADIUS 與 Certificate 伺服器的重點欄位

本章對應第 2 章「登入評估流程」的第 5 項:帳密送到 Realm 指定的 Auth Server 驗證。

一、Auth Server 是什麼?類型一覽

用大樓的查證櫃台來想

  • 本機帳號像櫃台自己手上的訪客名冊:名冊上有就放行,適合外包與測試人員。
  • LDAP / AD像櫃台打電話問人事部:員工資料都在人事部那邊,櫃台只負責問。
  • RADIUS、TOTP像再多一道手續:RADIUS 常用來串接 OTP 伺服器;TOTP 則是再多一道一次性驗證碼。

Auth Server 的工作是驗證帳號密碼,有些類型還能查使用者所屬的群組。選單位置:Authentication > Auth. Servers。

分類類型典型用途
本機Local Authentication外包、測試帳號,帳號存在 ICS 本機
本機Certificate用戶端憑證登入
本機SAML串接 Entra ID、Okta 等外部 IdP(第 11 章)
外部(標準)LDAP查 AD 或其他 LDAP 目錄
外部(標準)RADIUS串接 OTP 伺服器、NPS
外部(其他)Active Directory / Windows NT加入網域,用 Kerberos / NTLM 驗證
外部(其他)RSA ACE(RSA Authentication Manager)RSA SecurID
外部(其他)MDMIvanti(原 MobileIron)、Microsoft Intune、Workspace ONE
多因素Time based One-Time Password(TOTP)Server驗證 app 產生的 6 位數動態碼(第 11 章)

表中縮寫的白話說明:OTP(一次性密碼)、CA(憑證授權單位,簽發憑證的機構)、IdP(身分提供者,例如 Entra ID)。

已經不在清單上的類型

舊版設定手冊列出的支援清單裡有 Anonymous、NIS、SiteMinder 三項,新版已經不在清單上,看到舊教材提到時不必再找。

三、連接 Active Directory:兩種做法

公司的員工帳號通常放在 AD 裡。ICS 要驗證 AD 帳號,有兩種做法,選哪一種取決於你要不要加入網域。

做法伺服器類型適合
A. 加入網域Active Directory / Windows NT要用 Kerberos、NTLM,或需要網域信任查詢時
B. 當 LDAP 目錄查LDAP(Server Type 選 Active Directory)單純驗證帳密加查群組,設定最直觀。舊版安裝教材的範例就是這種

名詞小卡

LDAP

查詢目錄服務(例如 AD)的通訊協定。ICS 靠它確認帳密、查使用者所屬的群組。

LDAPS 與 Start TLS

替 LDAP 加密的兩種方式。LDAPS 用 636 埠;Start TLS 走 389 埠再升級成加密。沒加密的 LDAP 是明文。

服務帳號(Service Account)

專門給系統查目錄用的帳號,不屬於任何一位真人。範例環境是唯讀的 svc-ics-ldap。

Trusted Server CAs

ICS 往外連線時信任的 CA 清單。連 LDAPS 時,簽發網域控制站憑證的 CA 要先放進來。

做法 A 的重點欄位

  • Domain、Kerberos Realm、Domain Join Configuration(加入網域用的帳密)
  • Container Name、Computer Name
  • Authentication Protocol(Kerberos、NTLM)、Trusted domain lookup
  • AD 驗證伺服器的 Legacy Mode 已不支援,升級前要改成 Standard Mode。
  • 網域控制站是 Windows Server 2025 以上時,要用 ICS 25.x(22.7 / 22.8 不相容)。

用 LDAPS 之前,先匯入 CA

用 LDAPS 前,要先把簽發網域控制站憑證的 CA 匯入 Trusted Server CAs(第 4 章)。【25.x】25.1.3.0 起,新建的 LDAP 伺服器預設啟用 Validate Server Certificate,沒匯入 CA 就會連不上。

五、另外兩種常見類型:RADIUS 與 Certificate

RADIUS

常用來串接第三方 OTP 或 Windows NPS。要做帳務記錄時,在 Realm 的 Accounting 欄位指定 RADIUS 伺服器(第 7 章)。

欄位說明
NAS-IdentifierICS 在 RADIUS 伺服器上的名稱
Primary / Backup ServerRADIUS Server、Authentication Port(預設 1812)、Shared Secret、Accounting Port
Timeout、Retries逾時與重試次數
Radius Rules處理 Access Challenge:Next Token、New PIN、Generic Login

Certificate

使用者出示用戶端憑證登入。重點欄位是 User Name Template,也就是從憑證的哪個欄位取出帳號。簽發用戶端憑證的 CA 要先匯入 Trusted Client CAs(第 4 章)。

七、常見踩坑與版本差異

照抄舊範例:明文 LDAP 加網域管理員

舊版安裝教材用 389 埠、Unencrypted,又拿網域管理員帳號當查詢帳號。帳號密碼與查詢內容在網路上是明文,而且管理員密碼一旦外洩,整個網域都危險。請改用 636 + LDAPS 與唯讀服務帳號。

AD 帳號登入失敗,但本機帳號正常

先查 LDAPS 的憑證:簽發網域控制站憑證的 CA 有沒有匯入 Trusted Server CAs。本機帳號不經過 LDAP,所以不受影響,這正好能幫你縮小問題範圍。

LDAP Server 填 IP

憑證上寫的是網域控制站的名稱。用 IP 連線,名稱對不上;請填主機名稱,例如 dc01.corp.example.com。

只有一台網域控制站可以查

沒有填 Backup LDAP Server 時,那台網域控制站一維修或當機,所有 AD 帳號都登入不了。第二台的位址填進 Backup LDAP Server 即可。

版本差異

  • 25.1.3.0 起,新建的 LDAP 伺服器預設啟用 Validate Server Certificate;沒匯入 CA 就會連不上。
  • 25.1.3.0 新增 Certificate 伺服器的憑證挑戰逾時設定,範圍 1–4 分鐘,預設 1 分鐘。
  • AD 驗證伺服器(做法 A)的 Legacy Mode 已不支援,升級前要改成 Standard Mode。
  • 網域控制站是 Windows Server 2025 以上時,要用 ICS 25.x(22.7 / 22.8 不相容)。
  • Local Authentication 的預設值(錯 3 次鎖定 10 分鐘、密碼 64 天到期)來自 22.6R2 文件。
