單元 9:VPN Tunneling(原 Network Connect)

講師導言

VPN Tunneling 就是大家口中的「連上 VPN」:在使用者的電腦和公司之間,建立一條加密的隧道。這一章有兩件事最常出問題。 第一,只建了連線設定、忘了 Access Control,結果使用者「連得上 VPN,卻什麼都打不開」。 第二,分流沒搞懂,結果使用者抱怨「連上 VPN 後,家裡的印表機為什麼印不了?」。 這是 VPN 最常被問到的問題,所以後面會用一個模擬器,把 6 種設定組合全部玩一遍。

Goals 本章學習目標

  • 說出 VPN Tunneling 的設定位置與順序
  • 建立 Connection Profile,並看懂 ESP / SSL、UDP 4500 等主要欄位
  • 寫出最小權限的 Access Control 規則,並說明「連著 VPN 不能上網」是怎麼來的
  • 分辨 Direct、Indirect、Default 三種流量,並預測每種設定組合下它們走隧道還是走本地
  • 說明為什麼官方建議全部走隧道,以及範例環境選了哪個組合

本章是第 2 章「存取管理模型」裡 Role 與 Resource Policy 的 VPN 版本。

一、VPN Tunneling 的設定地圖

用公司專用的地下通道來想

  • Connection Profile 像通道的規格:發給你哪一個內部位址(IP)、通道用什麼方式傳、用哪台 DNS。
  • Access Control 像通道出口的警衛:只放行名單上的目的地,名單外一律攔下。
  • 分流與路由優先權 像你出門時選路:哪些目的地走地下通道,哪些走地面的馬路(你家的網路)。

VPN Tunneling(現行名稱)就是舊版教材所說的 Network Connect。它要設定的地方比較分散,先看地圖,免得漏掉:

步驟選單位置做什麼
1 角色啟用Users > User Roles > (角色) > General > Overview勾選 VPN Tunneling
2 建立 Resource PolicyUsers > Resource Policies > VPN Tunneling三個分頁:Access Control(能連哪些網段)、Connection Profiles(配發 IP、傳輸方式、DNS)、Split-tunneling Networks(哪些網段走隧道,分流時才需要)
3 角色層級選項Users > User Roles > (角色) > VPN Tunneling分流、路由優先權、自動啟動。要啟用分流,必須先建立至少一條 Split-tunneling Networks 政策
4 伺服器端 IPSystem > Network > VPN Tunneling設定伺服器端的 IP
5 用戶端日誌(選配)System > Log/Monitoring > Client Logs > Settings需要追查用戶端問題時再開

三個分頁缺一不可(分流除外)

舊版教材的範例只建了 Connection Profile,沒有建 Access Control。照著做,使用者連得上 VPN,卻打不開任何內部服務。所以 Connection Profile + Access Control 一定要一起建;Split-tunneling Networks 只有要分流時才需要。

官方頁面對這幾個選單的名稱略有差異(Split Tunneling / Split-tunneling Networks / Split Tunneling Networks),以實機畫面為準。

三、動手做:Access Control,只放行該放行的

Connection Profile 只負責「把你接進來」,Access Control 才決定「接進來之後能連哪裡」。 規則由上而下比對,命中即停止。官方的最佳實務是最小權限:只放行必要的 IP、埠與協定,盡量寫明確的 IP 而不是整個網段,並且依角色分開套用。

  3. 3規則 3:Role-IT-Full 放行整個伺服器網段 10.0.10.0/24 的所有埠。
  4. 4規則 4:*:* 對全部角色 Deny access,把名單以外的目的地一律擋掉。Action 另有 Use Detailed Rules 可以寫更細的規則。
  5. 5用上下箭頭調整順序。Deny 這種「兜底」規則一定要放最後。

設計提醒:全部走隧道 + 最後一條 Deny = 連著 VPN 不能上網

本章的範例是「全部流量走隧道」(第五節說明原因),再加上第 4 條 *:* Deny。兩者相加,代表使用者連著 VPN 時不能上網。這是最嚴格的做法,本教材範例採用它。

若要讓使用者連著 VPN 也能上網,要把最後一條改成「只拒絕其他內部網段,再放行對外流量」,並確認公司內部有通往 Internet 的出口與過濾機制(Proxy 或防火牆)。實際的規則寫法,以實機為準。

用 FQDN 寫規則時,要先在 System > Configuration > VPN Tunneling 啟用 FQDN ACL(這個位置以實機為準)。

四、分流與路由優先權:為什麼印表機印不了?

這是 VPN 最常被問到的問題:「連上 VPN 後,家裡的印表機為什麼印不了?」要回答它,先認識使用者家裡網路上的三種流量。

流量定義例子
Direct直接相連的子網,不經過路由器家用網段 192.168.1.0/24 上的印表機 192.168.1.101
Indirect路由表上有明確路由、要經過另一台路由器的子網經家裡第二台路由器 192.168.1.2 才到的 192.168.50.0/24
Default其他所有目的地(0.0.0.0/0)Internet

兩個設定(都在角色的 VPN Tunneling 選項)

  • Split Tunneling:Enable 時只有 Split-tunneling Networks 列出的網段走隧道;Disable 時全部流量都走隧道。
  • Route Precedence(路由優先權),有三個選項:
    • Tunnel routes have precedence:隧道路由優先
    • Tunnel routes with local subnet access:隧道路由優先,但保留本地子網(只支援 Windows、macOS)
    • Endpoint routes have precedence:端點自己的路由優先

舊版教材有幾處要更正

  • 舊版簡報只用了 Endpoint Route 與 Tunnel Routes 兩個名稱,沒有介紹第三個選項 Tunnel routes with local subnet access。
  • 「全部走隧道就連不到印表機」只在選 Tunnel routes have precedence 時成立。Split Tunneling 為 Disable 時,選另外兩個選項,Direct 都能保留在本地。
  • 舊版設定手冊對「啟用分流」的說明寫反了。官方定義是:啟用分流後,只有列出的網段走 VPN,其餘走本地。
  • 家裡和公司剛好用同一個網段時(舊版簡報的範例就是這樣),不論怎麼設,都會失去其中一邊的連線。

五、全部走隧道,還是分流?

用公司接駁車來想

  • 全部走隧道:所有行程都搭公司接駁車。公司看得到你去哪裡,可以檢查,但你想去的私人地點也得經過公司。
  • 分流:只有去公司的路段搭接駁車,其他自己走。比較順,可是公司看不到你另外去了哪,而你的電腦一旦被入侵,攻擊者也能順著這條路進公司。

Ivanti 官方 Security Best Practices Guide 的立場很明確:

  • 分流可能成為「後門」:遠端電腦一旦被入侵,攻擊者可以拿它當跳板進入公司內網。
  • 建議所有遠端存取使用者都不分流(全部走隧道),讓流量能被檢查。
  • 真的要分流時:搭配 Route Precedence 與 Traffic Enforcement、用 Access Control 嚴格限縮、把 VPN 日誌送到 SIEM、定期稽核。

另有一種常見的效能例外做法,是把 Microsoft 365 依 IP 排除在隧道之外。這個說法目前只有第二手資料,正式採用前請先查官方文件。

範例環境的選擇

Role-Staff 與 Role-IT-Full 都設 Split Tunneling = Disable、Route Precedence = Tunnel routes with local subnet access。全部流量進隧道,但保留家用印表機。

七、常見踩坑與版本差異

連得上 VPN,卻打不開任何內部服務

只建了 Connection Profile、沒建 Access Control(舊版教材的範例就是這樣)。補上 Access Control 的允許規則即可。

不要賭「沒有規則命中」時的預設行為

新版官方頁面沒有寫沒有任何規則命中時會怎樣,舊版手冊寫的是「預設全部允許」。教學上一律明確寫出允許清單,最後加一條拒絕,實際行為以實機為準。

UDP port 填 500、Encryption 選 MD5

UDP port 預設 4500,500 保留給 IKEv2,不要用。Encryption 不要選 MD5 的組合,範例用 AES256/SHA1。

要分流卻沒先建 Split-tunneling Networks

要啟用分流,必須先建立至少一條 Split-tunneling Networks 政策。若本來就打算全部走隧道,這一步可以略過。

同一個人拿到的多個角色,VPN 選項不一致

第 7 章說過,多個角色合併時,VPN 的路由優先權不建議靠合併來決定。同一位使用者可能拿到的角色,VPN 選項最好設成一致。

版本差異

  • 【25.x】25.1.3.0 起,DNS 改為 Split DNS Settings,有四個選項:Tunnel All DNS queries、Split DNS、IP based split tunneling rules only、FQDN based split tunneling rules only。Split DNS 只支援 Windows,macOS 與 Linux 一律 Tunnel All。
  • 22.x 文件註明 AES256/SHA256 只限已停產的 PSA 硬體,所以在 ISA 上建議選 AES256/SHA1。25.x 的加密選項清單以實機為準。
  • Split Tunneling / Split-tunneling Networks 等選單名稱,在不同官方頁面略有差異,以實機畫面為準。
