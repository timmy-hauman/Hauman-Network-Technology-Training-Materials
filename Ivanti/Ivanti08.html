單元 8:資源存取(Resource Profile 與 Resource Policy)

講師導言

使用者登入成功、也拿到角色了,可是系統還有最後一道關卡:這個角色,到底能不能連到這個資源? 這一章要設定的就是「能連哪些網站、哪些檔案、哪些伺服器」。你會看到兩個入口:Resource Profile 一次做完、適合日常設定; Resource Policy 是一份規則清單,適合做細部調整。最容易踩的雷只有一個:規則由上而下比對,第一條符合的就生效。

Goals 本章學習目標

  • 說出 Resource Profile 與 Resource Policy 的差別,以及 autopolicy 是怎麼來的
  • 建立一個 Web 資源(ERP),並指派角色、設定書籤
  • 說明為什麼「第一條符合的規則生效」,以及全新安裝時預設是 Deny
  • 為內部 Linux 伺服器建立 HTML5 Access(SSH)資源,並說明為什麼不再用 Telnet
  • 分辨 Secure Application Manager(SAM)和 VPN Tunneling 的差別

本章對應第 2 章「登入評估流程」的第 9 與第 10 項。

一、Profile 與 Policy:一個管日常、一個管細節

用社區門禁來想

  • Resource Profile 像「住戶登記單」:填一張單子,把這個資源、可以進的門、誰能進、首頁上的捷徑一次登記完。
  • Resource Policy 像「警衛室的規則總表」:警衛從第一行往下看,第一行寫到你,就照那一行辦,不再看下面。
  • 全新安裝的總表,預設是 Deny:沒有任何規則明確允許的,一律不准進。

Resource Profile 存檔時,系統會自動替它產生對應的 Resource Policy, 這組自動產生的政策就叫 autopolicy。所以日常新增資源,填一張 Profile 就夠了;只有需要例外處理、細部規則時,才回頭到 Resource Policies 調整。

Resource ProfileResource Policy
選單位置Users > Resource ProfilesUsers > Resource Policies
內容一個資源,加上自動產生的政策(autopolicy)、書籤、指派的角色一份由上而下比對的規則清單;每條規則可以限定適用哪些角色
適合日常設定,一次做完需要細部規則、例外處理

註:初始政策在清單中的位置為示意,實際排序以實機為準。

名詞小卡

Resource Profile

一個資源的完整設定:資源本身、自動產生的政策、指派的角色、書籤。選單在 Users > Resource Profiles。

Resource Policy

一份由上而下比對的規則清單,第一條符合的規則決定允許或拒絕。選單在 Users > Resource Policies。

Autopolicy

Resource Profile 存檔時自動產生的政策。例如 Web Access Control 允許 http://erp.corp.example.com:80/*。

Initial Policy

全新安裝時,Web 的 Initial Policy for Local Resources 與 File 的 Initial File Browsing Policy 預設都是 Deny。

Secure Application Manager(SAM)

  • PSAM(Windows):舊 WSAM 的後繼者,用 WFP 驅動程式攔截特定程式或目的地的流量。
  • JSAM(Java):25.1.3.0 仍列在跨平台功能內,Java 平台改為 OpenJDK-21。
  • SAM 不會分配 IP 給使用者。所以當使用者家裡的網段和公司內網重疊時,SAM 仍然能用,這是它和 VPN Tunneling 最大的差別。
  • 一般情境下,VPN Tunneling(第 9 章)已經取代 SAM。舊版設定手冊裡的 WSAM、JSAM 範例不再沿用。

五、常見踩坑與版本差異

Deny 排在 Allow 後面

第一條符合的規則生效,後面的規則就不再看。如果寬鬆的 /* Allow 排在前面,後面針對 /admin/* 的 Deny 永遠派不上用場。例外(Deny)放前面,一般(Allow)放後面。

資源建好了,卻沒指派角色

使用者登入成功,首頁卻沒有任何書籤。常見原因有兩個:Role Mapping 沒命中(第 7 章),或是資源沒有在 Roles 分頁指派給角色。「登入成功」和「能存取資源」是兩回事。

角色沒有啟用對應的存取功能

使用者要資源時,系統先確認 Session 的角色有啟用對應功能(登入評估流程第 9 項),再比對政策(第 10 項)。例如要用 SSH,角色必須先啟用 HTML5 Access。

還在用 Telnet

Telnet 是明文傳輸,帳號密碼在網路上一覽無遺。範例一律改用 SSH。

版本差異

  • HTML5 Access 的連線類型:22.8R2 文件列了 RDP、SSH、VNC、Telnet;25.1R1 的資源類型只列 RDP、SSH、VNC。
  • 22.x 起不再支援 Pulse Collaboration、HOB Java RDP、Basic HTML5。舊設定遷移到新機時,這些設定與引用它們的政策會被自動刪除。
  • JSAM 在 25.1.3.0 仍列在跨平台功能內,Java 平台改為 OpenJDK-21。
  • 新版 autopolicy 的完整選項清單,以實機畫面為準(舊版設定手冊列了 6 種)。
