Ivanti Connect Secure SSL VPN 實戰課程

單元 3:部署規劃

講師導言

設備還沒開機之前,先回答三個問題:使用者有多少、要裝在哪種平台、網路要怎麼接。 這三件事決定要買(或建立)哪個機型、能不能做高可用、防火牆要開哪些埠。 這一章最後的「部署規劃小幫手」,會把這幾個選擇串起來給你一份清單。

Goals 本章學習目標

  • 依預估的並行使用者數與平台,選出機型與虛擬機規格
  • 說出 Internal、External、Management 三個網路介面各自的用途與限制
  • 畫出雙防火牆 DMZ 拓樸,並標出要放行的埠
  • 說出 VMware、Hyper-V 與雲端平台各自的注意事項
  • 看懂 vCenter 匯入 OVF(虛擬機的標準範本檔)時,三個網路如何對應到 port group(虛擬交換器上的網路群組)

一、先選部署型態

Ivanti Connect Secure(ICS)可以是一台實體設備,也可以是跑在虛擬化平台或雲端上的虛擬機。

型態機型適用情境
實體設備ISA6500、ISA8500大量並行使用者、要求硬體 Secure Boot
虛擬版(地端)ISA4500-V / 6500-V / 8500-V,跑在 VMware ESXi、Hyper-V(KVM 系列在 25.1.3.0 為 Beta)已有虛擬化平台
虛擬版(雲端)同上,跑在 Azure(25.1.1.0 起)、AWS 與 GCP(皆 25.1.3.0 起)使用者分散、閘道放雲端

二、虛擬版規格

虛擬版依並行使用者(同一時間連線的人數)分成三個型號。授權若為 Gateway 並行模式,是以同時連線的裝置數計算。

型號vCPU記憶體磁碟約略使用者數
ISA4500-V48 GB80 GB250
ISA6500-V816 GB80 GB2,500
ISA8500-V1232 GB80 GB25,000
  • 上表是 VMware、Hyper-V 的規格。雲端機型的規格不同(例如 AWS 上的 ISA8500-V 是 16 vCPU),以 25.1.3.1 Release Notes 的支援平台表為準。
  • 22.x 的 ISA4000-V / 6000-V / 8000-V 規格相同,只是型號不同。
  • 官方明講不要縮小磁碟。磁碟大小只能在全新安裝或升級時調整一次。
  • 25.x 虛擬版需要 vTPM(虛擬的可信任平台模組,用來保存金鑰、支援安全開機)。
  • 22.x 文件:VMware HA 有認證,DRS 與 Fault Tolerance 沒有認證。

三、三個網路介面與 DMZ 拓樸

用一間門市的三個出入口來想

  • External port 像面向街道的大門:外面的客人從這裡進來,只能走到櫃台,進不了後台。
  • Internal port 像通往倉庫和後場的門:連到公司內部的伺服器。
  • Management port 像員工專用的後門:只給管理人員進出,平常的客人看不到。

Internal port

範例:10.0.20.10/24,閘道 10.0.20.1

  • 連內部網路與伺服器
  • 沒有啟用 Management port 時,也負責管理
  • 叢集同步只走這個介面
  • 必設,且一定要有 IPv4

External port

範例:203.0.113.10(對應 vpn.example.com)

  • 讓 Internet 上的使用者連進來
  • 只接受 ping / traceroute 與使用者發起的連線
  • 22.7R2.9 起不支援從 External port 管理設備

Management port

範例:10.0.30.10/24

  • 管理介面專用
  • 啟用後,syslog、SNMP、NTP、備份封存、Push Config 都改走這個介面

雙防火牆 DMZ 拓樸

典型做法是把 Ivanti 放在兩道防火牆之間的 DMZ(隔離區):外側防火牆擋 Internet,內側防火牆保護內部伺服器。 圖中紅字是要放行的埠。

管理要走哪裡?

External port 面對 Internet,22.7R2.9 起不支援從這裡管理設備。管理流量走 Management port;沒有啟用 Management port 時,由 Internal port 負責管理。

五、各虛擬平台的眉角

VMware

  • 匯入 OVF(虛擬機的標準範本檔)時要對應三個網路:ExternalNetwork、InternalNetwork、ManagementNetwork,分別接到對應的 port group(虛擬交換器上的網路群組)(下一節有示意畫面)

Hyper-V

  • 22.x 文件寫只支援 Generation 1、只支援 IDE 磁碟
  • 開機前就要依序加好三張網卡:Internal(1)、External(2)、Management(3)。開機後才加,可能造成網路錯亂。這是 Hyper-V 加網卡的順序,和 VMware 示意畫面的編號無關
  • 25.x 虛擬版需要 vTPM,而 Hyper-V 只有 Generation 2 虛擬機才有 vTPM。25.x 在 Hyper-V 上的世代要求,以實機與 25.x 部署指南為準

雲端

  • Azure 部分機型只支援 2 張網卡
  • 官方部署指南裡寫有預設帳密,教材不照抄。部署時用 provisioning 參數(部署時預先帶入的設定值)指定管理員帳密,上線前再改一次

示意畫面(vCenter):這是 VMware vCenter 的匯入精靈,不是 Ivanti 的畫面;Source Network 名稱依 Ivanti OVF,port group 名稱為自訂範例,版面與按鈕位置以實機為準。
  1. 1ExternalNetwork 對應 PG-DMZ:這張網卡就是 External port,接在外部防火牆後面的 DMZ 網段,讓 Internet 上的使用者連進來。
  2. 2InternalNetwork 對應 PG-Internal:這張網卡是 Internal port,通往內部防火牆與內部伺服器網段(AD、ERP 等)。叢集同步也走這張網卡。
  3. 3ManagementNetwork 對應 PG-Mgmt:這張網卡是 Management port,接管理網段。

重點不是 port group 叫什麼名字,而是三個 Source Network 各自對到「用途正確」的 port group。對錯了,External 與 Internal 的流量就會走錯網段。

八、常見踩坑與版本差異

想在 Azure 或 AWS 做 Active/Passive

依 22.x 虛擬版部署指南,Azure 與 AWS 不支援 Active/Passive 叢集,只支援 Active/Active(要自備負載平衡器)。這是規劃階段就要確認的事,等機器建好才發現就來不及了。

把管理介面開在 External port

22.7R2.9 起不支援從 External port 管理設備。管理請走 Management port,沒有啟用時走 Internal port。

Hyper-V 開機後才補網卡

要在開機前依序加好 Internal(1)、External(2)、Management(3)三張網卡。開機後才加,可能造成網路錯亂。

照抄官方部署指南的預設帳密

雲端部署指南裡寫有預設帳密,不要照抄。部署時用 provisioning 參數指定管理員帳密,上線前再改一次。

把 UDP 500 設成 ESP 埠

UDP 500 保留給 IKEv2,不要設成 VPN Tunneling 的 ESP 埠。ESP 埠預設是 UDP 4500,要改的話,整條路徑上的路由器與防火牆都要跟著放行。

版本差異

  • 22.x 文件:Hyper-V 只支援 Generation 1 與 IDE 磁碟;25.x 虛擬版需要 vTPM,世代要求以 25.x 部署指南與實機為準。
  • Azure 從 25.1.1.0 起,AWS 與 GCP 皆從 25.1.3.0 起;KVM 系列在 25.1.3.0 為 Beta。
  • 22.x 文件:VMware HA 有認證,DRS 與 Fault Tolerance 沒有認證。
  • 22.7R2.9 起,不支援從 External port 管理設備。
