單元 12:端點合規檢查(Host Checker)

講師導言

帳號密碼和 TOTP 驗證的是「人」,但還有一個問題:這個人用的「電腦」安全嗎?沒裝防毒、沒開防火牆的電腦連進內網,等於把風險一起帶進來。 Host Checker 會在使用者的電腦上做健康檢查,把「這台電腦安不安全」當成存取條件。 這一章的重點不只是怎麼建政策,而是政策放在哪裡:同一個條件放在不同位置,沒通過時的後果差很多。

Goals 本章學習目標

  • 說出 Host Checker 規則的兩種類型:Predefined 與 Custom
  • 建立一條要求防毒與防火牆的政策,並說明為什麼每個作業系統都要各自設定
  • 分辨 Host Checker 套用在 Realm、Role、Resource Policy 三個位置,沒通過時各會發生什麼事
  • 說明為什麼沒設定規則的作業系統(例如 Linux)會被判定為不合規
  • 知道舊版教材與現行版本在 ESAP 上的差異,以及哪些舊功能本教材不討論

本章對應第 2 章「登入評估流程」的第 3 項(登入前限制)、第 7 項(角色的 Restrictions)與第 10 項(Resource Policy)。

一、Host Checker:替電腦做健康檢查

用大樓的安檢來想

  • 帳號密碼和 TOTP 像「識別證」:證明你是誰。
  • Host Checker 像「安檢口」:檢查你帶的「電腦」有沒有危險物品(沒防毒、沒防火牆)。
  • 安檢口可以設在大樓大門(沒過就整棟進不去)、機房門口(大樓進得去,機房進不去)、或單一房間門口(只擋那一間)。這就是第三節要講的三個位置。

Host Checker 在使用者電腦上執行檢查,結果只有兩種:合規(通過)或不合規(沒通過)。 檢查規則分成兩大類:

類型由誰提供檢查項目
PredefinedOPSWAT,透過 ESAP 外掛防毒、防火牆、反間諜軟體、磁碟加密、修補管理、作業系統版本、CVE 檢查
Custom管理員自訂埠、執行中的程式(Process)、檔案、登錄機碼、NetBIOS、MAC 位址、電腦憑證、指令等

白話:Predefined 是現成的檢查項目,由 OPSWAT 提供,透過 ESAP 外掛帶進 ICS;Custom 則是現成項目不夠用時,由管理員自己定義要查什麼。

名詞小卡

Policy(政策)

一組規則的集合。位置在 Authentication > Endpoint Security > Host Checker > Policies。

合規 / 不合規

電腦符合政策所有要求就是合規。本例要求每條規則都通過;沒設定規則的作業系統一律不合規。

Remediation(修復動作)

不合規時可以自動做的事:結束執行中的程式、刪除檔案、顯示原因說明。視需要才設定。

ESAP

提供 Predefined 規則(防毒、防火牆等)的外掛。版本會更新,新舊版本的差異見第六節。

每個作業系統都要各自設定

剛剛只設定了 Windows 分頁。Mac 分頁要照樣再設一次。本章的教學範例就是「Windows 與 macOS 都要防毒加防火牆,Linux 不設定」。 沒設定規則的作業系統,會被判定為不合規。所以 Linux 電腦就算防毒、防火牆都開著,也一樣過不了關。

三、套用在哪裡:Realm、Role、Resource Policy

政策建好之後還不會自動生效,要「掛」在某個位置上才算數。有三個位置可以選,條件一樣,沒通過的後果卻不一樣。

位置路徑效果
RealmUsers > User Realms > (realm) > Authentication Policy > Host Checker選 Require and Enforce:沒通過就不能登入這個 Realm
RoleUsers > User Roles > (角色) > General > Restrictions > Host Checker沒通過就拿不到這個角色(但可以拿到其他角色)
Resource PolicyDetailed Rules 裡檢查 Host Checker 狀態只限制特定資源

用範例環境來看

第 18 章的 Role-IT-Full 可以加 Host Checker(步驟 7)。資訊人員用公司筆電登入,拿到完整權限;用沒通過檢查的個人電腦登入,只要他同時在 VPN-Users 群組,仍拿得到 Role-Staff,只是不能存取整個伺服器網段。這就是把政策放在 Role 的效果。

掛在 Role:Restrictions

  1. 1Users > User Roles > Role-IT-Full > General > Restrictions > Host Checker。
  2. 2選擇 Corp-Compliance 並儲存。沒通過的人拿不到 Role-IT-Full,但可以拿到其他角色。

掛在 Resource Policy:Detailed Rules

在要保護的那條 Resource Policy,用 Detailed Rules 檢查 Host Checker 狀態,只限制這個資源。其他資源、登入、角色都不受影響。具體畫面因資源類型而異,以實機為準。

五、動手玩:端點合規模擬

換一台電腦、關掉防毒或防火牆、把政策掛在不同位置,看看這位資訊人員登入後會怎樣。 政策只設定了 Windows 與 macOS(各要防毒加防火牆),Linux 沒有設定。使用者固定在 VPN-IT 群組,所以 Role Mapping 會發 Role-IT-Full;勾選「同時在 VPN-Users」就另外發 Role-Staff。

六、常見踩坑與版本差異

只設定了 Windows,其他作業系統全被擋

政策裡沒設定的作業系統,一律判定為不合規。如果你的使用者有 Mac,卻只設定了 Windows 分頁,Mac 使用者再怎麼把防毒開好也過不了關。反過來說,這也是刻意不支援 Linux 時最簡單的做法:不設定就好。

條件放錯位置

本來只想「個人電腦不給完整 VPN」,卻掛在 Realm,結果個人電腦連登入都被拒絕。反過來,把政策掛在 Role,卻沒讓使用者有其他角色可拿,沒通過的人就變成沒有任何可用角色,可能因此無法登入(實際行為以實機為準)。掛政策之前,先想清楚沒通過時要讓他「完全進不來」還是「只失去部分權限」。

使用者說「被擋了」卻不知道哪裡不合規

用戶端出現錯誤代碼 1122,意思就是端點沒通過合規檢查,要檢查 Host Checker 的結果(第 13 章有完整錯誤代碼表)。25.1.3.0 的合規報告會顯示失敗的規則名稱與原因,排查時先看這份報告。

Remediation 設太積極

修復動作可以結束執行中的程式、刪除檔案,這些動作發生在使用者自己的電腦上。這是教學建議:先用「顯示原因說明」讓使用者自己處理,確定規則沒有誤判之後,再考慮更積極的動作。

與舊文件的差異

  • ESAP 版本:舊版設定手冊(約 2009 年)用的是 ESAP 1.5.4 版。【25.x】25.1.3.0 的預設 ESAP 是 4.6.4,合規報告也會顯示失敗的規則名稱與原因。
  • Secure Virtual Workspace、Cache Cleaner:舊版設定手冊有介紹這兩項功能,它們在新版的現況本教材沒有查證,所以不列入教學。要不要用,請另行查證官方文件與實機。
  • Realm 的 Authentication Policy 與角色的 Restrictions 這兩個位置,舊教材的觀念可以沿用;實際選項與畫面仍以你手上版本的實機為準。
