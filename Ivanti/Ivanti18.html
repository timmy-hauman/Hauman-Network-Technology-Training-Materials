單元 18:綜合實作:從零建好一套 SSL VPN

講師導言

前面十七章,我們一次學一個零件。這一章把零件組裝起來:拿一份需求,依官方建議的順序,從 Auth Server、Role、Realm、Sign-in Policy、Resource Profile 一路做到 VPN Tunneling,從零建好一套完整的 SSL VPN。 需求的骨架沿用舊版簡報的使用者 A、B 兩種情境,改成新版功能與安全做法,再加上第三種使用者 C,示範群組對應與角色合併。 每一步都標了對應章節,卡住時回去查那一章就好。

Goals 本章學習目標

  • 讀懂三種使用者的需求,畫出「登入網址 → Realm → 角色 → 資源」的對應
  • 照順序完成八個設定步驟,並說出每一步對應哪一章
  • 用「登入情境模擬」預測不同使用者、不同網址、不同動作的結果,並說明原因
  • 用 11 項驗證清單驗收,並用常見錯誤表排錯
  • 說出新版做法和舊版簡報的差異

本章是第 4 章到第 16 章的總整理,範例值都來自教材開頭的範例環境。

一、需求與整體架構

整套設定只有五個零件在互相引用:Auth Server(驗證帳號密碼)、User Realm(一群使用者的登入設定)、User Role(一組權限)、Sign-in Policy(登入網址對應哪個 Realm)、Resource Profile(能連到的資源)。

用大樓的兩個入口來想

  • 登入網址像兩個入口:外包走訪客櫃台(/contractor/),員工走員工通道(/)。
  • Realm是各入口的驗證方式:訪客櫃台查本機名冊(Realm-Local),員工通道刷公司識別證(Realm-AD)。
  • Role是發給你的門禁卡,Resource是卡片能刷開的門。走錯入口,名冊上就沒有你,連卡都拿不到。

三種使用者的需求

使用者身分驗證可用資源
A(外包)ICS 本機帳號帳密 + TOTPERP 網頁、檔案分享
B(一般員工)AD 帳號,群組 VPN-UsersAD 帳密 + TOTPERP 網頁、VPN 隧道(只能連 ERP 與 DNS)
C(資訊人員)AD 帳號,群組 VPN-ITAD 帳密 + TOTPERP 網頁、VPN 隧道(整個伺服器網段)、瀏覽器 SSH 連 10.0.10.30

整體架構圖

由上到下:使用者從哪個登入網址進來、進入哪個 Realm、拿到哪些角色、能用哪些資源。

和舊版簡報原版的對照

  • 使用者 B 的 Telnet 改成使用者 C 的 HTML5 SSH(Telnet 是明文)。
  • Network Connect 改成 VPN Tunneling,並補上原版缺少的 Access Control。
  • AD 改用 LDAPS 與唯讀服務帳號,群組改用專用群組。
  • 全部使用者加上 TOTP 雙因素。

二、動手前先確認:前置條件

下面三件事沒做完,後面的步驟會卡住。

  • 第 4 章的初始化已完成:網路、NTP、授權、正式憑證(SAN 含 vpn.example.com)。
  • AD 已建立群組 VPN-Users、VPN-IT 與服務帳號 svc-ics-ldap。
  • 網域控制站的 CA 憑證已匯入 Trusted Server CAs。

六、常見錯誤與版本差異

現象原因對應章節
登入頁沒有出現預期的 RealmSign-in Policy 順序錯,vpn.example.com/ 排在前面10.1
AD 帳號登入失敗,本機帳號正常LDAPS 憑證沒匯入 Trusted Server CAs5.3、4.7
登入成功但沒有任何書籤Role Mapping 沒命中,或資源沒指派角色7.3、8.2
VPN 連上了但打不開任何內部服務缺少 Access Control 規則9.3
VPN 連上後家裡印表機不能用Route Precedence 是 Tunnel routes have precedence9.4
TOTP 一直顯示驗證碼錯誤設備或手機時間不準4.5、11.1
從外面無法完成 TOTP 註冊預設只允許內部註冊11.1

「ping 不通」不一定是壞掉

B 連上 VPN 後 ping 10.0.10.30 不通,是 Access Control 最小權限的預期結果,驗證清單的第 5 項就是要確認這件事。只有 C 才應該連得到整個伺服器網段。

連著 VPN 不能上網,是設計不是故障

範例採全部流量走隧道,再加最後一條 Deny,所以使用者連著 VPN 時不能上網。若要允許上網,要改規則並確認公司內部有通往 Internet 的出口與過濾機制(Proxy 或防火牆)。實際的規則寫法以實機為準。

Linux 電腦被 Host Checker 擋下

Host Checker 每個作業系統都要各自設定規則,沒設定的作業系統會被判定為不合規。本章的政策只設了 Windows 與 macOS,所以 Linux 電腦拿不到 Role-IT-Full。

版本差異

  • 【25.x】25.1.3.0 起,新建的 LDAP 伺服器預設啟用 Validate Server Certificate,步驟 1 的 AD-LDAPS 沒匯入 CA 就會連不上(對應常見錯誤第 2 列)。
  • 【25.x】25.1.3.0 起,Connection Profile 的 DNS 改為 Split DNS Settings,有四個選項。步驟 6 的 DNS 10.0.10.10 要在新畫面找對應的設定,畫面以實機為準。
  • 【25.x】25.1.3.0 暫時移除了「上傳自訂登入頁」,步驟 4 的登入頁請使用內建的標準登入頁。
  • Route Precedence 的 Tunnel routes with local subnet access 只支援 Windows、macOS。
  • 22.x 是過渡版本,2027-01-31 終止支援;新版基準是 25.1.x。
