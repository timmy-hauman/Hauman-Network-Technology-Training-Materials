單元 10:登入政策(Sign-in Policy)與登入頁

講師導言

前幾章我們建好了驗證伺服器、角色和 Realm,可是使用者在瀏覽器輸入網址時,系統怎麼知道「這個人該看哪個登入頁、能選哪些 Realm」? 答案就是 Sign-in Policy:它是使用者走進系統的第一道門,先看網址,再決定登入頁和可選的 Realm。 最常見的錯誤是順序放反,結果明明設好了「外包專用網址」,外包人員卻看到員工的登入頁。

Goals 本章學習目標

  • 說出 Sign-in Policy 決定哪兩件事:顯示哪個登入頁、開放哪些 Realm
  • 說明系統先比管理員網址、再依清單順序比使用者網址,第一條命中的生效
  • 建立員工與外包各自使用的登入網址
  • 分辨 Realm 的兩種選擇方式,以及什麼時候登入頁不會出現下拉選單
  • 說明 25.1.3.0 起自訂登入頁的限制,並知道升級前要先規劃

本章對應第 2 章「登入評估流程」的第 2 與第 3 項。

一、Sign-in Policy:從哪個網址進來,看到什麼

用大樓的兩個入口來想

  • 大樓有「員工正門」和「外包專用門」。Sign-in Policy 像門口的警衛,看你從哪個門進來。
  • 警衛手上有一張門牌清單,由上而下找,找到第一個符合的門牌就照辦,不會再往下看。
  • 從正門進,帶你去員工櫃台(Realm-AD);從外包門進,帶你去外包櫃台(Realm-Local)。彼此看不到對方的櫃台。

使用者在瀏覽器輸入網址後,系統會拿這個網址去比對 Sign-in Policy。比對成功,就決定了兩件事:顯示哪一個 Sign-in Page(登入頁),以及開放哪些 Realm 讓使用者登入。

Sign-in Policy 的三個欄位

位置:Authentication > Signing In > Sign-in Policies。政策分成管理員(Administrator)與使用者(User)兩種。預設網址是管理員 */admin/、使用者 */。

欄位說明
Sign-in URL格式為「主機/路徑」,萬用字元 * 只能放在主機名稱開頭
Sign-in Page要顯示的登入頁
Authentication realm開放的 Realm,以及使用者怎麼選

Realm 的兩種選擇方式

  • User picks from a list of authentication realms:登入頁出現下拉選單,讓使用者選(舊版教材都用這種)。
  • User types the realm name:使用者自己輸入 Realm 名稱。

只開放一個 Realm,就沒有下拉選單

只選一個 Realm 的政策,登入頁不會出現 Realm 選單,使用者直接看到帳號密碼欄位。這正是外包專用網址的好處:外包人員連選項都看不到員工的 Realm。

名詞小卡

Sign-in Policy

依網址決定登入頁與可選 Realm 的規則清單,由上而下比對,第一條命中的生效。

Sign-in URL

格式是「主機/路徑」,例如 vpn.example.com/contractor/。越寬的網址(如 */)越容易擋住後面具體的網址。

Sign-in Page

使用者在瀏覽器看到的登入畫面。選單在 Authentication > Signing In > Sign-in Pages。

Authentication realm

這條政策開放給使用者的 Realm。Sign-in Policy 要選 Realm,所以 Realm 要先建好(第 7 章)。

三、Sign-in Page:登入頁長什麼樣子

Sign-in Policy 決定「顯示哪一頁」,而登入頁本身的外觀在 Authentication > Signing In > Sign-in Pages 設定。 內建的標準登入頁可以修改下列項目,不必自己寫網頁:

  • 文字
  • 頁首與 Logo
  • 顏色
  • 錯誤訊息

想上傳自己做的整套登入頁範本,在 25.1.3.0 起有新限制,請看第五節的版本差異。

五、常見踩坑與版本差異

寬的網址排在前面,擋住具體的網址

症狀是「登入頁沒有出現預期的 Realm」。原因是 vpn.example.com/(或 */)排在前面,外包網址 vpn.example.com/contractor/ 先被它命中。具體的網址排前面,寬的排後面。

預設的 Users realm 沒有拿掉

舊版教材的截圖在 Available realms 還留著預設的 Users realm,也沒有說明。正式環境不用的預設 Realm,請不要開放給使用者。

SAML 的 Sign-in URL 只能對應一個 Realm

用 SAML 驗證時,這條 Sign-in URL 只能對應一個 Realm,不能像一般政策那樣開放多個讓使用者挑。

萬用字元 * 放錯位置

Sign-in URL 的 * 只能放在主機名稱開頭,像預設的 */admin/ 與 */ 那樣。放在主機名稱的其他位置是不行的。

Realm 還沒建就想建政策

Sign-in Policy 要選 Realm,所以 Realm 一定要先存在。這幾項的相依順序是 Auth Server、Role → Realm → Sign-in Policy。

版本差異:25.1.3.0 暫時移除自訂登入頁上傳

  • 25.1.3.0 暫時移除了「上傳自訂登入頁」。原因是範本內可執行腳本有安全疑慮。
  • THTML ZIP 不能再上傳,既有的自訂範本也不再運作。
  • 舊環境若依賴自訂登入頁(包含含有 TOTP 範本的自訂頁),升級前要先規劃。
  • 內建的標準登入頁仍可修改文字、頁首、Logo、顏色與錯誤訊息。
